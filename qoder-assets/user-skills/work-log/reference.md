# 参考框架（方法论细节）

本文件是 [SKILL.md](SKILL.md) 的补充资料，仅在需要时阅读对应章节。

## 一、技能（skills）总结的三类写法

写工作总结或简历的 skills 部分时，按三类挑 6–10 条，每条尽量配数据或成果，避免只堆名词：

1. **通用能力**：工作总结与复盘、问题分析与解决、跨部门沟通协作、需求对接与对齐、项目管理与进度把控、风险预警、数据分析与报告、文档编写（方案/纪要/制度）、时间管理与多任务并行。
2. **按岗位的专业能力**（开发岗示例）：模块设计、代码重构、性能优化、接口开发、Bug 排查、单元测试、CI/CD。
3. **工具技能**（写具体名称 + 熟练度）：Office（Excel 函数/透视表、PPT）、协作（飞书/钉钉、Jira/TAPD）、数据（SQL、Python、Power BI）、设计（Figma、XMind）、其他（Git、Linux、Docker）。

## 二、熟练度分级（避免"精通"滥用）

| 级别 | 定义 | 能扛住什么追问 |
|---|---|---|
| 精通/深度掌握 | 看过源码或规范，调过线上疑难问题，能讲清原理和取舍 | 原理、边界条件、为什么不用另一方案 |
| 熟练/主力使用 | 日常主力栈，独立负责过完整模块 | 常用 API、工程化配置、典型坑 |
| 熟悉/用过 | 做过项目，能干活但需查文档 | 基本用法、适用场景 |
| 了解/接触过 | Demo、教程、简单尝试 | 是什么、解决什么问题 |

简历约束：**"精通"最多 2–3 个**，且必须是你愿意被深挖到底的技术；其余统一用"熟练/熟悉"。

AI 相关技能按证据评级：有黄金集和指标前后对比才够"熟练"，只调通 API、搭过 demo 一律"了解"。

1 年经验段位：简历不写"精通"；"熟练"最多 2 项且必须有独立交付的模块佐证，其余写"熟悉/了解"；用交付物、数字和端到端闭环补年限，不靠形容词。

## 三、全栈技能分类框架（按此顺序列）

1. **前端**：HTML5/CSS3/JS/TS → Vue3/React/小程序 → 工程化（Vite、ESLint、CI 部署）→ 硬核项（首屏与 LCP、分包懒加载、虚拟列表、WebSocket/SSE 断线重连、路由/按钮/数据三级权限、TS 泛型与类型收窄）→ 前后端契约（OpenAPI 类型生成、BFF、缓存分层）→ 微前端/组件库/可视化（ECharts）/跨端。
2. **后端**：语言框架（Spring Boot、Node.js 等）→ 架构（RESTful/gRPC、JWT/OAuth2、RBAC）→ 并发异步（MQ、定时任务、幂等、分布式锁）→ 排查与优化（GC/JVM、慢 SQL、线程与内存分析、压测）→ 安全（XSS/CSRF/SQL 注入、限流熔断）。
3. **AI 工程**：模型接入与提示工程（Spring AI / LangChain 等）→ RAG（切分/召回/重排/引用）→ 开放域 Agent 链路（意图识别、MCP 工具建设、多轮记忆、多 Agent routing、在线监控）→ 评测体系（黄金集、端到端任务完成率、turn 级评测、LLM-as-judge、bad case 分析）→ 可靠性（超时重试、幂等、人工兜底、状态持久化、工具调用失败兜底）→ 成本（token 统计、上下文压缩、提示词缓存、小模型路由）。
4. **数据层**：MySQL（索引、事务、锁、慢查询）、Redis（数据结构、缓存穿透/击穿/雪崩、分布式锁）、MongoDB/ES、ORM（MyBatis/JPA）。
5. **基础设施 & DevOps**：Linux/Shell、Nginx、Docker、K8s 基础、CI/CD、监控告警（Prometheus/Grafana、日志）、云资源（ECS/RDS/OSS/CDN）。
6. **工程能力**（全栈最值钱的部分）：需求分析与技术方案、接口契约设计、数据库建模、Code Review、单元/E2E 测试、性能优化与故障排查、文档与规范制定。
7. **软技能**：跨部门沟通、排期与风险把控、技术选型论证、独立交付、新人带教。

## 四、技能清单表格模板

| 领域 | 技能 | 熟练度 | 佐证（项目/成果） |
|---|---|---|---|
| 后端 | Java + Spring Boot | 熟练 | 主导某系统告警全链路贯通（见 01-项目 对应记录） |

## 五、量化指标清单（写不出数字时从这里挑）

| 方向 | 可用指标 |
|---|---|
| 性能 | QPS/TPS、P99/P95 RT、首屏时间、FCP/LCP、打包体积、冷启动、虚拟列表帧率、长连接重连成功率 |
| AI 应用 | 评测准确率/召回/忠实度、端到端任务完成率、意图识别准确率、routing 准确率、多轮记忆命中率、bad case 占比、检索召回率、工具调用失败率、单次调用成本、token 消耗、月成本节省、首 token 延迟 P95 |
| 稳定性 | 可用性 SLA、故障次数/MTTR、告警误报率、错误率 |
| 成本 | 服务器/云费用、CPU 内存占用、带宽、存储、CDN 命中 |
| 效率 | 构建时长、部署时长、发布频率、需求交付周期 |
| 质量 | 单测覆盖率、Bug 数、回滚次数、Review 通过率 |
| 业务 | DAU/MAU、转化率、客诉量、人工工单减少量 |
| 团队 | 带教人数、输出文档数、组件复用项目数 |

没有精确数据时给量级和对比："接口 P99 从 ~800ms 降到 ~120ms"。

## 六、从记录到简历的转换公式

**动词 + 做了什么 + 用什么技术/方法 + 解决什么规模的问题 + 量化结果**

记录时把三样写清，改简历只是抄句子：原方案多烂、换了什么、数字变化多少。完整前后对比见 [examples.md](examples.md)。

## 七、常见坑

1. **只写技术名不写场景**："会用 Redis" 不如 "用 Redis ZSET 实现延迟队列替代定时轮询"。
2. **堆砌过时技术**：jQuery、SVN、JSP 这类除非岗位要求，不占位置。
3. **前后端平均用力**：全栈 ≠ 五五开；明确主方向（如"后端为主，前端能独立交付"）反而更可信。
4. **AI 玩具档描述**："实现了智能问答功能"会被归为兴趣项目；改成有评测、有 bad case、有成本数字的工程档表述。
5. **把时间花在背八股上**：纯八股（如 Vue 响应式源码）除非面专门岗位，不如投在做出可交付的东西；后端靠排查与优化故事保定价，前端靠独立交付消质疑。
6. **1 年经验虚标段位**："主导架构""精通 XX"会被追问穿；改成"独立交付了哪条链路 + 数字"，用交付物说话。
7. **AI 项目刻意对齐业界 benchmark**：复刻 SOTA 的项目没有真实数据和自己的 bad case，追问两层就露怯；值钱的是在开放域真实场景里把意图识别、记忆、routing、工具调用纠错这些环节做深，而不是项目题材像论文。

## 八、维护节奏

- **当天记**：每天下班前 5 分钟，哪怕只写三行；周五补周一的细节已丢一半。
- **月度回顾（每月最后一个周日，15 分钟）**：扫一遍 `00-履历总表.md`：① 同主题零散条目合并成专项（01 合并、06 提炼）；② 补齐 06 答不上的追问，补不出来就删；③ 校准 05 技能熟练度（新学→了解，常用→升级并补佐证，一年没碰→降级或删）；④ 对齐定位：确认 06 里后端深度条目没被前端/AI 挤掉，主推项目仍不超过 3 个，AI 项目补当月评测指标、bad case 与成本变化；顺带把当月最有价值的 3–5 条改写成成品句进 `04-简历素材池.md`。
- 投不同岗位时用同一母表裁剪重排，不一份通投。

## 九、数据目录初始化骨架

新环境首次使用时按此建目录与文件，建完告知用户实际路径。文件标题一律 H1，与记录层级规范一致。

`00-履历总表.md`：

```markdown
# 履历总表

> 一行一条总索引，由 work-log skill 维护；详细记录见 01-项目/。

| 日期 | 项目/模块 | 角色 | 关键词 | 核心成果 | 记录文件 |
|---|---|---|---|---|---|
```

`01-项目/<项目名>.md`：

```markdown
# <项目名>

> 详细记录按时间倒序追加；索引见 ../00-履历总表.md。
```
