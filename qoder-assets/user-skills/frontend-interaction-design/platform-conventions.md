# 平台惯例对照

先查表再动手。用户对"按钮该在哪"的预期来自他用过的其他 App，不来自当前页面的视觉引导。

## 核心场景对照

| 场景 | iOS | Android | Web（后台） | 微信小程序 / uni-app |
|---|---|---|---|---|
| 返回 | 左上角返回箭头 + 标题，或左滑手势 | 系统返回键 + 右边缘左滑 | Logo 回首页、面包屑、浏览器后退 | 除首页栈底外均由原生导航栏提供左上返回；自定义导航栏要自己实现且不能盖住胶囊 |
| 页面级操作 | 右上角文字按钮 | 顶部栏右侧图标或溢出菜单 | 右上角，或内容区末尾 | 右上角 —— 但必须和右上角胶囊按钮让位，别叠在一起 |
| 主操作（确认/提交） | Alert 里"确认"在右 | 主按钮在右（Material） | 表单下方，跟随阅读终点 | 底部整宽按钮或弹窗右侧 |
| 取消/关闭 | Alert 里"取消"在左 | 次要在左 | 主操作左侧 | 同左 |
| 全局新建 | 少见，多用底部 Tab | 右下角 FAB | 列表右上角"+" | 多在页面内按钮，FAB 较少见 |
| 主导航 | 底部 Tab Bar | 底部导航栏或左上抽屉 | 顶部导航栏 | 原生 tabBar 或自定义底部栏 |
| 删除列表项 | 左滑出"删除" | 长按或滑动 | 行内"删除"文字按钮 | 左滑（uni-swipe-action 等）或行内按钮 |
| 多选批量 | 右上角"编辑"进入选择模式 | 长按进入选择模式 | 表头复选框 + 顶部批量栏 | 右上角"编辑"或长按 |

## 红线：别跨平台混用

- iOS 页面里放左上角汉堡菜单（那是 Android 抽屉语汇）。
- Android 里用 iOS 风格：底部 Sheet 顶部放"完成/取消"、Alert 按钮先取消后确认但方向颠倒。
- 微信小程序里把操作按钮放右上角又压到胶囊上，等于做不出来。
- PC 后台用移动端的底部整宽主按钮（800px 宽的提交按钮，鼠标用户要横跨半个屏幕）。

## 微信小程序 / uni-app 的额外约束

- **右上角胶囊**：宽度约 87px，右侧安全区还要加约 7px 边距。自定义导航栏时所有右侧操作必须让位到胶囊左侧。
- **状态栏**：自定义导航栏要自己补 `statusBarHeight`，否则顶部被状态栏压住。
- **原生 tabBar vs 自定义**：原生 tabBar 由平台处理安全区；自定义底部栏必须自己加 `env(safe-area-inset-bottom)`，这是最容易漏的一条。
- **导航栏高度不统一**：`uni.getSystemInfoSync()` 的 `statusBarHeight` 与页面栈层级都影响布局，自定义导航栏不要写死 44px。
- **没有 hover**：PC 上"悬停才出现操作"的交互在小程序上完全不可用，必须给常驻入口或长按。
- **滚动区域**：`scroll-view` 需要固定高度才能滚，页面级底部操作栏用 flex 布局而不是 `position: fixed`，才能避开键盘弹出时的遮挡。

## RTL（阿拉伯语等从右到左语言）

整套左右镜像：返回在右上、确认在左、向导从右向左、进度条反向。用 CSS 逻辑属性写，别写死 `left/right`：

```scss
// 用 inline-start/inline-end 表达"开始/结束"，RTL 下自动镜像
padding-inline: 16px;
inset-inline-end: 12px;
```

图标的左右方向（箭头、前往）也要跟着镜像，但不要镜像播放键、音量、时钟这类有客观方向的图标。

## 桌面端（PC Web 后台）与移动端的差异

| 维度 | 移动端 | 桌面端 |
|---|---|---|
| 主要成本 | 拇指够不够得到 | 视线流 + 鼠标移动距离 |
| 位置逻辑 | 按可达性分层（下好上难） | 按 F/Z 型阅读路径，把 CTA 放在视线终点 |
| 危险操作降温 | 放远 + 弱样式 | 分隔线隔开 + 弱样式 + 二次确认 |
| 表格操作 | 卡片化，行内 1 到 2 个 | 操作列固定在右侧，超过 2 个收进"更多" |
| 悬停 | 不可用 | 可用但只能是增强，不能是唯一入口 |
| 批量操作 | 底部升起 | 表格顶部或表格底部吸附条 |

## 平板 / 折叠屏 / 横屏

可达区从"下半屏弧带"变成"左右下两个扇形"，屏幕几何中心反而最难够到。操作栏放两侧或底部，别放顶部居中；分栏布局把主操作放右栏底部，而不是横跨整个屏幕居中。
