## 需求 43｜外部施工队可独立办理作业票

**边界说明**：APP 登录走 `SysLoginService.appLogin/appPwdLogin`，强制校验 `sys_user.user_type='01'`。承包商人员存于 `base_contractor_people`，**无 sys_user 账号**，故"外施队人员自己登录建票"链路断开。
已实现部分：内部人员建票时作业单位可挂外施队、监护人可跨企业选外施队人员。

**路径（APP）**
1. PC `企业管理 → 人员管理`（/cbs/contractorPeople）先录入外施队人员：所属企业选承包商企业（正式库如 `1039 宜昌华直能源开发有限公司`），状态置审核通过，否则 APP 选人接口 `status=3` 过滤选不到
2. APP 首页 → 选票型（如动火作业）→ 右上 **添加**
3. 点 **作业单位** → 选外施队企业 → 统一社会信用代码自动回填只读
4. 点 **作业部门** → 选该单位班组
5. 点 **监护人** → 弹窗应能勾到该外施队人员（监护人模式下 `deptName` 传 null，不按部门过滤）
6. 填作业负责人、地点、时间、等级 → 签字 → 提交
7. 列表出现该票，作业单位显示外施队企业

**校验**：`SELECT outerId,workNo,workUnitName,contractorId,jhr,workUnitType FROM base_work_special WHERE workNo='<编号>';`

## 需求 35｜开工前必须完成有效气体检测

**只对动火（ticketsType=1→平台码11）和受限空间（2→14）生效**，其他票型直接放行。

**APP 四个分支**
1. 动火票不录气体 → **开始作业** → 「开工前 30 分钟内未完成气体检测，禁止开工」
2. 录了但**分析时间回填到 31 分钟前** → 同样被拦
3. 录了但超标（氧气填 25）→「气体检测不合格，禁止开工：氧含量 25.00%（应 19.5%~23.5%），不合格」
4. 动火票只录氧气 → 「动火作业开工前无合格的可燃气体分析记录」；受限空间票只录可燃 → 「受限空间作业开工前无合格的氧含量检测记录」
5. 全部合格 → 开工成功

**重要口径**：可燃/氧气**同类型只认最新一条**（先测不合格、通风后再测合格能放行）；**有毒气体逐条判**，任一超标不放行。

## 需求 51｜装置按设定时间自动开停车

**语义冲突**：装置开停车（`base_device_ctrl`）是「本地登记 + 上报园区审核」的**备案制**，系统内没有下发装置开关的通道，也没有开停计划的修改接口。库里虽有 `exec_status`/`exec_time` 两列，但 Java/Mapper 零引用（已回退）。
真正实现"到点自动"的是**风险单元启停**：`base_risk_unit_log` 登记停用/启用时间 → `DataSyncTask.syncRiskUnitStatusOnTime` **每分钟**跑 `autoSyncUnitStatus`，到点自动切单元状态并联动排查任务启停。

**线 A｜风险单元到点自动启停**
1. `风险管理 → 风险单元`（/risk/riskUnit）→ 把某单元「工作状态」开关切到 **停**
2. 弹窗填 停用时间=此刻、启用时间=2 分钟后、原因 → 确定 → 落 `base_risk_unit_log`
3. 等 1 分钟内 → 单元状态变「停」，该单元排查任务同步停用
4. 到启用时间后再等 1 分钟 → 单元自动回「开」，排查任务恢复

**线 B｜装置开停车页备案流程**
1. `平台对接 → 装置开停车` → **新增开停记录**
2. 选重大危险源 → 是：填 12 位装置编码 + 单元编码（19 位数字）+ 单元名称；否：填装置名称 + 单元名称
3. 选开停类型 → 开始时间、结束时间（须晚于开始）、申请单位、**附件必填** → 保存
4. 点 **上报** → 园区校验（时间段不重叠、开车前最近一条须为停车）

| 2.9 | **有毒逐条判** | 同票 2 条有毒，一条合格一条超标 → 开工 | 有毒**逐条判**，任一超标 → 拦下（与可燃/氧气规则不同） |

| 6.2 | 窗口命中 | 停用=1分钟前、启用=1小时后 | → 停用，且**排查任务同步停用**（联动是重点） |
| 6.3 | 启用时间已过 | 停用=2小时前、启用=1小时前 | → 自动恢复"开"，任务恢复 |
| 6.4 | 多单元独立 | 3 个单元，1 个在窗口内 | 只有窗口内那个停用 |
| 6.5 | 任务联动不孤儿 | 单元恢复后查排查任务 | 不能出现"单元已恢复、任务仍停用" |
| 6.6 | 定时器幂等 | 连等 3 个周期 | `NOT EXISTS` 判定，重复执行不重复改；日志只在有变更时打 |
| 6.7 | 手动改动被覆盖 | 手动改单元状态后等 1 分钟 | 定时器按时间窗覆盖手动状态 —— 设计如此，但要记录 |
| 6.8 | quartzEnabled 无关性 | 本地 `quartzEnabled=false` | `@Scheduled` 由 `@EnableScheduling` 驱动，与 quartz 开关无关，每分钟任务照跑 |

**取证要点与踩坑**：

1. **气体录入页有 4 个必填项**：分析标准、CAS 号、分析人、结果单位。漏一个只弹 Toast（不跳页），容易误以为提交失败。Toast 只存活 2 秒，必须点击后立即 screencap。
2. **下拉选择器选项顺序会漂移**：同一对话框两次打开，气体类型（可燃/有毒）和单位（%/%VOL）的行位置不同。必须每次重新 dump 取坐标，**不能沿用上一次坐标**。
3. **介质名与气体类型要配套**：名称填 CH4 但类型选「有毒有害」→ 查 TOXIC_LIMIT_TABLE 未收录 → 判「无法自动判定」直接拦开工。测可燃气体必须 type=1。
4. **详情页数据是打开时快照**：开工写入 actualStartTime 后，当前详情页的现场会签页签不会自动刷新，需退出重进才看到「实际开工时间」。
5. **开工前置**：需现场会签节点已签（可 UPDATE base_work_approve 的 fileId/fileIdUrl/content 模拟），签名图放 `D:\ruoyi\uploadPath\` 且 /profile/** 可直链访问。
6. **权限接口调用顺序**：非授权人先撞业务报错（现场会签未完成）说明 checkOperatePermission 没排在最前，已修为前置。
7. **后端重载会失效 APP token**：点 RuoYiApplication.class 触发 devtools 重载后，APP 出现「登录信息失效」→ 重新登录（账号 `17329995095` / 123456，验证码是算术题 capStr）。
8. **PC 端 admin/admin123 不可用**：实测提示「用户不存在/密码错误」。可用账号见 `file/login_body.json`（`6018082666`）。

**已知缺陷（已修复）**：监护人选人弹框点「全部」或岗位维度时会重新请求接口并重建列表，**已勾选的人被清空**；只有「本公司」「承包商」两个维度之间切换才保留勾选。2026-10-27 已改为人员池合并入池 + 复用池中对象（保留 show 勾选态），「全部」维度也改走本地过滤。

**状态掩码（易误判）**：非管理员 + 非当前操作人 → 详情接口把 `workStatus` 抹成 `"1"`；列表接口不掩码。同一 outerId 两个接口返回不同状态是设计如此，不是连错库。**2026-10-27 已改为 viewOnly 标记**（状态恒真实），可操作口径 = 开票人 + 监护人。

# 第五部分：校验查询速查

**执行前先确认落点**：`SELECT @@hostname` —— MCP 的 `tgr-gz-vue` 连正式库（anwei1-0001），只读；结论不可与其他环境的库互相推断。MCP 返回 datetime 带 Z 后缀偏 8 小时，判读用 `DATE_FORMAT(col,'%Y-%m-%d %H:%i:%s')`。

-- 票面状态与监护人
SELECT outerId,workNo,ticketsType,workStatus,actualStartTime,jhr,workUnitName,contractorId
FROM base_work_special WHERE workNo='<编号>' OR outerId='<outerId>';

-- 各状态票量分布
SELECT workStatus,COUNT(*) FROM base_work_special WHERE deleteMark='0' GROUP BY workStatus;

-- 中断记录

FROM base_work_interrupt WHERE workId='<outerId>' ORDER BY interruptTime;

-- 气体检测记录

-- 30 分钟窗口内有效记录
SELECT outerId,type,name,result,unit,time FROM base_work_sensor
WHERE workId='<outerId>' AND deleteMark='0' AND time >= NOW() - INTERVAL 30 MINUTE;

-- 人员库与归属（内外判定依据）
SELECT p.id,p.name,p.contractor_id,p.status,p.sync_id,p.dept_name,p.job_post,
       c.company_name,c.company_type
FROM base_contractor_people p LEFT JOIN base_contractor c ON p.contractor_id=c.id
WHERE p.del_flag='0' AND p.name IN ('胡军','王外施');

-- 重名排查（用例 1.5）
SELECT name,COUNT(*) cnt,GROUP_CONCAT(DISTINCT contractor_id) cids
FROM base_contractor_people WHERE del_flag='0' GROUP BY name HAVING cnt>1;

-- 外施队人员数（每家承包商）
SELECT c.id,c.company_name,c.company_type,COUNT(p.id) people_cnt
FROM base_contractor c LEFT JOIN base_contractor_people p ON p.contractor_id=c.id AND p.del_flag='0'

FROM base_contractor_people_cert c

SELECT u.id,u.riskUnitName,u.status,l.stopTime,l.activationTime,l.reason

-- 排查任务联动
SELECT id,unit_id,status FROM base_risk_task WHERE unit_id='<单元id>';

-- 装置开停车
SELECT id,major_hazard,ctrl_mode,device_name,device_code,start_time,end_time,sync_status

-- 菜单路径核实（不要凭路由推断）
SELECT m.menu_id,m.menu_name,m.path,m.component,m.perms,p.menu_name parent_name
