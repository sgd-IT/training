Bug class: 同一铸造单元显示多条声音报警，不能仅凭相近时间认定同一终端重复上报。
Root cause: 2026-09-18只读核实腾讯云anwei_mon_aluminum：云南创新合金井119当前名为2#铸造单元。17:41:11记录78765的node_id为0909452581，17:41:16记录78766为0909452694；msg_id和local_random_id均不同，两条都有不同音频地址。此次已证实为两个终端标识分别产生记录，原先单终端重复上报仅是假设。中午12:42的四条及12:48的三条则均为0909452694。云端设备映射行虽均指向井119，但data_status=0，不能当作现场当前生效配置。
Fix pattern: 先区分终端身份、事件幂等与井级事件合并；核实设备归属和业务计数口径后再决定修复，不盲目按设备时间窗口去重或删除映射。
Reusable lesson: Redis附件Hash不提供报警事件幂等；云端记录可证明保存来源标识，不能单独证明物理报警次数、原始请求次数或现场部署版本。适用于多终端映射同一井的声音报警诊断。
