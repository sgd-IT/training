## Goal
查证青海桥头铝电（customer_id=377）在平台的报警数据，解释现场反馈的"非铸造状态也会报警"。

## 关键事实（2026-09-20 从云库核实）
- 桥头仅有 1 个铸造单元：井 id=118「1#铸造单元」node_id=08b96d0f...，设备 device_num=qhld001（PLC 点位 QHQTLD_*）。无嘉果/声音漏铝终端（em_aluminum_device_info 无记录，全表60行核对为0），mon_aluminum_leakage_alarm_record 零记录，报警全在 mon_alarm_information（9/18-9/19 共56条）。
- 数据 9/18 06:16 接入，阈值配置 9/16-9/18 大量新建/修改 → 处于新上线调参期；当前 ax0047/ax0024 均为 0（非铸造）。
- 报警构成：低阈值报警24条+关闭即报警11条（云侧产生，9/18 18:47 前后与停电/停机事件吻合）；高高连锁"连锁值0.0"11条+关闭即预警6条+市电断电/恢复3条+炉口液位渗漏提醒1条（带 local_random_id 本地离线补传标记）。
- 异常点：分配流槽入口液位的高高连锁运行时阈值为 0.0（云端配置 set_value=60/alarm_threshold=180），0.7~1.1mm 微波动即报警，疑为本地端配置/同步不一致。
- "炉口液位渗漏异常提醒"（74.1mm≥30mm）来自 FzzqjMethod.BjInfo2 用 is_leakage=1 的"非铸造期间"阈值（DB3.DBD4=30mm、DB2.DBD130=300℃），本就是非铸造期监测设计，代码不判铸造状态。

## 结论
非铸造报警来源：a) 非铸造期渗漏监测设计如此；b) 高高连锁阈值 0.0 的配置异常；c) 安全点位（压力/流量/应急水/联锁）常规阈值报警无铸造过滤，停机时值归0即触发；bz_range_alarm_config 未配置任何点位开关。

## 订正（2026-09-20 代码复核）
上文中"带 local_random_id 本地离线补传标记"表述不准确：local_random_id 是 MyBatis-Plus INSERT 自动填充的随机ID（MyMetaObjectHandler.insertFill，用于数据同步去重），其有无只取决于入库代码路径（MP实体插入 vs 自定义SQL插入），不能据此判断数据来自本地端还是云侧。
