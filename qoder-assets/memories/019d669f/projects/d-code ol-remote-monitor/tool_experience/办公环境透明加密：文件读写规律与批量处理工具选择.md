办公电脑部署了透明加密系统：由 IDE/编辑器写入的文件在磁盘上是加密存储的，PowerShell 等未授权进程读到时是高熵乱码（Get-Content 乱码、脚本莫名报错），而 IDE 和 git.exe 在放行名单中可正常读取明文；PowerShell 自己用 Set-Content 创建的文件可正常自读自写。另外系统级防护会拦截对 .git 目录的 Rename/移动（Access Denied），沙箱内外均如此。

处理规律：
1. 批量改文件前先做探针判定——用 Get-Content 读一个最近被编辑器修改过的文本文件，乱码即坐实磁盘密文；再用 git hash-object / git grep 读同一文件对照，git 能读到解密后的真实内容，是此类环境下唯一可靠的脚本侧内容校验与全文扫描通道。若 PowerShell 也能读明文则按普通环境处理。
2. 明文文件可用 PowerShell 批处理，采用字节级（cp1252 编码映射）字符串替换可无损保真；被加密的文件必须改用 IDE 的 Read/Write/SearchReplace 处理，用 PowerShell 对密文做正则替换会把密文当内容写回，导致文件损坏或漏替换。最终交由 git 提交（git 视角始终正确）。
3. 构建推送副本时用 git ls-files 清单驱动 Copy-Item，并先把控制台输出编码设为 UTF-8、用 -z NUL 分隔解析文件名；不加 -z 时中文文件名被八进制转义，造成复制失败与虚假缺失告警。直接通配复制会带入被忽略文件。
4. 副本完整性校验逐文件比对 git hash-object，数量对账会被幽灵条目与编码误报干扰，内容哈希才是权威证据。每次改写后用 git diff --stat / git grep 复核命中与残留，以 git 视角验证代替脚本读文件。
