Conclusion: 向公开仓库（github.com/sgd-IT/remote）推送含敏感信息的既有项目时，采用"快照式首推"——新建独立目录复制三仓库当前工作区文件、脱敏后做单个 root-commit 推送，不携带任何提交历史。
Rationale (trade-off): 历史每个旧提交中同样存在明文密钥，用 filter-repo 逐版本清洗无法保证 100% 干净且对本机受保护的原仓库风险高；快照方案内容边界可控、可用 git grep 全量复核残留，代价是丢失历史与多仓库合并为单仓库（backend/frontend/mobile 三目录）。
Rejected alternatives: ①改写原仓库历史后再推（被环境对 .git 的系统级写拦截否决，且破坏 Gitea 协作历史）；②保留历史逐 commit 清洗（成本高且不可验证完全干净）——两者均非错误做法，是本场景权衡后的落选。
Applicable / expiry conditions: 适用于"公开仓库首次分享内部代码、历史含不可回收凭据、原仓库不宜动"的场景；该方案已验证闭环——快照 35f2b3f（含全部大资源共 191MiB）已成功全量推送至远端 master。若日后需要保留提交历史或做增量同步，须重新评估（届时应先在源头轮换密钥并考虑私有仓库+完整历史清洗）。
