## Usage Scenario
在 Qoder 的沙箱终端（PowerShell，常提示 "Executed by Node fallback"）中对工作区文件做内容校验、运行 Maven 包装器，或将工作区文件交给外部 CLI（如 mysql.exe）处理时。

## Usage Method
1. 判断文件是否"损坏"：不要在终端用 Get-Content / [System.IO.File]::ReadAllBytes 直接判断。若读到以固定魔术头（如 88 7D 1C）开头的二进制密文，且同一批次里"未改动的文件"也如此，说明是沙箱文件系统视图假象，而非文件损坏。
2. 权威校验手段：git diff / git diff --check / git ls-files --eol（git 能读到真实明文），以及 IDE 侧工具（Read、Grep、GetProblems）。
3. node 进程可读明文（file:readFileSync），但 PowerShell 的文件 API 及经其启动的外部 CLI（mysql.exe 的 source 读文件）会得到密文。
4. 运行 Maven 时不要用项目内 .\mvnw.cmd（其内部用 Get-Content -Raw 自读脚本，会因密文视图解析失败报 "Cannot start maven from wrapper"）；改用本机 maven 可执行文件绝对路径。
5. PowerShell 默认禁止运行 pnpm.ps1（执行策略），改用 node 直接调用（node node_modules\vue-tsc\bin\vue-tsc.js --noEmit）。
6. 需让外部 CLI 处理工作区文件内容时：改由 node 读明文、经 stdin 交给子进程（child_process.execFileSync 的 input 选项喂给 mysql.exe 等），避开文件视图；且启动工作区外程序的写操作命令须先取得沙箱外执行权限（required_permissions='all'），否则报 "拒绝访问" 或 execFileSync 返回 exit=null。
7. mysql 的短参数（-h192.168.x.x）在 fallback shell 会被截断（报 Unknown host '192'），必须用 --host= 等长参数并加引号。

## Notes
误判"文件被写坏"会触发无必要的重写甚至回滚；下次遇到疑似乱码，先用 git 交叉验证再行动。PS 管道默认 UTF-16 编码，直接管道给 mysql 会报 ASCII '\0' 错误。
