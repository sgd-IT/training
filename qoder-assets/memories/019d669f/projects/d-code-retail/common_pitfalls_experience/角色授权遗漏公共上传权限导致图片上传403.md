## Bug 类型
角色（如 regulator）配置了业务菜单与按钮权限后，能进页面、能打开表单弹窗，但上传图片时报 403「无此权限：fireworks:oss:upload」。

## 根因
项目内所有图片/文件上传组件（ImageUpload、FileUpload）统一调用 /fireworks/oss/upload 接口，由独立按钮权限 fireworks:oss:upload 保护，与业务模块按钮权限分离。配置角色授权时只勾选业务菜单（如报警处置、零售店编辑）会遗漏该公共能力权限；监管角色的处置现场照片、零售店证照上传均受此影响。

## 修复模式
给角色补授 fireworks:oss:upload（sys_role_menu 插入），推荐幂等写法：INSERT IGNORE INTO sys_role_menu SELECT r.role_id, m.menu_id FROM sys_role r JOIN sys_menu m ON m.perms='fireworks:oss:upload' WHERE r.role_key='regulator'（按 perms 匹配不硬编码 menu_id，兼容不同 ID 体系）；执行后相关用户需重新登录才生效（Sa-Token 会话快照）。

## 可复用教训与边界
角色授权矩阵必须显式包含跨模块公共能力权限（文件上传等）；只要"上传组件独立挂权限"，新角色授权就需走一遍上传场景检查。适用于所有 RuoYi 系（Sa-Token）项目。
