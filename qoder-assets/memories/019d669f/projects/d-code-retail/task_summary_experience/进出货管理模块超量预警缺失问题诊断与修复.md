## Task description
- Core requirement: diagnose and fix the missing risk warning records in the '进出货管理' module when inventory operations exceed the approved drug weight threshold
- Task background: The system has `fireworks_inventory_record` (inventory records), `fireworks_current_stock` (current stock snapshot), and `fireworks_risk_warning_record` (risk warnings) tables. Currently, only `AlarmRecord` is created by `OverStorageDetectionService.checkAndAlert()`, but `RiskWarningRecord` is only generated later by a scheduled task (`dispatchWarnings()`), causing a delay in risk visibility.

## Execution process
1. Analyzed `InventoryRecordServiceImpl.insertByBo()` and `updateByBo()` — confirmed they correctly call `overStorageDetectionService.checkAndAlert()` after syncing stock.
2. Analyzed `OverStorageDetectionService.checkAndAlert()` — confirmed it creates `AlarmRecord` but does NOT create `RiskWarningRecord`.
3. Identified that `RiskWarningRecord` is only generated by the scheduled task `dispatchWarnings()`, which waits for alarms to remain unresolved for 2h/4h/8h before generating warnings.
4. Confirmed that the previously implemented synchronous `RiskWarningRecord` creation has been removed: `OverStorageDetectionService.checkAndAlert()` now inserts only `AlarmRecord`; `fireworks_risk_warning_record` table has no active write source.
