## Task description
- Core requirement: resolve '403 no permission' and 'current user not bound to retail store' errors when accessing the regulatory cockpit interface
- Task background: the regulator role was created and menus authorized, but users still got 403; investigation revealed two independent layers of permission/data isolation that both needed to be configured for the regulator role: Sa-Token's session-based permission snapshot and MyBatis SQL-layer tenant interceptor (PlusTenantLineHandler); the latter was missing the regulator bypass logic

## Execution process
1. Diagnosed the 403 error by checking login logs (18:14:07 login) and verifying the database permission chain returned all 8 expected permissions (fireworks:regulator:statistics + fireworks:alarm:*), concluding it was a session snapshot issue requiring re-login
2. Diagnosed the 'not bound to retail store' error by tracing the exception stack to PlusTenantLineHandler.java, confirming it only bypassed superadmin and lacked regulator support
3. Fixed PlusTenantLineHandler.ignoreTable() by adding case five: check LoginHelper.getLoginUser().getRolePermission() contains 'regulator'
4. Updated documentation (监管后端接口开发文档（零售店）.md) to correct the 2.2 section, removing the incorrect 'tenant isolation requires no changes' statement and adding the new PlusTenantLineHandler bypass logic
5. Verified the fix by restarting the backend service and confirming all 5 regulatory cockpit interfaces succeeded
