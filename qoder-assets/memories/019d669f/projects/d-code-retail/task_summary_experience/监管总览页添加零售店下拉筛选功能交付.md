## Task description
- Core requirement: add a retail store dropdown selector to the right of the "监管总览" title, defaulting to "全部零售店"
- Task background: the regulatory cockpit currently displays aggregated data across all stores; users need per-store filtering for compliance oversight; existing `fireworks_retail_info` table holds valid stores (2 active, 2 deleted), and `@TableLogic` ensures automatic filtering; the original implementation had two issues: (1) the frontend's empty string `value=""` for the "全部" option was interpreted as unselected, causing the UI to show "请选择"; (2) the backend was missing the `/fireworks/regulator/retail-options` endpoint, preventing the dynamic loading of retail store options.

## Execution process
1. Backend: added `RetailOptionVo` (retailId + retailName); extended all 7 regulatory cockpit endpoints with optional `retailId` query parameter; implemented new `GET /fireworks/regulator/retail-options`; updated `RegulatorStatisticsServiceImpl` to apply `retailId` filters across all KPIs, trends, distributions, rankings, and stock snapshots; modified `RegulatorStatisticsMapper` SQL with `<if>` conditions
2. Frontend: added `RegulatorRetailOption` type; updated API wrappers to accept `retailId`; inserted `el-select` in `index.vue` header with default "全部"; wired `handleRetailChange` to reset pagination and reload all 5 modules + escalation list; added `loadRetailOptions` on mount; changed the "全部" option's `value` to the sentinel `'all'` and introduced a computed property `retailIdParam` to conditionally omit the `retailId` parameter when selecting "全部"
3. Documentation: updated interface overview table (added row 8 for `/retail-options`); added "零售店筛选" section explaining `retailId` parameter usage; appended entry to execution台账
4. Validation: backend compiled successfully; frontend lint passed; database query confirmed 2 active stores returned by `/retail-options`; HTTP probe to `http://localhost:8080/fireworks/regulator/retail-options` returned status 200 with `code=401`, confirming the endpoint is now registered and functional.

## Notes
- Using an empty string `value=""` for a default selection option in Element Plus causes it to be rendered as unselected (displaying "请选择"). A sentinel value like `'all'` must be used instead, and the request parameter logic must be updated to omit the parameter when this sentinel is selected.
