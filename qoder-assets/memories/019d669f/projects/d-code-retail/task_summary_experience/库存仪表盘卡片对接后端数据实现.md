## Task description
- Core requirement: connect the four indicator cards in the `summary-grid` section of the `/store/inventory` page to backend data sources
- Task background: the frontend index.vue had hardcoded metric values (118.00, 100.00, etc.); backend APIs existed for inventory records and current stock but lacked a unified dashboard endpoint; the existing `/statistics` API returned cumulative totals rather than daily figures needed for 'today in/out'

## Execution process
1. Backend: created `InventoryDashboardSummaryVo` with fields for current stock weight, approved drug weight, usage ratio, today's in/out weights, and last calculation timestamp
2. Backend: added `queryDashboardSummary(String retailId)` method to `IInventoryRecordService` and its implementation in `InventoryRecordServiceImpl`, aggregating data from `fireworks_current_stock`, `fireworks_retail_config`, and `fireworks_inventory_record`
3. Backend: added `GET /fireworks/inventory/dashboard` controller endpoint in `InventoryRecordController`, resolving the Spring MVC route conflict by placing it before the `/{id}` pattern
4. Frontend: added `InventoryDashboardSummary` type and `getInventoryDashboard()` API function in `src/api/fireworks/inventory/index.ts`
5. Frontend: updated `index.vue` to call the new API on mount, replace hardcoded card values with reactive data bindings, and dynamically set the warning band color based on stock usage ratio (<80% safe/green, 80-100% warning/orange, >100% danger/red)
6. Verified data isolation: `RetailDataScopeHelper.getAccessibleRetailIds()` ensures users only see stores they're authorized for

## Notes
- The dashboard endpoint uses `RetailDataScopeHelper` to automatically filter by user permissions: super admins see all stores, regular users see only their assigned stores
- The warning band color logic is implemented directly in the Vue template using conditional classes
- Route ordering in Spring MVC is critical: `/dashboard` must be defined before `/{id}` to avoid being intercepted
