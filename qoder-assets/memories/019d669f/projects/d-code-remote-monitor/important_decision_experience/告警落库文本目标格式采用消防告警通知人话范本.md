结论：B 方案统一告警落库文本（name/details）的目标形态，采用库内现有"【消防告警通知】"格式为范本——包含 告警类型/设备名/设备位置/部件名/部件位置/发生时间 + 处置指引，正常人可直接读懂。
权衡理由：该格式已在库内存在（eiot_channel_template 模板 15），是全表唯一人话可读格式，直接作为基准无需另造；值班/运营人员无需查编码。
被拒替代：延续机器风格（"事件类型=xxx, devSno=xxx"日志风、"Alert: 配置名, Conditions: [JSON]"的 Java 对象风、"火警 - 23位设备号"风）。
适用与失效条件：适用于 B 方案三条链路（UDP/TCP/AEP）及摄像头链路的落库文本组装；前提是模板变量由统一 AlarmMessage 一等字段提供，避免出现占位符裸露（该模板已有此缺陷先例）。
