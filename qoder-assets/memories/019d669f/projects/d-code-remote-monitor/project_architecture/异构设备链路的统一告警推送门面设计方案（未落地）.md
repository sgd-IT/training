## Goal
为异构 IoT 设备链路（AEP NB-IoT HTTP 推送、大华 UDP/TCP GB/T 26875）提供统一的实时告警推送入口，使下游通知服务与协议实现解耦。注意：这是曾提出但**未在代码落地**的设计草案，现行架构决策相反——设备告警统一写入 eiot_alert_record 并在代码层停用 eiot_device_alert_record，落地前必须先与该决策对齐。

## Steps
Step 1: 定义公共告警事件模型（如 AlertEvent）— 核心字段 deviceId、productKey、alarmType、subType、timestamp、payload，input: 各协议原始报文解析结果，output: 统一事件对象
Step 2: 实现协议适配器（AepAlertAdapter、DahuaAlertAdapter）— 把厂商专有消息转换为公共模型，input: 协议侧事件，output: AlertEvent
Step 3: 构建门面服务（UnifiedAlertPushFacade）— 接收公共模型并路由到下游（WebSocket、短信、邮件、RocketMQ），input: AlertEvent，output: 下游调用
Step 4: 按 productKey/alarmType 配置路由规则 — 决定各告警触发哪些下游服务，input: 配置表，output: 路由决策

## Notes
- 归一化之后才做去重 causes 各协议重复告警重复外发，必须在协议适配阶段前置去重
- 告警优先级与升级规则写死在代码 causes 无法满足不同 SLA，必须按 productKey 可配置
