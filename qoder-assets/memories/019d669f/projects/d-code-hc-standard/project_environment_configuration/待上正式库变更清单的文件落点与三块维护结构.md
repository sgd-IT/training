hc-standard 项目中《待上正式库变更清单》是单个 Markdown 文件，完整路径 ruoyi-admin/src/main/resources/sql/待上正式库变更清单.md（与各 .sql 迁移脚本同目录），是 SQL 变更跨库台账的唯一落点；不得为单次变更另建清单文件。

固定分三块维护：
1. 一、变更记录（待上正式库）——表格形式，每条登记一次变更并注明各库执行状态（⬜ 待执行 / ✅ 已生效）。新的 SQL 变更登记写在这里。
2. 二、存量脚本索引——逐行列出 sql 目录下每个脚本的用途与"是否已上正式库"备注（含 0 字节空文件的标注）。每次登记新变更后须同步更新对应脚本行的备注，保持两块一致。
3. 三、部署提醒——登记非 SQL 的正式部署前置动作。体量为百行内的小文件，可直接整读后局部改写。核对正式库状态的手段是用命令行 mysql.exe 直连 220 查 information_schema.COLUMNS / TABLES 与 sys_menu（只读）。

【2026-09-28 状态更新与发布前全量结构核查结论】(1) 清单第 2 项"平台对接类菜单移动"已于 2026-09-28 在 220 执行完成（move_platform_menus_to_platement.sql：服务记录2698/第三方单位2703/装置开停车2711/大检修2719 由 parent_id 2000→2503、order_num=4~7，脚本自带 BEFORE/AFTER 自检+独立复验双通过），清单表已同步打勾——至此清单内已无待执行项。(2) 全量列级 diff（160=2331 列 vs 220=1968 列，导出 TABLE_NAME.COLUMN_NAME 后 Compare-Object，文件留档 file\col160.txt / col220.txt）："160 有 220 无"共 379 条，逐类处置后结论=**无需新增任何字段**：①约 350 条属 em_*/bz_* 前缀表（em_information/bz_camera/em_personnel 等 20 余张）及 sys_area/sys_f_config/sys_oss——均为该库中共存的其他系统/历史遗留表，全仓 grep 零代码引用（sys_area 唯一命中是 BaseArea.java 注释笔误，项目实际用 base_area）；②涉及本项目的仅 6 条且全部零引用：base_check_content.remark/update_by/update_time、base_check_extend_record.check_pay/check_score_id/danger_id/harm_type、base_duty_schedule.remark——逐一对照 Mapper XML，select/insert/update 均不引用；③所有核心业务表两库列结构完全一致（batch_no/del_flag/sync 字段/专项检查/第三方单位/大检修等均已就位）。比对仅覆盖列存在性，类型/默认值差异未展开。
