## Bug class
Data repair diagnosis failure due to premature assumption of local data corruption.

Root cause
Assumed local business license images were missing without first verifying their existence and accessibility; the actual issue was that the platform sync payload lacks an image field, causing the images to be missing only on the remote platform.

Fix pattern
When diagnosing 'missing' data issues, first verify the local data's integrity and accessibility (DB values, file paths, network reachability, file content) before concluding a platform-side problem.

Reusable lesson
Don't assume local data is corrupted when a 'missing' issue is reported; instead, systematically verify local data integrity first. Applies when debugging data repair tickets where the defect manifests in a downstream system; does not apply to cases where local DB or file system errors are directly observed.

Bug class
Soft-delete implementation failure due to read-only MCP constraints.

Root cause
The MCP is read-only, so the required `del_flag` column cannot be added to the base_contractor table via tool call; the mapper XML must be modified to use `update` instead of `delete` and add `del_flag='0'` filters to all select statements.

Fix pattern
For soft-delete implementation, manually execute `ALTER TABLE ... ADD COLUMN del_flag` on the database; update the mapper XML to replace `delete` with `update set del_flag = '2'` and add `del_flag = '0'` to all `<where>` clauses in select statements.

Reusable lesson
Don't attempt to modify the database schema via read-only MCP tools; instead, provide the DDL for manual execution and update the mapper XML to support soft-delete. Applies when implementing soft-delete in a project with a read-only MCP; does not apply to projects where the MCP supports DDL operations.
