Bug 类：排查记录上报 checkStatus 语义错位，且过滤条件只放行本地"正常"记录。
根因：本地 check_status 语义为 0待检/1正常/2异常/3不涉及/4已逾期（sys_dict_data 字典 + APP 写入逻辑印证），而园区平台枚举为 0正常/1存在隐患/2未排查/3其他；原 BaseRiskTaskRecordMapper 直传 r.check_status 且 getSyncRecordList 过滤 check_status=1，导致 31333 条本地"正常"在平台被标成"存在隐患"，30 条真"异常"从未上传，280 条非 1 状态全部未上传。
修复（2026-09-22）：getSyncRecordList 与 getRecordListByDateRange 的 checkStatus 改为 CASE 映射（0→2、1→0、2→1、3→3、4→2），getSyncRecordList 去掉 check_status=1 过滤、补 r.deleted=0，实现全状态上传并排除已删；two 查询经 SQL 演练与全量编译验证。
遗留：平台侧已收的 31333 条错误显示需重推修正（id upsert 覆盖，属真实外呼须用户授权后执行）；dangerCode 仍为空串（候选 risk_event_code）；checkUserId 仍传创建人昵称非 user_id；近 2 个月时间窗保留。
