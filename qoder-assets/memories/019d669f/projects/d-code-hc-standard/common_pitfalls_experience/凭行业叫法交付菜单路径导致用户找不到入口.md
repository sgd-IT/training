Bug class: 交付给用户的界面操作路径中的目录名不存在，用户按图索骥找不到入口。
Root cause: 把业务领域的行业叫法当成系统内的菜单名写入操作流程。hc-standard 中双重预防机制相关页面实际挂在顶级菜单"风险管理"（sys_menu menu_id=2327，path=risk，parent_id=0）下，其子菜单为风险对象2605/风险单元2472/停机记录2633/风险事件2478/风险管控2484/排查任务2490/排查记录2496/四色图管理2611；系统内不存在"双控"这个目录名，但业务沟通中习惯称其为双控模块，于是助手在操作流程里写成"双控目录"。
Fix pattern: 凡交付界面点击路径，先查 sys_menu 逐级取 parent_id 直到 parent_id=0，用 menu_name 列的实际值拼路径（component 列用于定位前端页面文件，不能当作用户可见名称）；跨环境交付时对测试库与线上库各查一次，两者菜单结构可能不一致。
Reusable lesson: Don't 用领域术语或记忆中的口头叫法充当菜单/目录名称交付给用户，因为用户界面上找不到对应入口会直接阻断操作并需要返工；instead 以 sys_menu.menu_name 实测值为准拼接路径。适用于本仓所有 PC 端（ruoyi-ui）菜单路径交付与操作手册编写；不适用于 APP 端（other1）入口描述，后者由 FragmentHome 图标与 Activity 决定，需查客户端代码而非 sys_menu。
