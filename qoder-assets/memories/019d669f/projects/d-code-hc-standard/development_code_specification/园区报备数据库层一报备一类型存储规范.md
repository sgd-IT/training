The park reporting system requires that each report in the database corresponds to exactly one type; even if a user selects multiple types in the frontend, the backend must split them into separate database rows, each with its own outerId and type value. This ensures compliance with the park's outerId-as-primary-key constraint and enables independent processing (modification, deletion, ticket issuance) for each type.
