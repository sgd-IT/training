结论：人员证书（contractorPeopleCert）修改权限 = 管理员（admin 角色）或证书对应人员本人；本人判定 = base_contractor_people.phone（人员手机号）== 当前登录账号（sys_user.user_name，本系统账号即手机号，149 名承包商人员中 122 名可对上账号）。
理由权衡：证书表无 user_id 关联字段、create_by 历史数据全空，手机号是唯一可用的"账号↔人员"关联；前端行内"修改"按钮用 canEdit(row)（管理员或本人可见），后端 edit 接口做服务端校验（非管理员时查库比对手机号，不通过返回"仅管理员或本人可修改"）。
被放弃方案：仅管理员可改（原 3b2a948 实现，前端 v-hasRole + 后端 @ss.hasRole('admin')）；按 create_by 创建人判定（该列无数据，不可用）。
适用条件：contractorPeopleCert 页面与编辑接口；企业证书（contractorCert）"状态通过=3 仅管理员"的规则不在此口径内。
