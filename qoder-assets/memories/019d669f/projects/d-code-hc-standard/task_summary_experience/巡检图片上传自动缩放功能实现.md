## Task description
- Core requirement: Upload inspection (巡检) images and automatically resize them to an appropriate size for efficient viewing, without manual intervention.
- Task background: Inspection photos taken on mobile devices are often very large (e.g., 3000x2000 pixels), causing slow loading and poor user experience in the web UI. The upload logic is centralized in `FileUploadUtils.upload()`, which is used by all frontend modules (web and mobile).

## Execution process
1. Identified the central upload point: `CommonController.uploadFile` → `FileUploadUtils.upload(baseDir, file, allowedExtension)`.
2. Leveraged the existing `hutool-all` dependency (v5.8.26) to add image scaling logic using `ImgUtil.scale()`.
3. Modified `FileUploadUtils.upload()` to call a new `resizeImageIfNeeded()` helper after the file is saved to disk.
4. The `resizeImageIfNeeded()` helper checks if the uploaded file is a supported image type (JPEG, PNG, GIF), skips GIFs (to avoid frame loss), and resizes only if the longest side exceeds 1920 pixels.
5. Verified the implementation with a self-check script that confirmed correct behavior: 3000x2000 JPG scaled to 1920x1280, small images unchanged, GIFs skipped, non-images skipped.

## Notes
- This change affects all image uploads across the system (inspection, hidden danger reports, enterprise management, avatars), providing a global solution from one choke point.
- EXIF orientation handling (for rotated phone photos) was intentionally omitted as a future enhancement; current implementation is sufficient for the stated requirement.
