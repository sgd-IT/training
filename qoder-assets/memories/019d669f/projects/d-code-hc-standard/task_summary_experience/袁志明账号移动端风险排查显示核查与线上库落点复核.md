## Task description
- Core requirement：核查"袁志明"这个账号在移动端 APP"风险排查"页面是否有数据显示；随后要求直接交付可用 SQL；再要求复核是否误写线上库；最终明确目标环境为线上 220 并要求"只查看"。
- Task background：hc-standard（RuoYi）项目存在两个同名 schema `tgr-gz-vue` 实例——192.168.250.160（主机名 WINDOWS-3D9R3V5，测试库）与 220.203.23.144（anwei1-0001，线上正式库）。移动端风险排查列表按登录用户过滤 base_risk_task_record.check_user_id，详情页由 is_defend 判定"包保任务：是/否"。袁志明的账号经历过删除重建（697→858→862）。

## Execution process
1. 用 HEX(nick_name) LIKE '%E8A281E5BF97E6988E%' 在 160 定位账号，避开 PowerShell 终端中文字面量编码问题；同时按 check_user_name 同法统计 base_risk_task_record 归属分布。
2. 查得 160 上袁志明有 3 个账号：697（del_flag=2 已删）、858（del_flag=2 已删）、862（del_flag=0 有效，user_name=18571056138）；160 上所有排查记录挂在 697 / '696,697' 名下，862 名下 0 条 → 判定测试 APP 登录后四个标签页全空。
3. 交付三份方案 SQL（克隆母本插 c0de0004 造待检包保任务、UPDATE 把 697 名下记录迁到 862、CONCAT 给共享待检记录追加 862），check_user_name 一律用子查询取 sys_user.nick_name 以避免中文字面量乱码；INSERT 用固定主键 id 天然防重复执行。
4. 用户指出"tgr-gz-vue 是线上库"后做三方落点自证：分别在两实例执行 SELECT @@hostname,@@port,DATABASE(),USER()，确认本会话唯一写入（c0de0003）只在 160；比对 c0de% 记录集合，发现 220 上那条 c0dec827...（2025-09-01）在 160 同样存在且已同步，属历史遗留而非本次产生。
5. 补做交叉验证：220 上 cnt_862=5、cnt_697=19、cnt_877=0；160 上 cnt_862=0、c0de0004 不存在、b78b07f7 仍为 '696,697' —— 证明用户尚未执行任何方案 SQL，线上库无本会话痕迹。
6. 切到 220 做只读画像：按 is_defend='1' GROUP BY check_user_id 发现 697 名下有 9 条待检包保任务；再查 sys_user 确认 697/858 在线上同为 del_flag=2；查 check_user_id LIKE '%697%' 与 '%858%' 的形态分布，区分出独占 19 条与共享 '696,697' 13 条（后者不可单独迁移）。
7. 加 --default-character-set=gbk 后中文列（risk_unit_name/check_count）在 GBK 控制台正常显示，查明 19 条包保任务风险单元均为"液氯气化仓库"。
8. 复用 APP 列表 WHERE 做分标签 COUNT（getType 映射 0→check_status=0 / 1,2,3 / 4 / 全部，均含 deleted=0 AND create_time<=NOW()），得出线上 862 实际可见：待检 0、已检 4、逾期 1、全部 5。
9. 用户选"只查看"后停止一切写操作提议，数据保持原样。

## Notes
- 库名相同不等于同一环境：本仓 tgr-gz-vue 在两实例同名，任何结论与交付 SQL 必须按 host 标注目标，并用 SELECT @@hostname 做防呆（WINDOWS-3D9R3V5=测试可写 / anwei1-0001=线上只读）。
- check_user_id 是记录生成时的快照，账号删除重建后历史数据不会自动迁移，会造成"人还在、任务看不见"的假象；判断某人有无数据须同时扫其全部历史 user_id（含已删除账号）。
- LIKE '%862%' 这类子串匹配会连带命中 '696,697' 等共享记录，与等值比较口径不同，给生产库出 UPDATE 前必须先按形态分组确认范围，否则会误改他人共用记录。
- 中文在 Windows 控制台有两种可行路线：查询侧用 HEX() 比对字节，或直接加 --default-character-set=gbk 让人可读；写操作侧则用子查询取中文字段避免字面量传参。
- 线上库曾发现的历史测试数据（c0de 前缀、2025-09-01）易被误判为本会话污染，须靠"两库同 id 同时存在 + create_time 早于本会话"来排除。
