## Task description
- Core requirement: 用户反馈"修改报备信息时弹窗里明明已显示作业类型，点确定仍提示请选择作业类型"，需定位并修复
- Task background: PC 端作业报备表单（ruoyi-ui/src/views/base/TicketBb/index.vue）的作业类型为多选下拉，其值原先存放在组件顶层独立 data 字段 typeLevels 中；而 el-form 的校验规则 prop="typeLevels" 绑定在 :model="form" 上，提交前校验读取的是 form.typeLevels

## Execution process
1. 读文件确认根因：el-form 校验只认 model（form）上的字段，form 上从未定义 typeLevels，故校验恒为 undefined → required + type:'array' 必失败；而下拉框 v-model 绑的是顶层 typeLevels，所以界面有值但校验报错（新增场景同样会报，不止修改）
2. 模板改造：v-model="typeLevels" 改为 v-model="form.typeLevels"
3. 删除组件顶层 data 字段 typeLevels，改在 form 初始化对象与 reset() 中声明 typeLevels: []
4. handleUpdate 回填：把反推得到的类型数组先挂在待赋值的数据对象上再整体赋给 this.form，规避 Vue2 对后补属性的响应式丢失
5. handleTypeLevelChange 三处引用（同类别互斥去重、单值回填）统一改用 this.form.typeLevels
6. submitForm 改造：校验通过后先 const data = { ...this.form } 并 delete data.typeLevels（该字段非后端字段），单条走 addTicketBb(data)；多类型分支不再重复声明局部 data，直接 data.typeLevels = this.form.typeLevels.map(v => this.parseTypeLevel(v)) 后走批量接口，保持后端按类型拆单逻辑不变
7. 验证：Grep 全文件确认无残留顶层 this.typeLevels 引用；GetProblems 检查无语法错误；Grep 确认 ruoyi-admin/ruoyi-framework 未开启 FAIL_ON_UNKNOWN_PROPERTIES（Jackson 仅定制 timeZone），多传字段不会导致后端反序列化失败
