## Task description
- Core requirement：在"最近一周代码变更快诊"发现的三处缺陷中，用户明确指示"只改1、3"，即修复定位 WebSocket 断线不重连与服务记录上报失败仍显示已同步两处问题，第2项（企业证书新增可绕过审核）不改。
- Task background：ApiLocationWebSocket.onClose 中重连线程创建后从未 start()，且 WebsocketClientServiceImpl 心跳循环里 send 异常会令线程退出，一次断线后定位报警永久收不到；BaseServiceRecordServiceImpl.sync 的业务异常分支被外层吞成日志，不回写失败状态，本地与平台状态不一致。

## Execution process
1. ApiLocationWebSocket.java：移除 onClose 中另起线程做重连的逻辑，把重连职责收敛到心跳线程，避免重复重连。
2. WebsocketClientServiceImpl.java：改造既有心跳循环——连接已关闭时先 reconnectBlocking()，连接成功后才发送心跳；连接/发送异常捕获后继续下一轮循环不退出线程，仅在 interrupt 时退出。
3. BaseServiceRecordServiceImpl.java：将 sync 的异常分支改为先 updateSyncResult(id, "2", e.getMessage(), null) 回写失败再 rethrow，并删除原第170行的重复失败回写。
4. 关键决策：updateSyncResult 最后一个参数必须传 null，只更新本次同步结果、不清除历史成功标记 synced，保证重试仍走正确的 save/update 路由（依据 base_service_record.synced 列语义）。
5. 验证：设 JAVA_HOME 后用 mvn -o -pl ruoyi-system -am compile -DskipTests 离线编译通过；GetProblems 因语言服务器未就绪不可用；git diff --stat 确认仅三个目标文件被改，未触碰 BaseContractorCert 相关代码与用户已有的 BaseThirdPartyUnitService.java 修改；未执行 git commit。
