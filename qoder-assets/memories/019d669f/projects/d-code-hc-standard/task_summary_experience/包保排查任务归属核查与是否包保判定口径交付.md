## Task description
- Core requirement：用户连续五问——①"把排查任务都改为 862 这个账号可以吗"；②"看看以前那些账号排查任务"；③"给我 SQL 查询是哪些排查任务"；④"袁志明"（要袁志明视角明细）；⑤"怎么确定是包保的排查任务"；⑥"那我直接让用户在排查任务新增就好了对吧"。
- Task background：hc-standard（RuoYi）园区对接中，包保履职由 base_risk_task（配置）+ base_risk_task_record（记录）承载；液氯气化仓库（risk_unit_id=334b8aa659464ade8d5bda20c68fc8af）是全系统唯一挂有负责人任务的单元。前序会话已确立"风险单元停机级联停用其下全部排查任务""恢复走风险单元工作状态开关"两条机制。目标库为线上 220.203.23.144（anwei1-0001），按口径全程只读。

## Execution process
1. 先重跑现状再作答（沿用"基线会变"教训）：GROUP BY work_type,check_user_id,status 查得 28 条负责人任务已全部 status=0（启用）、task_next_time 统一重置为 220 当天日期——证明有人已通过风险单元切"开"完成恢复，推翻了上一轮"仍处停用"的读数。
2. 查 base_risk_unit + base_risk_unit_log 交叉验证，发现关键矛盾：单元 status 已切"开"，但最新那条停机记录（9-22 起、计划 10-05 恢复）的 activationTime 仍未被结掉 → 推断当晚 23:30 的自动同步会因"当前时间仍落在停机区间"把单元自动切回"停"（不影响已启用的任务表）。
3. 回答"都改 862"：区分两种范围——主要负责人 9 条本就已迁至 862（无需再改）；若要连技术负责人 696/操作负责人 835 的 19 条一并改到 862，技术上可行但业务上等于把三级包保职责压给一人且原责任人不再收任务，须先向客户确认职责口径；给出 UPDATE base_risk_task SET check_user_id/check_user_name（子查询取 sys_user.nick_name）并预期影响 19 行，强调须在次日 00:10 生成新批次前执行。
4. 拉"以前那些账号"全景：配置层 862/袁志明 9 条、696/朱文浩 9 条、835/夏翔飞 10 条；记录层 is_defend='1' 全库约 395 条 = 夏翔飞 350（含 2 条"异常"真实履职）+ 朱文浩 26 + 旧号 697 名下 19（9 待检+10 已检），另有 '696,697'、'696,698' 共享日常记录不可单独迁移。
5. 交付三条可复用 SQL（均标注 220 执行、命令行加 --default-character-set=gbk）：①单元内全部任务明细（含 troubleshoot_content、周期、task_next_time）；②按人员/类型汇总；③某账号名下记录明细（LIKE 匹配会连带命中共享记录，需独占时改等值）。所有 SQL 先实跑验证再交付。
6. 回答"怎么确定是包保"：用两个字段判定——配置 work_type<>'0'、记录 is_defend='1'，两者是上下游继承关系；实测 862 名下 5 条记录 is_defend=0 对应配置 work_type=0（日常），join 校验一致；三层入口分别为 DB、PC 排查任务列表"任务类型"列（PC 记录列表不显示该标识、需点开表单）、APP 详情页"包保任务：是/否"。
7. 回答"让客户自助新增即可"：确认可行并交代四点注意（类型必须选三类负责人否则不成包保、检查人员勿选已删旧账号、保存后次日 00:10 才生成、新增即默认启用）与两个边界（改/停非自助、替换旧任务须先停旧以免双份派发），并提醒液氯这条线已就绪无需新增。

## Notes
- "已生成的记录不跟人走"：改配置的 check_user_id 只决定后续批次派发，历史记录归属不变；若同时要历史可见须另迁 base_risk_task_record，且 LIKE 子串匹配会误伤 '696,697' 这类共享记录。
- 单元切"开"≠状态稳定：若 base_risk_unit_log 的停机区间未被结掉（activationTime 为空或在未来），自动同步会按停机区间把单元状态回切，故恢复动作要连停机记录的收尾一起核查。
- 数据基线在多轮之间会变（本轮从"28 条停用"变为"28 条启用且 next 重置为当天"），任何"当前状态"结论前必须重跑现状查询。
- 中文列在 Windows 控制台可读输出靠 mysql 客户端加 --default-character-set=gbk；写操作中文字段一律用子查询取 sys_user.nick_name 避免字面量乱码。
