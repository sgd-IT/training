## Task description
- Core requirement：把承包商人员证书（contractorPeopleCert）的"修改"权限从"仅 admin 角色"放开为"管理员或证书人员本人可修改"（用户口头确认口径："管理员和本人可修改吧"）；同时向用户提供 base_ticket_bb 补 batch_no 列的 ALTER SQL；需求55（按钮恢复）按用户指示不再处理。
- Task background：原实现由提交 3b2a948 引入——后端 BaseContractorPeopleCertController.edit 用 @PreAuthorize("@ss.hasRole('admin')")，前端列表两处按钮用 v-hasRole="['admin']"。证书表无 user_id 字段、create_by 历史数据全空（27 条记录 create_by 均为空串），无法按创建人判定"本人"。

## Execution process
1. 关联链路取证：查 information_schema 确认 base_contractor_people 有 phone 列、证书表只有 people_id；查 sys_user 发现本系统登录账号 user_name 即手机号；统计得 149 名承包商人员中 122 名的 phone 能与 sys_user.user_name 对上，27 条证书全部能经 people_id → phone → 账号打通，故选定"手机号 == 当前登录账号"作为唯一可行的本人判定。
2. 项目内先例检索：BaseTicketYbServiceImpl 已有 `!ticketYb.getCreateBy().equals(SecurityUtils.getUsername())` + "非本人创建数据，不允许删除"的写法，沿用 SecurityUtils.getUsername() 做账号比对；PermissionService.hasRole("admin") 作管理员判定（兄弟控制器同款用法）。
3. /ruoyi-system/src/main/resources/mapper/base/BaseContractorPeopleCertMapper.xml：selectBaseContractorPeopleCertVo 的 LEFT JOIN base_contractor_people 增取 p.phone，resultMap 增加 phone 映射，使列表查询与按 id 单查都能带出人员手机号。
4. /ruoyi-common/.../entity/BaseContractorPeopleCert.java：新增 phone 展示字段及 getPhone/setPhone。
5. /ruoyi-admin/.../controller/base/BaseContractorPeopleCertController.java：edit 方法去掉 @ss.hasRole('admin')，改为注入 PermissionService，非管理员时按 id 重查库并比对 db.getPhone() 与 SecurityUtils.getUsername()，不匹配返回 AjaxResult.error("仅管理员或本人可修改")。
6. /ruoyi-ui/src/views/base/contractorPeopleCert/index.vue：行内"修改"按钮由 v-hasRole="['admin']" 改为 v-if="canEdit(row)"（admin 角色或 row.phone === 当前登录账号）；顶部批量"修改"保持仅管理员。
7. 验证：mvn -DskipTests -q compile 得 COMPILE_EXIT=0；ESLint 校验该 vue 文件失败——文件被 .eslintignore 排除，--no-ignore 强制检查暴露约 199 条既有风格报错，判定为非本次引入、不予处理。
8. 交付说明中提示两点遗留：企业证书页 contractorCert"状态通过=3 仅管理员"规则未同步放开；本人账号目前多只有 APP 端角色、缺 PC 端菜单角色，规则先把口径定死、有入口后自动生效。所有改动均留在工作区未提交。
