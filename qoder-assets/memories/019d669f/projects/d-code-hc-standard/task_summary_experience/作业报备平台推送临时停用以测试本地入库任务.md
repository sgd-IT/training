## Task description
- Core requirement：用户要求把"作业报备"的推送（上报园区平台）接口注释掉，以便在园区环境不可用/联调前单独测试本地入库
- Task background：作业报备（BaseTicketBb / TicketBb 菜单）原有实现是"先上报园区、成功才落库"——新增与修改走 reportPlatform → PlatementPrepareApi.save，删除走 api.delete；园区失败会抛"平台上报失败，报备未生效"，导致本地无法存下任何数据，阻塞入库测试。会话前半段还确认了人员证书（BaseContractorPeopleCert）口径不同：新增后同步上传但失败仅记日志不回滚，修改与删除完全不上报

## Execution process
1. Grep 全仓定位 PlatementPrepareApi / prepareApi 引用，确认推送入口唯一集中在 BaseTicketBbServiceImpl（避免漏改其他模块）
2. insertBaseTicketBb：注释掉写库前的 reportPlatform(baseTicketBb)，改为直接落本地库
3. updateBaseTicketBb：同样注释 reportPlatform，修改只写本地
4. deleteBaseTicketBbByOuterId：注释 api.delete(outerId)，删除只删本地（否则测试期删除同样会被园区阻塞）
5. 三处统一留恢复标记注释「暂禁用平台推送：联调确认后恢复（解除下面注释即可）」，保留 reportPlatform 方法本体不删，便于后续一键回滚
6. 执行 mvn -DskipTests -q compile -pl ruoyi-system -am 验证，退出码 0；PowerShell 下额外用 Write-Output "COMPILE_EXIT=$LASTEXITCODE" 显式回显退出码以确认成功
7. 向用户说明影响面：PC 批量接口 /base/TicketBb/batch 与 APP 端 batchAddTicketBb 均委托同一 insertBaseTicketBb，一处改动同时覆盖两端，前后端无需额外修改；改动仅留在工作区未提交

## Notes
- 测试期间入库的报备属于"从未推送过园区"的数据；恢复推送后需对这些记录做一次修改保存（园区侧为 saveOrUpdateBatch upsert 语义，修改即自动补推），或直接删除重报
- 禁用推送后本地不再出现"有记录但园区没有"的状态；也正因原逻辑失败不落库，前端一直没有同步状态列与重试按钮；若今后要支持离线录入，需另加同步状态字段承载重试
- 批量拆单场景下某条失败即停且已成功条目不回滚，这一行为在推送禁用后暂时不会触发
