## Task description
- Core requirement: diagnose and fix the 'Safety production report cannot be opened' issue in the RuoYi project's platement/baogao module
- Task background: the baogao list.vue displays reportFile as plain text with no clickable link; database stores full URLs like 'http://localhost:28080/profile/upload/...', which fail for other users; root cause is CommonController returning absolute URLs

## Execution process
1. Identified the frontend location: ruoyi-ui/src/views/platement/baogao/index.vue, where reportFile column was plain text
2. Added a clickable '查看' link using window.open() to open the file
3. Detected that existing database records store full localhost URLs due to CommonController.java returning serverConfig.getUrl() + fileName
4. Updated the frontend open logic to handle both relative paths (VUE_APP_BASE_API + file) and full URLs (direct open)
5. Provided SQL to fix existing localhost data: UPDATE platement_baogao SET reportFile = CONCAT('/profile', SUBSTRING_INDEX(reportFile, '/profile', -1)) WHERE reportFile LIKE '%/profile/%'

## Notes
- The backend CommonController's absolute URL return affects all FileUpload usages system-wide; changing it has high blast radius and requires separate evaluation

## Task overview
Successfully diagnosed and fixed the '安全生产报告无法打开' issue: added frontend open link, updated open logic to handle both relative and absolute URLs, and provided SQL to correct existing localhost-stored URLs in the database.
