## Notes
- RuoYi 动态路由在登录时构建，改完 sys_menu 可见性后必须重新登录或刷新页面才会出现新菜单。
- 排查记录表列名是 is_defend（实体字段 isDefend），直接按 isDefend 查询会报 Unknown column。
- PowerShell 下 mysql.exe 的 -h192.168.250.160 会被截断成 host=192，参数须写成 -h "192.168.250.160"；含中文的 SQL 用 -e "source d:/path/x.sql" 从文件执行以避开命令行编码问题。
- 包保责任人页面此前"看起来能用"是因为只能通过从业人员弹窗进入，隐藏菜单放出来才暴露出依赖 props.person 的一串崩溃点；同类"弹窗嵌入组件"转独立菜单前必须先查 props 依赖。
- 目录与子菜单原本同名（包保责任人>包保责任人），故顺手把目录改为"包保管理"。
- 【2026-09-22 更新】第 8 步的废弃接口清理方案已在后续会话全部落地（不再是"未落地待确认"）：PlatementImplementTaskServiceImpl 重写去除先推后插与 syncToPlatform，PushDataServiceImpl 删除 rePushImplementTask 及其字段/import，PushDataController 删除 POST /push/implementTask 端点，PlatementImplementPersonApi.task()/taskBatch() 与 OpenApiConstant.ImplementPerson.task 加废弃 Javadoc；mvn -DskipTests -q compile 全量编译通过。
- 【2026-09-22 更正】本条原述"替代链路 base_risk_task_record 3.16 万条活跃、78 条已同步即视为可用路径"不准确：后续实测发现本地 check_status 枚举（0待检/1正常/2异常/3不涉及/4已逾期）与园区 checkStatus（0正常/1存在隐患/2未排查/3其他）语义错位，原实现直传数值，导致 31333 条"正常"在平台侧被标成"存在隐患"、真隐患 30 条从未上传；该链路已在 mapper 两条同步查询中加 CASE 映射（0→2、1→0、2→1、3→3、4→2）并放开全状态、补 deleted=0 后才是真正可用的替代路径。
- 【2026-09-22 再次更新】第 4 步"从业人员远程搜索下拉"已再次演进：因 element-ui 远程下拉展开时不会自动调用 remoteMethod（点开是空的、必须输入姓名才出选项），用户要求"点开即可下拉选择"。现实现为：@visible-change 展开时调用 searchPerson('') 加载前 100 条默认列表、输入关键字仍远程过滤；去掉修改时只读 el-input，修改也可换从业人员，当前已选人员通过回显保护补入 options；嵌入从业人员页弹窗场景（props.person 预填）行为保留。
