hc-standard 仓库 .gitignore 的实际边界（经 git check-ignore 验证）：

- 根目录 .gitignore 未忽略以下产物，它们会出现在 git status 的未跟踪列表中，提交前必须手工排除：*.class、*.jar（ruoyi-quartz.jar、ruoyi-system.jar、ruoyi-system-new.jar）、ruoyi-ui/dist.zip、hello.pdf、nul、create-pdf.js、根目录 package.json 与 package-lock.json、skills-lock.json。
- file/ 目录整体未被忽略，内容混杂：既有需求清单文档（特殊作业票相关修改测试清单.md、预警报警信息远传与闭环处置需求清单.md、人员定位及相关需求清单.docx），也有大量联调临时文件（captcha.jpg、captcha_resp.json、token.txt、lic_*.jpg 等），是否入库需按用途分开决策。
- other1/（APP 端 Android 工程）：自 2026-09-24 起根 .gitignore 第 56 行已加 /other1/ 忽略整个目录（用户要求），不再出现在未跟踪列表；此前状态为整目录未跟踪（其自带 .gitignore 会过滤 .gradle、.idea、build、jks 密钥，仅剩约 500 个源码与 gradle 配置）。
- ruoyi-admin/src/main/resources/sql/ 下存在 0 字节空脚本（add_implement_soft_delete.sql、fix_contractor_file_path_port.sql、base_duty_schedule.sql），提交前应先判断是否为漏写内容而非直接收录。

补充（git add 执行注意）：在 Windows 下用 git add 添加形如 src/main/resources/mapper/base/BaseXxxMapper.xml 这类以连字符开头的目录段（mapper-base 型路径中 mapper\base / mapper\resources 等以 "-" 起始的路径片段）时，若路径被解析成命令行选项会导致 add 失败，须用双引号包裹完整路径再传给 git add（实测 "ruoyi-system/src/main/resources/mapper/base/BaseThirdPartyUnitMapper.xml" 加引号后成功）。
