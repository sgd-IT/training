hc-standard 园区基础资料类模块（第三方单位 thirdPartyUnit、装置开停车 deviceCtrl、大检修 overhaul）已按 ponytail-review 结果重构为基类模式（2026-09-23）：

- Controller（ruoyi-admin/.../web/controller/base/）：薄透传，统一用 PlatementBaseApi.requireSuccess/requireId/createdId 包装平台返回。
- Api（ruoyi-common/.../platement/api/）：三个资源继承抽象基类 PlatementResourceApi，子类构造器传 (save, detail, page) 三个 URL 常量；save/delete/getById/page 由基类实现。PlatementThirdPartyUnitApi 额外覆盖 save（附件校验）并提供 update。
- Service（ruoyi-system/.../base/service/）：三个资源继承 AbstractPlatementResourceService<T, M>，基类承载 get/list/add/validate/sync/delete/claim 及"不确定状态机"；子类只需 @Autowired 字段（mapper/api/fileApi/validator）+ 3 个访问器（resourceMapper/fileApi/validator）+ 钩子（notFoundMessage/attachmentFiles/toPlatformBody/apiSave/apiDelete；第三方单位另加 supportsUpdate/successMessage/apiUpdate）。实体 implements PlatementSyncRecord，Mapper extends PlatementResourceMapper。
- 前端：deviceCtrl/overhaul 共用 ruoyi-ui/src/views/base/mixins/platementResourcePage.js（页面提供 resourceName/syncTip/query/platformFields/unitCodeRules/rules 与 fetchList/fetchDetail/saveRecord/syncRecord/deleteRecord/newForm 六钩子）；三页共用 components/PlatementQuery 平台查询弹窗。
- 自检脚本 BasicModulesCheck（src/test）已于 2026-09-23 按用户决定删除（判定后续无用）；如未来重建类似自检或再次重构这三个 Service，注意其曾依赖：new Service() 无参构造 + 反射注入子类字段（mapper/api/fileApi/validator，getDeclaredField 不查父类）+ static buildBody 静态方法。
- 服务记录模块独立：BaseServiceRecordServiceImpl + PlatementValidator.validateServiceRecord（helper 压缩版，消息格式不变）。
