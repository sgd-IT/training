排查任务配置（base_risk_task）的同步状态在修改链路上会被前端隐式继承：PC 两个页面 riskTask/index.vue 与 riskMeasure/taskIndex.vue 的 handleUpdate 都是 `this.form = response.data` 整条回填、submitForm 再把整个 form 提交给 updateRiskTask；域对象 BaseRiskTask 的 syncStatus/syncResult 没有 @JsonIgnore，Mapper 的 updateBaseRiskTask 用 `<if test="syncStatus != null">sync_status = #{syncStatus},</if>` 条件写回。因此后端 update 即使不主动重置，也会把库里已有的 '1' 原样写回去——判断"修改后是否会自动重推"不能只查后端有无重置逻辑，前端整体回填同样是同步状态不被重置的来源。列默认值实测为 sync_status DEFAULT '0'、work_day_type DEFAULT '0'（char(1) 可空），insertBaseRiskTask 不写该列，故新增记录必然落在 quartz DataSyncTask.syncRiskTask 的扫描集合（sync_status is null or in ('0','2')）内。要让某次修改重新推送，必须显式改变 sync_status（重置为 '0' 或落库后立即调 sync）。该约束适用于所有沿用 RuoYi "form=response.data 整条回填"表单模式的 base 模块页面。
