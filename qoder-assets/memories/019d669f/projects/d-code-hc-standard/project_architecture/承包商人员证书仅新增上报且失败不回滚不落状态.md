承包商人员证书（BaseContractorPeopleCertServiceImpl）与园区平台的对接结构（实测确认）：

1. 外呼只发生在新增一处：insertBaseContractorPeopleCert 在写完本地库之后同步调用园区从业人员 saveOrUpdate（含把证书附件换取 fileId）。整段用 try-catch 包住，失败只 log.error，不回滚本地事务、不记录同步状态、也没有重试入口，因此会出现"本地有、园区没有"的不一致，且从库里看不出来。
2. 修改与删除完全不再调平台：updateBaseContractorPeopleCert 及删除只操作本地库，即证书内容（附件、证书编号）变更后园区侧不会更新，需人工在平台侧同步或走从业人员的批量接口重推。
3. 时序特征与作业报备相反：报备是"先上报成功才落库"（库里不存在待同步记录），证书是"先落库再尽力上报"（库里可能存在园区缺失的记录）。判断某个园区对接实体的同步行为时必须逐实体读其 ServiceImpl，不能按"同属 base 模块"套用——同为删除动作，作业报备会上报园区、人员证书不上报。
