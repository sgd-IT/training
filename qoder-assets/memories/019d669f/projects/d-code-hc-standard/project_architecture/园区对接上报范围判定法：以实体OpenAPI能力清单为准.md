## Usage Scenario
维护 hc-standard 园区 OpenAPI 对接模块时判断"某实体的删除是否要同步平台""上报字段该取什么值"。

## Usage Method
核心方法：上报范围与字段取值按每个实体在平台侧已封装的接口能力逐个决定，绝不按模块统一、也不按相邻模块的实现推断。判定依据是"该实体在已封装 OpenAPI 中有哪些接口"——只有 saveOrUpdateBatch（批量新增/变更）即视为无删除上报能力，只能本地删除；具备软删语义的实体（如从业人员 practitioners）才走"setDeleted(\"1\") → syncToPlatform 成功 → 再执行本地删除"的顺序，接口失败则中断本地删除并抛异常。各实体的具体删除口径见对应专条（包保责任人、作业报备、人员证书等）。

凡涉及状态类字段，必须核对本地 sys_dict_data 字典与平台文档枚举是否同义——两侧数值相同不代表含义相同，不同义时在 SQL 用 CASE 做值映射而非直传。

失效条件：若园区平台后续为某实体提供真正的删除接口或明确接受 deleted 软删语义，则该实体改走软删上报，本方法结论需重新评估。

## Notes
- 跨环境同名表的同步状态可能相反（一侧未同步、一侧推送失败），下结论前须逐环境分别取证。
- 把某实体的字段映射结论套到另一实体会引入错误外呼或错误语义并需整体回滚。
