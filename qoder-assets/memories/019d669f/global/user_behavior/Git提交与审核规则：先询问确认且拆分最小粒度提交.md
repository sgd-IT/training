用户的长期 git 行为规范（已写入用户级规则文件 C:\Users\Administrator\.qoder\rules\git-commit.md）：(1) 任何 git commit 或代码审核（review）操作之前，必须先向用户展示变更摘要并等待用户明确同意；获得整体同意后，每个单独提交执行前仍需逐个展示该提交摘要并等待确认，多个提交不得在同一条命令或同一批次中连续执行；(2) 提交必须拆分为最小逻辑单元：一个提交只包含一个功能点/修复点，即使两处修改位于同一行代码（如同一 SQL 里的两处独立逻辑修正），也必须拆成两个提交；(3) 原因：一次性提交或连发会影响后续查阅、回溯和 review。
