执行 git 提交前，先按 code-comment-style 规范检查本次改动涉及的新增/修改注释：对照"解释为什么而非是什么、长逻辑剧透、坑位预警、TODO 具体、密度控制"逐条评审，输出检查报告；需要改写的只动注释不动代码逻辑，检查通过后再走提交流程（提交信息仍先经用户确认）。

边界（2026-10-28 因用户问责"你删除注释干嘛"后补充，必须遵守）：
1. 该检查默认只输出报告与建议，不得擅自改写或删除注释后再提交；是否改写须取得用户明确同意。
2. 若改动对象是用户手敲训练产出的代码（hand-typing-training 的填空实现），其注释是学员的学习痕迹与思考过程记录，即使被判为"复述代码的废话"也一律不动，包括行内短句、多行 Javadoc 格式、@param/@return 空标签、分节注释、多余空行。
3. 已经误删/误改后，须先精确列出每一处被删或被改写的内容（位置 + 原文），再从手头保留的原始文本全量还原，不得只挑部分恢复。
