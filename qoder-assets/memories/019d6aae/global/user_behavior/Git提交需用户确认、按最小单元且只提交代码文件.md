执行 Git 提交前，必须先向用户展示待提交文件的完整清单与每个提交的完整提交信息（标题 + 正文全文，不只 subject 一行），并等待用户明确回复确认后才能执行 git add 与 git commit；禁止用选项式确认弹窗（例如"按推荐执行"）代替用户的明确回复，用户未回复前不得改动仓库状态，也不得擅自改动业务文件（如登记 SQL 清单）后直接提交，改动过的文件必须先把 diff 贴出再等确认。提交信息统一按 Conventional Commits 格式：type(scope): 中文描述，type 与 scope 用英文小写（如 feat(alert)、refactor(ai)），描述用中文。提交粒度按最小单元：一个提交只包含一个逻辑单元（单文件优先），禁止把多个文件的改动合并进同一个提交。提交范围只含代码文件，配置文件（.env*、pom.xml 等）不提交，保留在工作区即可。推送（git push）是与提交完全独立的授权动作：用户说"提交"只表示 commit，绝不等于允许 push；push 前必须单独列出将要推送的提交清单并获明确同意。为推送而执行的 stash、fetch+rebase、pull 等会改变工作区状态或重写本地提交 sha 的操作，同样属于独立授权范围，必须先征得同意再执行。
