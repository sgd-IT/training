方案形成与执行前，必须先盘点框架与代码库的现成能力（framework 各 spring-boot-starter、各 module 暴露的 Api/Service）以及已有数据库表（结构、字段演进、数据债、预留字段），基于盘点结果再定方案，优先复用，避免重复造轮子和不必要的新表新列。典型例子：SmsSendApi 等框架能力曾被闲置；告警推送统一方案冻结后，先盘点 websocket starter（多种 sender、会话租户过滤、双向通信、sendObject default 方法）与 eiot_alert_record 字段演进、push_post_ids/push_enabled 定向推送预留，确认零新增依赖后才落地方案。
