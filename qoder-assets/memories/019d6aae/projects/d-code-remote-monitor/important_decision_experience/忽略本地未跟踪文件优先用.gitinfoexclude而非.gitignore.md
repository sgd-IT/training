Conclusion: 当需要让某些未跟踪文件（如本地运维 SQL 脚本、项目内部文档）不再出现在 git status 且永不入库时，写入仓库的 .git/info/exclude，而不是修改 .gitignore。
Rationale (trade-off): .git/info/exclude 是纯本地仓库配置，只对本机生效、不会被提交、不污染协作者的忽略规则；而写 .gitignore 会新增一个需要提交进版本库的文件改动，与"这些文件本来就不该进仓库"的诉求矛盾，反而制造一次额外提交。
Rejected alternatives: 用 .gitignore —— 本身也能忽略，但会把忽略规则带进版本库影响他人，且要为这个 .gitignore 改动本身再做一次提交；直接删除文件 —— 会丢失磁盘上的内容，不可接受。
Applicable / expiry conditions: 适用于"个人本地不想跟踪但又不必全局共享忽略规则"的少量特定文件；若忽略规则需要团队共享（如构建产物 target/、node_modules），应改用 .gitignore。中文文件名路径在 exclude 里按 UTF-8 字节匹配，写完须用 git status 验证 ?? 条目确已消失。
