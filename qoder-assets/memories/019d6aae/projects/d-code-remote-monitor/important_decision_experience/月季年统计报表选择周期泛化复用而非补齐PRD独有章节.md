Conclusion: 消防值守中心统计报表（月/季/年）采用"把既有月度报告 PDF 的 month 参数泛化为 periodType+period、并复用现有 8 节章节只换时间窗口"的方案；不补齐 PRD-05 §3.2.4/§3.2.5 定义的季报/年报独有章节。

Rationale (trade-off): 盘点证实 ReportPdfWriter/PdfReportUtils 的绘制原语与"月"零耦合，周期泛化的工作量集中在聚合层窗口切换与文案参数化，风险最低且版面风格天然一致；而 PRD 季报的"安全评估/风险分析/合规性检查"、年报的"重大事件回顾/资源需求"中，"合规性检查""资源需求"经全仓库检索确认无任何数据源（只能 AI 泛述或人工留白），补齐会使工作量约翻倍却不提升可验证的交付质量。

Rejected alternatives: ① 为季报/年报新写独立三套报表实现——被否，因为渲染层完全可复用，分开做反而要返工；② 严格对齐 PRD 独有章节口径——被否，因无数据源项无法自动生成，且用户选择先保交付；③ 顺带补 PRD 月报内容表要求的"维保执行情况/巡检完成率/值班合规性"三项——被否，当前 8 节本来就没有这三项，纳入会使范围失控（getRepairStats 还是无时间窗口的当前状态快照，需另补窗口化 SQL）。

Applicable / expiry conditions: 该决策在"验收口径以现有 8 节 + 三周期为准"的前提下有效。若后续进入正式验收阶段要求逐条对齐 AC-F5.2.010~033（含自动生成、审核签发、签发后锁定归档），或业务方提供合规性检查/资源需求的数据来源，则必须重新评估章节补齐方案；同时注意本决策未涉及 PRD 月报原有的维保/巡检/值班三项缺失，那仍是遗留差异。
