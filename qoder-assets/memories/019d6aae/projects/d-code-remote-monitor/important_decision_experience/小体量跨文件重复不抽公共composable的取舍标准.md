Conclusion: 代码简洁度评审中，对"注释+3行逻辑、仅出现在 2 个文件"的前端重复片段判定为不建议抽取公共 composable，保持就地重复。

Rationale (trade-off): 抽象的收益随重复规模增长，而间接层的阅读成本固定；3 行 × 2 文件的抽取省下不足 5 行，却让后续每个改动都要跨文件跳转，且两个页面各自依赖独立的刷新函数与不同 UI 演进方向，强行共用需把差异塞进参数。

Rejected alternatives: 抽 useUdpDeviceEvent 之类共享 hook —— 该方案本身可行，只是在本例规模下净收益为负；同理 switch 改 Map 查表、删除语义化薄包装在纯减行口径下成立但在可读性维度是负优化。

Applicable / expiry conditions: 适用于重复块 ≤3~4 行且仅 2 处、两处后续可能各自分化的场景；当同一逻辑扩展到 3 处以上、行数增多或出现行为必须严格同步的要求时应重新评估并抽取。不适用于常量、类型定义等本就该单点导出的内容。
