Bug class: 编辑类工具读到的文件内容与磁盘真实内容不一致，导致按该视图构造的替换原文匹配失败。
Root cause: 任务中对 module-eiot 的 RemoteControlCodeServiceImpl.java，Read 工具返回一个 50 行版本（StringRedisTemplate、无 verifyCode），而 ripgrep 命中 56+ 行且含 verifyCode，node fs.readFileSync 读到磁盘为 70 行版本（RedisTemplate + verifyCode）；即编辑器缓冲/索引视图与磁盘工作区内容并存差异。另 PowerShell Get-Content 输出中文注释乱码，无法据此判断编码或内容。后果：按 Read 视图拼出的 original_text 使 SearchReplace 直接失败，并一度误判"实现类缺接口方法会编译不过"。
Fix pattern: 修改前用独立通道核实磁盘字节——node -e 打印 size/mtime 并输出指定行区间（必要时把内容 dump 到新临时文件再用 Read 读，新文件不受缓存影响），以 git status/git diff 交叉确认工作区状态；original_text 一律取自核实后的磁盘内容，而非首次 Read 结果。
Reusable lesson: 不要在一次任务里只凭单次 Read 的结果就构造精确替换原文，因为当存在未保存编辑缓冲或索引滞后时该视图可能与磁盘不同，会使替换失败甚至改动被覆盖到错误版本；必须先经第三方通道核实再改。适用于对同一文件出现工具结果互相矛盾（Read/Grep/终端行数或符号不一致）的场景；不适用于刚由本 agent 自己写入且已验证成功的文件。
