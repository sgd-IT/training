Bug 类：同一个处置动作在列表卡片和详情弹窗里各写一份 `v-if` 守卫，弹窗那份漏了状态判断，导致已闭环工单仍能点「确认火警」「确认设备故障」，点下去会把工单重新打开。根因：列表卡片写的是 `isOpenStatus(status) && alarmType === 'x'`，详情弹窗只写了 `alarmType === 'x'` 这半截条件，两处不同源。修复模式：同一操作出现在两个入口时，可见条件必须逐字对齐（最好抽成一个判断），改一处就要同时核对另一处。适用范围：anwei-fire-remote-monitor-vue 的 alarm-order 页，以及任何"列表行内操作 + 详情弹窗操作"双入口的页面；单入口场景不适用。

## Notes
- 新发现：本次任务中，详情弹窗底部的「确认设备故障」按钮也漏掉了 `isOpenStatus` 守卫，与「确认火警」是同一类缺陷，已一并修复。
