Bug class: 按 hunk 拆分原子提交时的"关键词泄漏"校验出现假阳性，把合法提交误判为跨主题污染并中止。

Root cause: 校验脚本用 git diff --cached 的全文本来判定「不应含关键词」，但该文本同时包含被删除的旧行（形如 -const pendingToast = ref(false)）与本次新写入的说明性注释（如在恢复方式注释里写 <IFrame :src="src" />）。这两类命中都不是"本笔引入了别的主题改动"，前者是拆分的必然产物，后者是文档性文字，于是 mustNot 校验连续两笔误报 F5(pendingToast)、F7(IFrame)。

Fix pattern: 双向关键词校验只作用于以 + 开头且非 +++ 的新增行集合——先把 git diff --cached 按行过滤出 addedLines 再做 must / mustNot 判定；若某关键词本身合法地出现在预期的新增注释里，应把它从 mustNot 移除而不是改代码或放宽整个校验。

Reusable lesson: Don't 对整段 git diff --cached 文本做 mustNot 关键词匹配 because 被删除行与恢复说明注释都会命中而反复误拦、拖慢分批提交；instead 只在新增行子集上做含/不含判定，并在设计 mustNot 清单时先确认该关键词不会作为文档文字出现在本笔预期新增内容里。适用于所有基于 diff 文本的主题归属校验（hunk 拆分、暂存区核对、PR 变更分类）；不适用于需要同时检测删除内容的场景（如确认某符号已被彻底移除），那种情况反而要扫 - 行。
