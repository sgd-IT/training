Bug class: 配置类 SQL 脚本用"逐条手工内联变量执行"的方式验证通过，但脚本本身仍带写法错误，交付后由他人执行时才失败。

Root cause: 通过受限 SQL 解析通道（如 MCP mysql_query）只能单条执行、不支持多语句与会话变量，于是把变量值内联进每条语句再跑——这恰好绕开了脚本里真正有问题的写法：① MySQL 中加号对字符串是数值相加而非拼接，会把拼变量的 JSON 字面量拆坏并报 "Truncated incorrect DOUBLE value"；② mysql 客户端按分号切句，多行字符串字面量与内嵌 JS 里的分号导致切点错乱（报 ASCII null byte / Unknown command）。这两种错误只在原样执行整份脚本文件时才暴露。

Fix pattern: 脚本类产物必须用其目标执行通道原样跑一遍（本地 mysql.exe 以 source 方式加载 .sql 文件），并二次重跑验证幂等（计数各表行数不增），而不是仅逐条替换成常量喂给交互式查询工具。

Reusable lesson: Don't 因为"每条语句单独都能执行成功"就认定脚本可用，因为内联变量会掩盖拼接与切句两类写法缺陷，交付后必然在生产执行时炸；instead 一定用脚本的目标运行器整体 source 一次并复跑验幂等。适用于所有需交给运维以命令行执行的配置/迁移 SQL 脚本；不适用于只读探查类单条 SELECT（那本就该走交互式查询通道）。
