Bug class: 跨环境业务数据同步后在应用侧完全不可见（静默孤儿数据）
Root cause: 项目按多租户机制在查询链路自动拼接 tenant_id 条件，若源库记录的 tenant_id（如生产库 video_camera 上挂在 174/176/178 的记录）在目标库 system_tenant 中没有对应行，INSERT 本身能成功（tenant_id 只是普通列，无外键约束），但任何带租户过滤的接口视图都筛不出这些行，形成"数据存在却查不到"的静默故障，排查者容易误判为同步失败或前端问题。
Fix pattern: 同步前先分别查两侧租户主表（SELECT id,name,status,deleted FROM system_tenant）做集合差，缺失租户三选一处置——一并复制租户主表记录（注意其下无用户与套餐，只能由超管跨租户查看，无法直接登录）、改写归属到目标库已有租户、或明确接受数据仅用于底层验证；同时用业务键（tenant_id+device_id+channel_id 之类）而非主键判定"是否已存在"，插入时不指定自增 id 以规避主键冲突。
Reusable lesson: Don't 只按数据条数差异决定同步范围就执行 INSERT because 目标库缺失租户主表记录会让写入静默不可见；instead 在写入前完成"主键冲突 + 归属字段有效性（租户/部门）+ 软删除是否需要携带"三项前置核查。适用于本项目所有带 tenant_id/dept_id 的业务表跨环境搬运与演示数据构造；不适用于无租户过滤的框架配置表搬运和同库内的 UPDATE 修正。
