Bug class: 前端公共 CRUD 组件工具栏扩展位缺失 + 事件无人监听导致的静默失效。

Root cause: 在自研列表组件 yt-crud / yt-table-fun 中，工具栏左组的渲染顺序固定为「新增按钮 → addRight 插槽 → 导出按钮 → 批量删除按钮」，addRight 位于导出按钮**左侧**；因此"把控件放到导出按钮右边"没有现成扩展位，必须先在组件里新增一个命名插槽（如 exportRight）并由上层组件透传，否则页面侧无论怎么写都放不到该位置。同时导出按钮点击只 emit('exportFun')，若页面未绑定 @export-fun 处理函数，按钮点击无任何反应且不报错——接口已定义、后端已支持过滤，但功能整体不可用，属于容易被误判为"后端没做好"的静默缺陷。

Fix pattern: ① 公共组件按已有 addRight 的写法做纯增量插槽（新插槽不传即不渲染，对旧页面零影响），并在中间层组件补一段透传；② 页面显式绑定导出事件处理函数，内部调用已定义的导出 API 并用现有下载工具落盘；③ 筛选值直接挂在搜索表单与页面共用的同一个 query 对象引用上（表单以 props.query 建 formModel），可避免搜索提交/重置覆盖外部筛选条件。

Reusable lesson: Don't 假设"工具栏某个按钮旁边"一定能塞进控件、也不要假设"导出按钮存在 = 导出功能可用"，因为插槽位置有严格左右顺序、emit 出的事件没人监听就完全静默；必须在动手前读一遍组件模板确认插槽的确切位置和页面是否绑定了对应事件。适用于修改 yt-crud/yt-table-fun 这类自研公共列表组件的工具栏区域，以及排查任何"按钮点了没反应"的功能；不适用于 Element Plus 原生组件或页面自行渲染工具栏的场景。
