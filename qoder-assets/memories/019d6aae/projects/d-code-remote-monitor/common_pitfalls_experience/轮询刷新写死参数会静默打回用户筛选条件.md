Bug class：前端定时轮询静默覆盖用户交互态筛选条件（数据看起来"自己跳回默认值"）
Root cause：监控中心 dashboard/index.vue 的 fetchDashboardData() 被 30 秒 setInterval 复用，其中 getAlarmTrend(7) 把天数写成字面量常量，而用户在 radio 上切换近 15/30 天时只更新 trendDays.value 并单独发一次请求；轮询下一拍仍按 7 天拉数据并直接赋值给 alarmTrendData，于是用户的选择不报错地被打回默认区间。同类隐患在"初始化函数 + 周期刷新函数"双入口结构里普遍存在：刷新路径不复用交互态 ref，而沿用初始硬编码参数。
Fix pattern：把刷新路径里的字面量参数改为读取当前交互态 ref（getAlarmTrend(trendDays.value)），使 radio 的 @change 处理与轮询共用同一状态源；若确有"轮询固定窗口"需求，则须在 UI 上禁用可切换项或让切换后重排定时器，而不是两套参数并存。
Reusable lesson：Don't 在周期刷新的取数调用里保留初始化时的字面量参数，因为用户交互选择会在下一个 tick 被无声覆盖，且日志与接口都正常、极难归因；instead 让所有取数入口统一读同一个响应式状态 ref。Applies when 改造带 setInterval/轮询的页面且该页面同时存在用户可控的筛选参数（时间范围、租户、分页大小等）；does not apply to 一次性加载无周期刷新的页面，以及后端本身只支持单一固定窗口的接口。
