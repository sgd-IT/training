Bug class: 同一轮并行发起"写文件"与"读取该文件的命令"导致后者读到旧内容（工具调用竞态）

Root cause: 在同一轮里并行发出 Write(提交信息文件) 与 Bash(git commit -F 该文件) 时，两条调度的先后顺序不受控制，commit 读到的是上一轮遗留的旧文本；实测表现为提交内容正确但提交信息串成了下一个提交的信息（需 git reset / commit --amend -F 回修）。同类问题：SearchReplace 设 replace_all 期望一次替换模板+注释共 5 处，实际只命中模板 1 处，若不 grep 复查会留下半改状态。

Fix pattern: 凡"产出一个文件 → 下一条命令消费它"存在依赖，必须拆到相邻两轮串行执行（本轮 Write，下一轮 Bash），绝不同批并行；每笔 -F 提交前用 status/diff --cached 确认暂存内容与预期文件一致，发现错位用 git commit --amend -F 修正（amend 只用暂存区不会卷入未暂存文件）；批量文案替换完成后一律用带否定前瞻的 grep（如 `旧词|新短词(?!后缀)`）复查残留计数为 0 才算完成。

Reusable lesson: Don't 把写入文件和运行依赖该文件的命令放在同一轮并行发出，因为读取顺序不可控会让命令用错版本内容；instead 严格交替（写一轮、消费下一轮）。适用于所有以临时文件为中介的命令链（commit -F、脚本参数文件、配置覆盖后启动）；不适用于命令不读取该文件的纯并行独立操作。同样地，不要相信 replace_all 一定全量命中，必须以 grep 复查裁决。
