## Notes（2026-10 复核，结论以本段为准）
- 本任务当年并未真正落地：当前测试库 system_users 共 22 列，不存在 login_type 列，唯一可用的端标识是 user_type（tinyint）。任何按 login_type 编写的查询/迁移都会因列缺失失败。
- 项目内区分登录端的现行口径：复用 user_type 作为账号固定平台位掩码（1=PC 端、2=移动端、3=双端），不再新增渠道标记列；渠道追溯交给登录日志（logType），无需在用户表留痕。
- 多端来源标识类需求的正确做法：先盘点该列是否被登录流程每次翻写（若是则不能当门禁用，必须先固化语义再收口），再决定复用现成列还是加列；不要照搬本条早期"加列 + 自动赋值"的思路。
