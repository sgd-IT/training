## Goal
把散落在多个前端页面/组件的同类样式问题（UI 审查清单、主题变量调整）安全落地，确认改动既编译通过又不引入格式与类型新增问题，且能把"本次改动引入的问题"与"仓库历史存量问题"区分开，交付为可回滚的原子提交。适用于任何有 prettier + vue-tsc/tsc + dev server 的前端仓库做大面积视觉或结构调整后的收尾验证。

## Steps
Step 1: 全局搜索 - 检索目标变量/mixin/类名在全仓的定义与使用位置，rationale: 未定位全部引用点就改变量定义会造成部分组件仍用旧值而样式割裂；输入: 变量名或 mixin 签名, output: 受影响文件清单（含 import 链上的定义文件）
Step 2: Read - 逐条复核待改点在当前代码里是否仍存在及其确切取值与用法上下文，rationale: 审查清单可能基于已漂移的代码状态，直接照抄会改到不存在的类名或覆盖错误的既有实现；输入: 清单条目 + 文件路径, output: 带行号的待改点集合 + 已合规项列表
Step 3: Phase check - 确认每条都有"当前值 → 目标值"落点；依赖产品口径（功能该不该存在）或影响面全站（全局字体、主题变量）的条目从本批剔除单独确认；mixins 参数形态不同的须记录变体以保证一致更新
Step 4: 按文件聚合并风险分档 - 重组为"零风险纯 CSS/文案"与"中风险结构或配色重分配"两批，rationale: 混批会让一处越界改动污染整批回滚粒度无法单点撤销；零风险批可一次做完，中风险批必须单做单验；input: 待改点集合, output: 两批改次清单
Step 5: 编辑工具 - 先改变量定义源文件，再分两轮落地（先模板/脚本、再样式区），同文件内全部同类改动一轮做完，rationale: 先改定义使后续引用统一指向新值；模板与样式的替换来源与失败面不同，分批能定位是哪一类改动出错；同文件多点位分散在多轮编辑会增加行号漂移与漏改概率；input: 单文件改动清单, output: 文件更新
Step 6: dev server 请求该模块 - 取 HTTP 状态码判断能否编译，rationale: 请求源码模块会触发即时编译，比等页面人工查看更快暴露语法错误；输入为模块 URL，输出为状态码与产物长度
Step 7: Bash - 把目标文件复制进临时隔离目录后用格式化检查工具写副本，再与原文件做无索引 diff 并只提取差异块头，rationale: 直接在原文件上跑格式化会把仓库历史遗留的格式问题一起改掉，污染本次 diff；副本方式能量化出"还剩几处不合规"及其行号分布；输入为文件路径，输出为差异块行号列表
Step 8: Phase check - 确认差异块全部落在未改动的区域；若出现在本次改动区域，说明本次写法不合格式规范，须按格式化器输出的期望形式修正后回到 Step 7 复跑；若差异块全在存量区域则视为既有基线可放行
Step 9: 类型检查命令 - 全量跑一次并按本次改动文件路径过滤输出，rationale: 样式改动同样能引入编译期错误（SCSS 变量未定义、模板绑定失效），退出码非零与错误总数都不可作判据，只有改动文件的错误才是信号；输入为过滤模式，输出为改动文件的错误清单
Step 10: Git - 按最小逻辑单元分批提交，每批提交前列文件清单与提交信息给用户确认，rationale: 批量样式改动天然跨多文件，不按批次切分就无法定位哪一处引起观感回退，且提交授权不可跳过；input: 已完成批次, output: N 个原子提交
Step 11: Bash - 删除临时隔离目录与中间日志文件，rationale: 残留副本会被后续提交误纳入版本控制

## Notes
- 把"审查建议"当成"已确认需求"全量落地会导致产品口径类改动被顺手改掉，必须先剔除需确认项再动手
- 只改变量定义不清点上层的 mixin 参数变体 causes 部分组件仍走旧参数呈现不一致，必须同轮收口全部使用点
- 引用未清零就删除定义会让编译直接失败，而编译器报错无法指出是哪个删除动作造成的，必须先清点本文件内引用
- 在原文件上直接运行格式化器会把仓库历史遗留格式问题一并改写使本次 diff 失真，须用隔离副本比对
- 给组件标签追加属性使其超出打印宽度，会造成格式化检查报出大量新差异块，必须同轮把该标签重排为多行属性形式而不是忽略
- 只看类型检查工具的退出码或非零错误总数，会因存量报错而误判本次改动失败，必须按改动文件过滤并与改前基线对比
- IDE 语言服务诊断（GetProblems）返回"not ready or still initializing"时不要重复重试同一调用，必须转不依赖语言服务的兜底链：git status/diff --stat 划定被改文件 → git diff -U0 逐块取本次真实改动行 → 读源码定位具体行核对结构
- 校验发现清单外的同类问题追加为零风险批补充项，不得临时扩大中风险批范围
- 未实际运行得到的诊断结论不能写成已验证，只能表述为逻辑推定并要求用户在 IDE 面板与浏览器运行时确认
