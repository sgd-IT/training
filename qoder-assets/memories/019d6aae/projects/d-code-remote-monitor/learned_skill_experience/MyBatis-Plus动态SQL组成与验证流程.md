## Goal
Diagnose and verify the actual SQL generated by MyBatis-Plus dynamic query builders (e.g., LambdaQueryWrapper) when no XML mapper exists.

## Steps
Step 1: Static analysis - Trace the service method (e.g., doPageFromAlertRecord) to confirm it uses LambdaQueryWrapperX, not XML mapper.
Step 2: Dynamic verification - Enable SQL logging via application.yaml (logging.level.com.enjoyiot.module.eiot.dal.mysql: debug) or MyBatis-Plus log-impl (StdOutImpl).
Step 3: Runtime capture - Use p6spy or MySQL general_log to capture raw SQL executed against the database.
Step 4: Index validation - Replace ? placeholders in logged SQL with real values and run EXPLAIN to verify index usage and avoid Using filesort.

## Notes
- Relying on application.yaml logging is the safest, zero-intrusion method; StdOutImpl prints all SQL to console but may be too verbose in production.
- EXPLAIN is essential to confirm whether composite indexes (e.g., idx_tenant_alert_time) are actually used for filtering and sorting.
