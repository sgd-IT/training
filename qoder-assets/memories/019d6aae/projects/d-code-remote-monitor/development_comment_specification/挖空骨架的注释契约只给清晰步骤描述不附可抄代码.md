在留给学员手敲的挖空骨架处，注释契约只给步骤描述、不附任何可抄代码或骨架代码块（用户原话："契约不用带可抄代码，只给步骤描述，但是要清晰明了"）。但步骤描述必须写到能直接落笔的粒度：禁止只写结论式摘要（如"分两步解：先解信封再取 data"），要把中间那步的具体动作交代清楚——用哪个 API、传什么参数、结果存到哪个变量、拿它干什么；可写清方法的归属与调用形式，但不给成品语句。其余配套约定：一次只挖一层、同一概念不在多处重复交代、坑位单独成行标"坑："、学员要求"别挖了直接写"时立即停挖并还原其已填内容。

【更正 2026-10-28】原文末尾"文字教程模式（学员逐块跟敲、非挖空）仍可给可抄改小块，两种模式口径不可混用"须再加一层限定：**可抄改小块仅限前端**。后端在任何模式（含跟敲教程模式）下都只给方法签名 + 步骤描述 + 坑位，不给完整方法体，也不给可直接粘贴的控制流代码块。学员画像本身就是"前端零基础需照抄、后端能看懂需参考"，按前端口径对待后端等于代写，学员已明确反感（原话："为什么会直接给代码你按skills来了吗"）。该口径已写入 SKILL.md 红线2与 5.4 第②项。
