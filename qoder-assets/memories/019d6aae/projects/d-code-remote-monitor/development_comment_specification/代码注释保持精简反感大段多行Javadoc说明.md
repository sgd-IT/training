用户偏好精简注释，反感大段多行 Javadoc 说明（原话"过于多行，看也不想看"），并以 FireSpaceServiceImpl.createFireSpace 为"个人风格"样本：类头一句功能 + 至多一行关键结论（保留租户隔离、唯一键、软删占唯一键等结论，删括号推演与实现细节）；方法级 Javadoc 一两句话即可，实现类不展开推演；行内注释用约 15 字以内的口语化步骤短句（获取/对值进行/组装/查询/插入），同一动作全链路用同一措辞。

2026-10-30 因 agent 把单行 Javadoc 扩写成带 `<p>` 分段的多行块，用户问责"不符合我的风格"，补充硬约束：① 常量/字段 Javadoc 一律单行 `/** 一句话 */`；② 已有的单行 Javadoc 不得扩写成多行，改写只在原行内动字；③ 方法 Javadoc 最多「做什么 + 一条关键结论」加必要 @param，不写 `<p>` 推演；④ 只有当用户字面要求"详细说明/写清背景"时才展开多行，不能以"逻辑复杂"为由自行加长。该节已写入 code-comment-style 的 SKILL.md「用户风格硬约束（优先级高于上面六条）」。
