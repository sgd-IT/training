## Usage Scenario
Description: 需要确认某个标识符/字符串是否存在于前端打包产物、minified JS、超大 JSON 等"单行极长"的文件中时。
Examples: 判断第三方交付包是否真的消费了某个 URL 参数；核对压缩 chunk 里是否含有某段逻辑。

## Usage Method
Grep/ripgrep 类检索工具：对这类文件可能**整份跳过并返回 0 匹配**（既可能是文件体积超上限，也可能是单行超长被判定为二进制），因此"0 匹配"不能当作"字符串不存在"的证据。要改用 Read 按行区间分段通读，并用 LSP documentSymbol 拿符号表来定位函数所在行，再针对性读取；先用一个已知必然存在的字符串做正向对照，确认工具在该文件上是否真的生效。
Read 工具：长度上限按字节计，含中文内容的行更易超限；一次请求的连续多行若总量超限会整次失败，应拆成更小区间或逐行读取。

## Notes
- 仅凭检索工具返回 0 匹配就断定压缩产物里没有某段实现，会导致得出相反的错误结论（本轮即先误判后再被逐行读取推翻），必须用另一种读取方式交叉验证后才下结论
- 一次性读取"看起来不大"的字符数量仍可能失败，因为限制是字节数而非字符数，必须按更小行区间拆分重试
