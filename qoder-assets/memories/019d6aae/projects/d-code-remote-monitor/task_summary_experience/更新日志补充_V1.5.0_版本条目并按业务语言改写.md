## Task description
- Core requirement：用户先只发「data.ts」再补「更新日志」，需定位意图并把本次已推送的功能改动追加成 PC 管理台更新日志的新版本条目。
- Task background：src/views/system/changelog/data.ts 是更新日志唯一数据源，CHANGELOG 数组按版本倒序、CURRENT_VERSION = CHANGELOG[0]，页面与 App.vue 登录弹窗同步读取；最新一条为 V1.4.0（2026-10-23），本次已推送后端 7 笔 + 前端 8 笔共 15 笔功能改动尚无对应日志。

## Execution process
1. 意图定位：duty-screen 目录下不存在 data.ts（只有 components/ 与 index.vue），全仓检索出 5 个同名 data.ts，其中 views/system/changelog/data.ts 为「数据源唯一入口」范式；因指令过短不猜测落盘，列出四选一候选（抽常量 / 放 demo 数据 / 指已有 scene-data.ts / 参照 changelog 建文件）后由用户回复「更新日志」锁定目标。
2. 取证 index.vue 结构判断无抽离价值：2686 行中 script 段 980 行，静态量仅 navRoutes + ALARM_PAGE_STEP(10) + ALARM_MAX_LIMIT(50) + ALARM_ORDER_WINDOW，loadMockData 只剩 6 行置零兜底，无大块数据可搬。
3. 条目撰写：在 CHANGELOG 数组最前插入 V1.5.0 / 2026-10-28 / 「大华 UDP 终端接入与大屏稳定性提升」，共 8 条——feature 3 条（UDP 消防终端接入并实时推送到大屏、值守大屏与监控中心接入设备实时事件、处置中心现场视频统一到右侧面板）、improve 3 条（联动预案改为确认火警后才可启动、大屏统计加租户级缓存与并发保护、页面切后台自动暂停刷新）、fix 2 条（确认火警后按钮不再重复显示、断连不再误记为服务端错误）。
4. 措辞收敛口径：全部改写成用户可读的业务说法，剔除 Semaphore、druid、boot3、hunk、帧解析器等技术术语；4 笔提交判定为不可见噪音未写入日志（UDP 组件退出释放端口、月报注释、ARCHITECTURE 文档、不入菜单的液位电压演示页）。
5. 建立「提交 → 日志条目」映射表逐条溯源：UDP 终端接入 ← 929908c/bca7979/cb6bb49；实时事件上屏 ← 009a694；视频入口收敛与联动预案门禁与按钮复现 ← 5310fd2；统计缓存 ← 606035a；可见性轮询 ← 51a5f7b/ef698b7/009a694/e8dbd2b/78850db；断连降噪 ← a0b52e2。
6. 校验：GetProblems 报 language server not ready 属假象，改用 node 直调 node_modules/eslint/bin/eslint.js 得 exit=0；node 脚本核对版本序列 V1.5.0→V1.4.0→…→V0.9.0 且新条目居首、CURRENT_VERSION 取 CHANGELOG[0] 自动变为 V1.5.0、文件 113→128 行。
7. 停在待确认：按 IMMUTABLE 规范以正文列出拟用提交信息 docs(changelog): 新增 V1.5.0 更新日志 + 单文件清单，等用户文字回复后再 commit（不 push），版本号是否改走 V1.4.1 一并交用户定。

## Notes
- 只发文件名（如「data.ts」）这类超短指令时，必须先列目录实况 + 全仓同名文件清单再给有限候选澄清，不能凭当前打开文件猜着落盘；用户后续补一词即可锁定目标。
- 更新日志条目必须与 git 提交建立逐条映射，否则无法判断哪些提交属于用户可见变更、哪些应作为技术噪音剔除；本次 15 笔中有 4 笔不入日志。
- 该文件的 items.type 实际取值是 feature/improve/fix（历史记忆写作 feat/opt/fix），追加前应以文件现状为准。
