## Notes
- 【逐格跳转已落地（2026-10-23）】「今日警情」卡已从整卡统一跳 unclosed 演进为四个 stat-cell 各自带状态：告警总数与处置率 → 仅 today=1（今日全部）；已处置 → today=1&orderStatus=finished；待处理 → today=1&orderStatus=unclosed；整卡空白处仍默认跳 unclosed。实现要点：每个 .stat-cell 加 @click.stop（阻止冒泡到整卡 click）+ cursor:pointer，新增 goAlarmOrders(orderStatus?) 统一构造 query。
- 【关键口径】「已处置」格子必须传分组值 finished 而不是 handled 单值——大屏 handledCount 来自 AlertOrderStatusResolver.sumHandled = handled + closed 两部分之和，只传 handled 会漏掉「已关闭」那批，重现"卡片 N 条、点进去 N-1 条"。后端 FireAlarmOrderServiceImpl.applyOrderStatusFilter 已增 case "finished" → CASE IN ('handled','closed')；前端 ORDER_STATUS_FILTERS 白名单与处置中心下拉同步加「已闭环」。该分支同样被导出/PDF 复用。
- 【部署提醒】新增的 orderStatus 分组分支需重启后端才生效，否则落到 default 分支打 warn 且不筛选，列表退化为今日全部。
