## Execution process
1. 埋点结论：盘点确认 framework/spring-boot-starter-web 的 ApiAccessLogFilter 全局写 infra_api_access_log（dev/prod 均 access-log.enable: true），入口若调接口则按 request_url 分组即可统计，无需开发；AccessLogCleanJob 只保留短期天数，长期趋势才需汇总表；前端无任何埋点 SDK，私有化部署不引第三方统计。
2. 造数落点：MCP mysql_query 查得 test 库 system_tenant id=1 为"安为科技值守中心"（超管 admin 所在租户、dept_id=103 研发部门），角色 161 远程值守员、165 消控室值班员可用。
3. 密码生成：用本地 .m2 的 spring-security-crypto jar + commons-logging 直接以 `java -cp <jars> GenBcrypt.java` 单文件运行，生成明文 123456 的 BCrypt hash 并 matches 校验通过，避免为一次性工具建工程。
4. 落库：INSERT system_users 三行（zhangwei 张伟 / lina 李娜 / wangqiang 王强，tenant_id=1、dept_id=103、status=0、user_type=3、push_enabled=0），Last insert ID 156；再 INSERT system_user_role 三行绑定 role_id=161 且带 tenant_id=1；联表 SELECT 验证全部生效。
5. 下拉排查：核对 FirePropertyRespVO 确有 tenantId 且 convertToRespVO 已 setTenantId，排除映射缺失；再按租户聚合 system_users（status=0）得到各"所属单位"可选名单——tenant 1 有 8 人含新建三人，165 仅张三，167 为 0 人，168 仅碧桂园，判定用户选了企业单位而非值守中心单位，属设计使然而非数据缺陷。
6. 环境一致性核验：MySQL @@hostname 与本机 hostname 不同，再读 Qoder extension/local/mcp.json 确认 anwei_fire_remote_monitor_test 实际连 192.168.250.160，与后端 application-dev.yaml 的 jdbc 地址一致，排除"插错库"假设。
7. 去班次名称：duty/index.vue 删除表格"班次名称"列、新增/编辑弹窗的 shiftName 输入项、导出 CSV 表头与数据行中的该列；数据库 shift_name 字段、后端 DO/VO、提交时由班次类型联动赋值的逻辑全部保留，历史数据与大屏/监控中心展示不受影响。
