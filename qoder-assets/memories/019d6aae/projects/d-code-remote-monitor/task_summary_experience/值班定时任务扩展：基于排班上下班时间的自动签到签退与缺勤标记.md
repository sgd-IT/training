## Task description
- Core requirement: design and implement new scheduled tasks in FirewatchScheduledTask.java to handle duty schedule status changes (check-in/check-out/absent marking) based on shift start/end times
- Task background: existing FirewatchScheduledTask.java has reserved space for '值班状态变更' at lines 145-149 but no implementation; FireDutyScheduleServiceImpl.java provides checkIn()/checkOut() methods and stores shift times as start_time/end_time strings with status values like 'scheduled', 'on_duty', 'completed', 'absent'

## Execution process
1. Identified three core status transition scenarios: automatic check-in at start_time, automatic check-out at end_time, and absent marking after start_time + buffer
2. Designed cron expressions: '0 */5 * * * ?' for frequent scanning of start/end time conditions, '0 0 */1 * * ?' for hourly absent checks
3. Specified SQL update logic for each scenario: status transitions with tenant-aware filtering via @TenantIgnore
4. Proposed mapper method additions: autoCheckIn(), autoCheckOut(), autoMarkAbsent()
5. Confirmed multi-tenant isolation requirements: all methods require @TenantIgnore annotation and proper tenant_id handling

## Notes
- Night shift cross-day logic requires special handling when end_time < start_time
- All scheduled task methods must be idempotent to handle potential duplicate triggers
- Buffer time for absent marking should be configurable (e.g., 30 minutes)

## 补充说明（后续会话）
- 后续 24 小时值班制改造已把默认班次口径定为 wholeday 全天班 08:00 → 次日 08:00，并新增"自动排班与导入只排明天及以后"的时间窗口规则。上述基于 start_time/end_time 的签到签退与缺勤判定仍适用，但跨天判定的统一口径是"结束时间 ≤ 开始时间即跨天"（wholeday 的 08:00==08:00 也按此判定为跨天到次日），改造定时任务时应沿用该同一把尺子，勿另写判断条件。
- 因新排班不再产生今天及以前的记录，缺勤扫描针对存量/手动补录数据仍需保留，不能因"只排未来"而移除过期未签到的缺勤标记逻辑。
