## Task description
- Core requirement: identify which database table stores the '所属单位' (property/unit) data and explain why so many units appear in the dropdown
- Task background: frontend loads propertyList via getPropertyList() API; backend controller calls service to query firePropertyMapper; investigation revealed tenant filtering logic determines visibility

## Execution process
1. Frontend: index.vue uses v-model="queryParams.propertyId" and binds propertyList loaded by getPropertyList() API
2. API: GET /eiot/firewatch/property/list mapped to FirePropertyController.listProperties()
3. Service: FirePropertyServiceImpl.listProperties() checks TenantContextHolder.getTenantId(); if tenantId == 1L (super admin), uses @TenantIgnore to bypass tenant filter and return all fire_property records
4. Data source: FirePropertyDO maps to fire_property table; SQL queries use firePropertyMapper.selectList()
5. Verification: confirmed that super admin (tenantId=1) sees all units because tenant filter is ignored

## Notes
- The core insight is tenant filtering behavior: super admin (tenantId=1) ignores tenant isolation and fetches all units from fire_property table; ordinary tenants only see their own units
- This explains why 'so many units' appear — the user is logged in as super admin
