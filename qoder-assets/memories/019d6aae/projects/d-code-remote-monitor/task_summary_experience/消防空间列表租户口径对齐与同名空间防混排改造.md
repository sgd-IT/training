## Task description
- Core requirement: 修正消防远程监控项目中"admin（系统租户）应能查看全部数据"的口径，并解决多租户下同名空间（如多个租户都有"1号楼3层东区"）在下拉框里混排分不清的问题；最后按要求让每条空间记录在楼栋字段前带上租户名称。
- Task background: 空间管理 GET /eiot/firewatch/space/list 早期实现把查询条件锁死为"上下文租户"，导致 admin 也被限制在租户 1；设备详情页（deviceinfo/detail.vue）的设备地址下拉因此出现无数据或跨租户混排。框架 TenantDatabaseInterceptor 对系统租户用户本就跳过内置 tenant_id 过滤，故需对齐三处消费点（编辑设备、新增设备、全量列表）并保留保存校验兜底。

## Execution process
1. 逐行读 framework/spring-boot-starter-biz-tenant/.../TenantDatabaseInterceptor.java，确认 ignoreTable 第三层判定：登录用户带 INFO_KEY_IS_SYSTEM_TENANT 且上下文租户==登录租户时不加 tenant_id 条件（即查全部），据此认定原 /list 实现属收窄而非框架限制。
2. FireSpaceController / FireSpaceService / FireSpaceServiceImpl：/list 增加可选 tenantId 参数——系统租户不传查全部、传则按指定租户过滤；企业租户强制本租户（param 无效），Service 层仍显式 eq(tenant_id) 作双保险。
3. DeviceInfoServiceImpl.initSpaceAddr：保存校验的租户来源由"上下文租户"改为"设备所属租户（产品租户）"，跨租户 spaceId 直接抛 SPACE_NOT_EXISTS，成为最后一道防线。
4. 核实 ProductRespVO 未透出 tenantId（而 api 层 Product 继承 TenantModel 本就有该字段、ProductDO 继承 TenantBaseDO），给 ProductRespVO 补 tenantId 字段，BeanUtils.toBean 同名拷贝自动生效；前端 src/api/eiot/product/index.ts 的 ProductVO 同步补字段。
5. detail.vue：编辑态用 data.tenantId 加载下拉；新增态改为选定产品后在 getProductData 内 loadSpaceOptions(product.tenantId) 重载，消除"未选产品就倒全量"的撞名缺口；查看态不再请求空间列表。
6. 新建 controller/admin/firewatch/vo/space/FireSpaceRespVO.java，字段顺序 id → tenantId → tenantName → building → floor → area → remark（租户名位于楼栋之前）；FireSpaceController 的 /list 改返 VO，并用 TenantUtils.executeIgnore + TenantService.getTenant 去重批量填充 tenantName，照抄 DeviceInfoController"所属企业"填充写法避免 N+1。
7. 前端拆 formatSpaceLabel（下拉展示 = 租户名 + 空格 + 地址部分）与 formatSpaceAddr（地址部分）；写入 addr 的快照仍不含租户名，因 addr 会进告警文案与巡检场景。
8. 每轮改动后验证：module-eiot-biz clean + -am compile 出现 Compiling 550→551 source files 且 BUILD SUCCESS（JAVA_HOME 切 JDK 21）；前端 node node_modules/eslint/bin/eslint.js 目标文件 EXIT=0。IDE 报的 4 处模板类型错误均在未改动的旧行（disabled="true" 字符串、scope.row.content 类型、el-tag type），判定为既有 vue-tsc 严格性遗留，不动。

## Notes
- 设计时以"下拉数据源保持一致"为由把 /list 锁在上下文租户，结果与框架既有的 admin 查全部口径冲突，被用户质疑后才回退——同类改造应先读拦截器源码确认框架默认行为，再决定业务层是否要收窄，不要凭一致性直觉自行加限制。
- "新增设备"场景的下拉租户无法从设备本身取得（设备还没有归属），必须借道 product.tenantId 推导；若只改编辑态会留下明显缺口。
- 跨租户同名的唯一键是 (tenant_id, building, floor, area)，属合法数据，不能靠禁止同名解决，只能保证每个消费点同一时刻只呈现单租户视图。
