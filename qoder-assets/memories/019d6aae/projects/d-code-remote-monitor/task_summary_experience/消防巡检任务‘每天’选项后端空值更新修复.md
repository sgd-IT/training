## Task description
- Core requirement: fix the '每天' (every day) patrol task option so that selecting it correctly updates the database plan_date column to NULL and displays '每天' in the frontend
- Task background: frontend radio toggle worked but backend updateById skipped null planDate due to MyBatis-Plus FieldStrategy.NOT_NULL default; this caused frontend to reload old date instead of '每天'

## Execution process
1. Added @TableField(updateStrategy = FieldStrategy.ALWAYS) annotation to FirePatrolTaskDO.planDate field to force updateById to include NULL values in UPDATE SQL
2. Reverted FirePatrolTaskServiceImpl.updateTask() back to using firePatrolTaskMapper.updateById(updateObj) instead of LambdaUpdateWrapper
3. Verified that updateById now generates SET plan_date = NULL when planDate is null
4. Confirmed frontend correctly displays '每天' after editing and reloading

## Notes
- Database column fire_patrol_task.plan_date must be ALTER TABLE ... MODIFY COLUMN ... DEFAULT NULL to support NULL values
- The @TableField(updateStrategy = FieldStrategy.ALWAYS) annotation ensures all updateById calls for this entity will include plan_date in the UPDATE statement, even when null

## Task overview
Successfully fixed the '每天' patrol task backend update issue: added FieldStrategy.ALWAYS annotation to planDate field and reverted to simple updateById, ensuring NULL values are correctly written to the database and frontend displays '每天' correctly.
