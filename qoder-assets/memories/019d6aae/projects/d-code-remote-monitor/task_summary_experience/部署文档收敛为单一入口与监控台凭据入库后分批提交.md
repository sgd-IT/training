## Task description
- Core requirement：用户依次提出「服务器部署是命令行方式的」「同事拉代码后怎么部署看不懂」「不用那么多文档，一个简单明了的步骤就好」「私有库直接提交也行」「提交」，最终要把部署说明做成单一无歧义入口、凭据全部入私有库，并把两仓改动按主题原子化提交。
- Task background：anwei-fire-remote-monitor/deploy 下原有 部署操作手册.md(298行)、操作文档.txt、初始化操作流程.txt 三份文档，无一处说明先看哪份，且初始化流程路径仍是旧的 D:\deploy\config\monitor-api 与服务名 monkey-monitor-api；前一轮已生成 node 版 htpasswd 命令与 .gitignore 忽略 + docker-compose DRUID_* 透传的环境变量方案。

## Execution process
1. 澄清机器角色而非补命令：明确 sba.htpasswd 只在构建机（Windows）生成并被 build-push.ps1 打进前端镜像，服务器只跑 ./pull-images.sh + docker compose up -d，不需要该文件；实测本机 where.exe openssl 找不到、node 在 D:\nodejs\node.exe，故文档坚持走 node 命令而非 openssl dgst。
2. 验证 node 命令跨 shell 可用：外层双引号包单引号、内嵌 \n 由 JS 解析，cmd / PowerShell / bash 三种 shell 原样传给 node，构建机换成 Linux 也无需改命令。
3. 先建 deploy/README.md（113 行，含"先判断你要做什么"分流 + 其它四份文档索引表），再按用户要求把 监控台部署说明.md 内容折进 README 并删除该文件（从未提交过，删除不留 git 痕迹），最终 README 约 90 行。
4. 凭据方案整体回退三处：application-prod.yaml 的 Druid 登录由 ${DRUID_USERNAME}/${DRUID_PASSWORD} 改回明文 admin/Awkj@20260821；docker-compose.yml 删除 DRUID_* 透传（git diff 长度归 0）；deploy/.gitignore 删除 htpasswd 忽略规则（diff 归 0），sba.htpasswd 重新出现在未跟踪列表并随 B2 入库。
5. 后端 mvn -f pom.xml compile -DskipTests 得 mvn_exit=0；用 Node 脚本导出 alarm-order/index.vue 完整 diff 并列出 18 个 hunk 头，按关键词分组为 F1=5、F2=5、F3=7、F4=1。
6. 拆分器 _ao_split.cjs 重算 patch 头部 new-side 起始行号（首个保留 hunk new_start=old_start，后续 new_start=前一保留 hunk new_end+(当前 old_start-前一 old_end)），git apply --cached --check 干跑通过后 apply --cached，末笔剩余 hunk 直接整文件 git add。
7. 执行器逐笔校验暂存清单==预期、新增行关键词含/不含双向判定、commit -F 消息文件后经 git cat-file commit 原始 hex 比对 UTF-8 三字节序列。
8. 前端 8 笔与后端 3 笔完成后，用 git archive HEAD 导出快照独立跑 mvn compile 得 exit=0，证明提交后仓库自洽；node 直调 node_modules/eslint/bin/eslint.js 校验 8 个改动 vue/ts 文件 exit=0。

## Notes
- 校验规则两次误拦（非代码问题）：mustNot 关键词扫了整段 git diff --cached，被删除行（-const pendingToast = ref(false)）与新写入的恢复说明注释（<IFrame :src="src" />）都命中而报泄漏；正确做法是只扫以 + 开头的新增行，且当某关键词本身合法出现在新注释里时应直接从 mustNot 移除。两次均在 commit 前中止，未产生错提交。
- 用户嫌文档多时的正解是"合并+删冗余"而不是继续精简单份：四份文档的问题不是长度而是缺唯一起点，故新增 README 作入口并在末尾用一张表说明其余文档各管什么、什么时候看。
- 私有库口径下凭据入库能直接把发版流程从三步砍到两步（不再需要生成 htpasswd、不再需要服务器 .env 补两行），代价是旧值永久留在 git 历史，轮换时须注意。
- 临时脚本与 patch 一律落 d:\code\remote-monitor\_temp\，收尾用单个 node 脚本按文件名列表批量 rmSync 清理。
