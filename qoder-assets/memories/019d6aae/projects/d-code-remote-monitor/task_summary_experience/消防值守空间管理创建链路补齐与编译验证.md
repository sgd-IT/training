## Task description
- Core requirement：从 FireSpaceController 的 createFireSpace 端点开始，把消防值守"空间管理"链路的下游各层补齐，并保持用户既有写法不变。
- Task background：后端仓 anwei-fire-remote-monitor 的 module-eiot-biz 中，firewatch 域已有 Controller 与 DO（用户自写），但 Service、ServiceImpl、DTO、Mapper 四个文件是 MyBatis-Plus 代码生成器残留（类名仍为 EiotSpace、引用不存在的 generator.* 包、BaseMapper<> 缺泛型、DTO 文件里装的是实体），整条链路编译不过；库表由 _sql/mysql/V20261012__create_eiot_space.sql 与 20261012_add_remark_to_eiot_space.sql 定义，含 tenant_id + building + floor + area 的唯一键。

## Execution process
1. 现状盘点：逐层读取六个 FireSpace 文件，确认 Controller/DO 保留、其余四层需重写；全仓 Grep EiotSpace|generator.(domain|service|mapper) 确认 generator 残留仅存在于这四个文件，无 XML 或其他 Java 引用。
2. 风格对齐：以兄弟链路 DutyPhone（Controller/Service/ServiceImpl/Mapper/CreateReqVO）与维保单位服务为模板，确定 DTO 校验、builder 落库、log.info 打点、异常抛出写法。
3. 错误码核对：module-eiot-api 的 ErrorCodeConstants 已预留 SPACE_EXISTS（2_006_007_200，"该租户下相同楼栋/楼层/区域的空间已存在"），直接复用未新建。
4. 租户机制核实（关键决策点）：读 TenantDatabaseInterceptor 确认其为 MyBatis-Plus 租户拦截器，系统租户管理员视角下会跳过内置过滤；读 DefaultDBFieldHandler 确认自动填充仅覆盖 createTime/updateTime/creator/updater，不含 tenant_id；读 server/application.yaml 的 ignore-tables 清单确认 eiot_space 不在忽略表中。据此定下三条写法：查重 wrapper 显式 .eq(getTenantId, 上下文租户)、插入前显式 setTenantId、area 为空时归一为空串（避免存 NULL 绕过 DB 唯一键）。
5. 四层重写：FireSpaceDTO 改为创建请求 DTO（building/floor @NotBlank，area 可不填，remark 透传）；FireSpaceService 改为普通接口只声明 Long createFireSpace(FireSpaceDTO)；FireSpaceServiceImpl 修正类名并按 checkWrapper 查重 → 命中抛 SPACE_EXISTS → builder 落库 → log.info；FireSpaceMapper 修正为 extends BaseMapperX<FireSpaceDO> 并加 @Mapper。
6. 编译验证：GetProblems 因语言服务未就绪不可用，改用 JDK 21 + 先 clean 再定向 compile，日志出现 Recompiling 且 BUILD SUCCESS（41 模块）。
7. 署名统一：按用户追加要求，FireSpace 全部六个文件的 Javadoc 署名统一为 @author sgd（五个 EnjoyIot→sgd，DTO 原无 javadoc 头补上），纯注释改动无需重编译。

## Notes
- 代码生成器一次性生成的骨架若落在业务包里但未纳入 git，后续易被误当作既有实现；判定方法是查类名/包名是否与项目规范不一致（如 generator.domain.EiotSpace、IService<EiotSpace>），并用全仓 Grep 确认无外部引用后再整体重写。
- 租户字段不能想当然依赖框架：本框架的 MetaObjectHandler 不填 tenant_id，而租户 SQL 拦截器对系统租户管理员会放行，因此"靠拦截器兜底"的查重在管理员视角下会误判跨租户重复，必须显式带 tenant 条件。
- 唯一键里的可空字符串列应在写入侧归一为空串，否则 NULL 不参与唯一比较，约束形同虚设。
- GetProblems 在语言服务初始化期间返回"Unable to detect code problems"，此时必须转 Maven 真实编译取结论，并把"是否出现 Recompiling/Compiling N source files"作为 BUILD SUCCESS 是否有效的判据。
