## Task description
- Core requirement: determine the correct role assignment for a new mobile app demo account ("yszh") to ensure it can view all relevant data on the mobile app
- Task background: the system uses a multi-tenant RBAC model with additional area_code-based data filtering for "monitor_role"; the goal is to find the role that provides maximum data visibility for demonstration purposes

## Execution process
1. Verified the mobile app's API endpoints and their required permissions (eiot:firewatch:alarm:query, eiot:firewatch:data-center:query, etc.)
2. Checked the permission assignments for existing roles (167 wx_user, 166 monitor_role) in system_role_menu table
3. Discovered the critical data visibility rule: system tenant (tenant_id=1) + wx_user role sees ALL tenants' firewatch data, while system tenant + monitor_role is filtered by area_code
4. Confirmed the current test account (id=104) has area_code="440000" (Guangdong) and monitor_role, explaining why it sees tenant 166's data
5. Analyzed the demo data distribution across tenants, confirming tenant 166 has 31207 alarms while tenant 1 has only 2
6. Concluded that for maximum data visibility, assign the new yszh account the "wx_user" (小程序用户) role under tenant 1
