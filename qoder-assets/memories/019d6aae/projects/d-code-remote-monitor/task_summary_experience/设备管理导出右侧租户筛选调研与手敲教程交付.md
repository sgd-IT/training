## Task description
- Core requirement: 设备管理页在"导出"按钮右侧增加一个租户筛选下拉。
- Task background: 前端页面 deviceinfo/index.vue 使用 yt-crud 公共组件，导出按钮由 fun-props.exportBtn 在 yt-table-fun.vue 工具栏渲染；用户中途改为"我来手动添加"，任务转为只读调研 + 手敲教程交付，agent 未改任何代码。

## Execution process
1. 定位落点：yt-table-fun.vue 工具栏左组顺序为 新增col → addRight插槽 → 导出col → 批量删除col，导出右侧无扩展位；需照 addRight 先例新增 exportRight 插槽并在 yt-crud.vue 透传（纯增量，旧页面不传不渲染）。
2. 后端盘点确认零改动：DeviceInfoPageReqVO 已有 tenantId 字段，EiotDeviceInfoMapper.selectPage 有 eqIfPresent(tenantId)；/eiot/device/export-excel 复用同一 VO，列表与导出过滤均天然生效。
3. 发现既有缺陷：页面未监听 yt-crud 的 exportFun 事件，导出按钮当前点击无反应（哑按钮）；DeviceInfoApi.exportDeviceInfo 已定义好可复用。
4. 关键结构事实：yt-table-search.tsx 第20行 formModel = ref(props.query)，搜索表单与页面 state.query 是同一对象引用——外部挂到 state.query 的 tenantId 不会被搜索提交覆盖，重置也只清表单注册字段。
5. 复用现有资产：页面已有 loadTenantOptions()/tenantOptions（原仅批量分配弹窗调用），改为初始化即加载；参照 space/index.vue 第23-39行所属企业筛选写法。
6. 交付手敲教程：分4步（开插槽→初始化拉租户→#exportRight放下拉→接export-fun），标注3个照抄坑（分页需先 pageNo=1 再刷新、清空用 delete state.query.tenantId 归一、el-row flex 子元素加 margin-left），附 F12 验证清单与边界说明（未分配租户不支持、企业账号无意义但无害）。
