## Task description
- Core requirement: 用户授权通过浏览器操作实测一级/二级报警流程，先明确测试流程再执行。
- Task background: 告警语义统一改造（level/alarm_kind/tier）已落地，需端到端验证触发→落库→WS推送→大屏分流→处置闭环全链路；后端 48080 与前端 Vite dev(3000) 均在本机运行，浏览器已带 admin 登录态直达 /#/duty-screen。

## Execution process
1. 流程梳理：读 docs/消防告警分级响应系统方案修订建议书.md（目标态）与消防告警字段语义定稿.md（现状），确认测试口径以当前代码实现为准。
2. 环境盘点：netstat + Invoke-WebRequest 确认 3000 端口即本项目 PC 前端 dev server（VITE_PORT=3000），.env.local 指向本机 192.168.250.130:48080（本机 IP 即 .130）。
3. 数据基线：MCP mysql_query 查 eiot_alert_record 最新记录（31593-31604）与大屏"今日警情 6"完全对上；eiot_device_info.dn 定位租户 166 四台摄像头（id8 烟火/id12 通道占用/id13 离岗/id17 热成像）。
4. T1 二级造数：POST /app-api/open/camera-alert/report（form data=JSON，@PermitAll 免登录）eventType=4 → 新记录 31605 四维正确（level=2/kind=3/type=4/tier NULL）；大屏无全屏弹窗、通知匣出现「离岗事件报警 ×4」聚合条目；JS 点击条目跳 /remote-console?deviceId=7&alertDeviceId=13。
5. T2 一级造数：eventType=2（devSno=CE0DD7APAGA8B59）→ 子代理 157 秒 DOM 轮询捕捉到弹窗 3 次完整周期：:18s 弹出、15 秒倒计时自动关、精确 60 秒重弹，与旧烟火告警相位差 30 秒串行排队。
6. T3 处置闭环：JS 点击『去处置』→ status=2+read_flg=1、弹窗关、经 findTransferDeviceId(17)=7 跳远程控制台、不再重弹；另造 31607 点『稍后处置』→ status=1、不跳转、约 144 秒后原样重弹。
7. MCP 会话中途掉线（not found MCPHost severName）：改从 .qoder/mcp.json 读 env 变量，用本地 mysql.exe + $env:MYSQL_PWD 兜底完成全部数据库校验。
8. Browser 视图宿主窗口不可见致截图全败：约 15 种页内恢复手段无效，须用户在 IDE 重开 Browser 视图；测试改以 JS evaluate/DOM 快照为证据继续推进。
