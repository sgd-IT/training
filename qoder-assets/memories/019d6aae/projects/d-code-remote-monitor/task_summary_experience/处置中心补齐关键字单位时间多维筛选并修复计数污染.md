## Task description
- Core requirement: 给 PC 端「处置中心」（views/eiot/firewatch/alarm-order/index.vue）补齐可筛选条件，用户表述为"添加可筛选的各种条件"。
- Task background: 后端 GET /eiot/firewatch/alarm-order/page 的 AlarmOrderPageReqVO 已支持 orderNo/propertyId/propertyName/alarmType/alarmLevel/orderStatus/deviceType/alarmTimeBegin/alarmTimeEnd/keyword，但前端只接了 alarmType 与 orderStatus 两项，且原控件挤在「实时警情」标题右侧 header-actions 里；页面 3127 行，属单文件前端改造。

## Execution process
1. 前置盘点结论：后端零改动即可实现，因此方案定为"前端暴露已有入参"；先向用户点选确认要哪些维度与布局位置（用户选关键字/时间范围/所属单位 + 独立筛选区）。
2. 排除「设备类型」筛选：查证 dashboard/device-category 返回的是 categoryName+count 图表数据、无 category_id，而 alarm-record 页把该接口当字典用并取 categoryCode||productKey||id（三字段均不存在），value 恒为 undefined —— 该页设备类型筛选实为死参数；换用 /eiot/category/list 又需 iot:category:query 权限，故本次不做。
3. 排除「告警级别」筛选：level 列新旧双语义（旧行 1-6 类型编码、新行风险等级 1-3），mapAlarmLevelToRecordLevel 会把两者混着筛，暴露给用户会误筛。
4. 物业下拉权限核验：用 MySQL MCP 聚合 system_role_menu，确认除 role_id=168「值班人员」外全部角色都有 eiot:firewatch:property:query，PC 处置中心主用角色（远程值守员 161、消控室值班员 165）均可用，故保留该项；加载失败时下拉留空不阻塞其它条件。
5. alarm-order/index.vue 模板：新增独立筛选卡片置于左栏最上方（实时警情卡之前），含关键字 el-input（回车/搜索触发）、所属单位 el-select（filterable）、报警时间 el-date-picker datetimerange（最近一周/一月/三月快捷项）、报警类型（补 info 值）、处置状态 + 搜索/重置按钮；标题栏只留实时刷新 tag 与刷新/历史按钮；删除 handleAlarmTypeChange/handleOrderStatusChange，合并为统一 handleSearch（任一条件变化回第 1 页）。
6. alarm-order/index.vue 脚本：refreshAlarms 透传 keyword/propertyId/alarmTimeBegin/alarmTimeEnd（空值转 undefined），时间格式 YYYY-MM-DD HH:mm:ss 对齐后端 @DateTimeFormat；alert_time 实测为毫秒 bigint，后端做 LocalDateTime→毫秒换算。
7. 顺带修复两缺陷：每分钟计时器原本把 pendingCount 覆盖成当前页 pending 条数（≤pageSize=10，加筛选后还会随筛选跳动），改为独立 nowTick 时间基准驱动「持续时间」重算；refreshAlarms 增加 notify 参数，仅手动刷新按钮/快捷键 R 才弹 toast。
8. 验证：语言服务检查从 7 个问题降到 6 个既有 unused-var 警告、零 error；el-date-picker 的 v-model 不接受 null，把 timeRangeFilter 由 ref<string[]|null>(null) 改为 ref<string[]>([]) 消除类型错误；测试库 SQL 核对关键字"消防主机"命中 1555 条、当天区间命中 1391 条。

## Notes
- 模板事件绑定 @click="fn(true)" 会被 vue-tsc 按 handler 签名比对报类型错（(notify?: boolean)=>Promise<void> 不能赋给 (evt: MouseEvent)=>any），改 @click="() => fn(true)" 或抽具名函数即可；无参函数直接绑定则安全。
- 「所属单位」走后端 propertyId → tenantId 换算，企业租户下多物业共用同一 tenant_id 时选任一单位都返回该租户全量，主要对 admin 跨租户查看有效；测试库实测大量物业 tenant_id=1 而告警集中在 tenant 166。
- git diff 显示该文件工作区仍有前序会话未提交改动（deferred 状态相关），本次未触碰，提交时需按最小单元只挑筛选相关部分。
- 未启动 dev server 做浏览器验收（本地无前端/后端端口监听），排版靠代码审查保证。
