## Task description
- 核心需求一：用户要求 alarm-popup-card 报警弹窗弹出时"外侧的大屏背景不要太模糊"。
- 核心需求二：随后用 /ponytail 追问"这里可以缩减代码行吧"，指向当时打开的设备详情页，需在不改变行为前提下精简代码。
- 背景：报警弹窗为 duty-screen 与 monitoring-center 两页各自内联实现的深色卡片，外侧模糊由遮罩层 `.alarm-popup-overlay` 的 backdrop-filter + 黑色遮罩叠加造成；detail.vue 约 1466 行，含大量历史注释块与无引用变量。

## Execution process
1. 定位模糊来源：两文件的 `.alarm-popup-overlay` 均为 `background: rgba(0, 0, 0, 0.65)` + `backdrop-filter: blur(4px)`；duty-screen 其余 blur(8px)/blur(16px) 属下拉菜单等组件，与本需求无关。
2. 判断"只降 blur 感知不明显"：模糊感是 blur 与遮罩暗度叠加结果，故两处同步改为 `rgba(0, 0, 0, 0.4)` + `blur(1px)`，保持两屏一致（弹窗卡片自身有发光边框与阴影，聚焦感不受影响）。
3. detail.vue 死代码逐项验证后删除：先用 Grep 确认 showMap/showDeviceMap/mapLnglat/eventMap/state.deviceLogs/onlineTime/tagForm.identifier/locateChange/sipInfo/getPlayerData/channelRef/deviceLiveStreamRef 均无读取方，再批量 SearchReplace 移除；同时删除已注释的旧功能块（设备通道/直播 tab、旧分页、标签提交逻辑）。
4. 保留故意嵌套的时序依赖：getDeviceInfo 中 fillProperty 必须等 state.thingModel 在回调里赋值后才能调用，两次 getDeviceProperties 调用的嵌套结构不可外提并行。
5. 重复逻辑合并：序列号双按钮 → 单按钮 + 三元文案；pickerOptions 四个手写 shortcut → 数组 .map() 生成；timeRangeChange 包装函数删除，模板直接绑 refreshPropertyHistory。
6. 顺手修既有类型错误：getLevelType 返回类型缩窄为 el-tag 接受的联合类型并去掉无效 '' 映射；`disabled="true"` → `disabled`；`rows="4"` → `:rows="4"`；删除未使用的 ProductVO import。
