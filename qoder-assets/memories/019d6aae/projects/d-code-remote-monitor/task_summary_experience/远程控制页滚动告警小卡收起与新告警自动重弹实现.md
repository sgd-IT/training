## Task description
- Core requirement: 给远程控制页（remote-console）右上角"滚动告警小卡"增加"×收起"按钮，点击后本次会话静默、出现新告警再自动重新弹出。
- Task background: 该小卡每 10 秒轮询未处置告警并轮播展示；库里存在 handle_status=1（稍后处置）的历史告警未被回捞排除，导致小卡长期重复展示同几条旧警，用户从大屏处置完跳过来仍被打扰。此前已就"UI 收起 vs 数据侧根治"做过权衡决策，用户拍板先做 UI 收起（A 项），B（handle_status 排除）与 C（小卡显示口径）仍待拍板。

## Execution process
1. remote-console/index.vue 模板：在小卡头部右侧新增"×"收起按钮，hover 提亮样式写在组件内 style 块。
2. 新增两个页面级内存态 ref：scrollAlertDismissed（是否处于收起静默态）与 dismissedAlertIds（收起那一刻已见过的告警 id 集合）。
3. 点击收起：置 scrollAlertDismissed=true 使小卡消失，并把当前 pendingAlerts 的全部 id 记入 dismissedAlertIds；不做任何后端回写，刷新/重进页面即复位。
4. 轮询回调改造（核心逻辑）：取数后统一兼容 `const alerts = (Array.isArray(res) ? res : res?.data) || []`，赋值 pendingAlerts，非空则 startAlertScroll()；若处于静默态，用 `alerts.findIndex((a) => !dismissedAlertIds.value.has(a.id))` 找第一条未见过的告警，命中则把 scrollAlertIndex 定位到该下标并置 scrollAlertDismissed=false，实现"新告警自动重弹且直接定位到那条新告警"。
5. 再次点击收起以新的 id 名单重新静默，循环往复；静默期间轮询照常运行（后台持续监测）。
6. 验证：node 直跑 eslint --quiet 结果 0 错误；提取 index.vue 全部 `<style>` 块（共 2 个）逐个 sass.compileString，结果 BLOCK0_OK / BLOCK1_OK。

## Notes
- 首次 SCSS 校验误报失败：sass.compileString 未传 url，导致样式块内既有的 `@import './styles/common.scss'` 相对导入解析不到基准路径。修正方式是传 `url: pathToFileURL(path.resolve(vueFile))`，让相对导入按 .vue 文件所在目录解析；loadPaths 对以 ./ 开头的相对导入无效。
- compileString 通过时仍会打印大量 darken()/lighten()/@import 弃用警告，这是全项目既有基线，不代表本次改动引入问题，判定只看 BLOCKx_OK/ERR。
- "本次会话静默"只针对收起那一刻已见过的那批告警，因此库里 status=1 的旧警不会再打扰，但全新告警仍会重弹——这与 B 项（数据侧排除 handle_status=1）语义不同，不能混淆。
- 收起态是纯前端内存态，与既有"通知匣未读计数只做内存态不持久化"的口径一致。
