## Task description
- Core requirement: 两项。①回答「安为科技值守中心租户可以查看全部租户数据吗」；②在租户「安为科技值守中心」下创建 3 个「消控室值班员」账号（昵称袁宏凡/张开然/黄运航），同时给管理员补一个「用户管理里重新设置密码」的功能。

## Execution process
1. 可见性查证：查 system_tenant 确认「安为科技值守中心」= id=1 且 package_id=0（系统套餐），165/167 为企业套餐、166 为智慧消防测试套餐；读 TenantAreaTenantIdDataPermissionRule、OAuth2TokenServiceImpl.fillTenantAndRoleInfo、TenantSecurityWebFilter 三层源码，得出「租户层全量 + 角色层 area_code 收紧 + 页面层 super_admin 才显示租户下拉」的口径，并确认企业账号篡改 tenant-id header 会被 403 拦截。
2. 建号信息逐项确认（AskUserQuestion 一轮一项）：账号名取拼音全拼；手机号由用户提供真实号码（袁宏凡 17371094396、张开然 13945708206、黄运航 19165760135），查重 SELECT ... WHERE mobile IN (...) 返回空；登录平台选「仅 PC」即 user_type=1、初始密码 123456。
3. 重置密码需求核实为「功能已存在、无需开发」：后端 UserController 的 PUT /system/user/update-password + AdminUserServiceImpl.updateUserPassword(id, password)（不校验旧密码、bcrypt 覆盖、写操作日志）、前端 user/index.vue 行尾「更多」→「重置密码」、权限点菜单 1007 system:user:update-password 均已具备；进一步查 system_role_menu 发现该权限只分配给租户 166/168 的 tenant_admin（role 155/170）及 role 164/169，而租户 1 根本没有 tenant_admin 角色行，只有 super_admin。
4. 密码哈希核验：用 JDK21 单文件源码模式运行 _temp/VerifyHash.java，classpath 需同时带 spring-security-crypto + spring-core + spring-jcl（缺 spring-jcl 会 NoClassDefFoundError: org/apache/commons/logging/LogFactory）；先比对 zhangwei/lina/wangqiang 三人 hash 完全相同且 matches("123456")=true，再用 BCrypt strength=10 生成 3 个各自独立的新 hash 并逐一自校验。
5. 落库：向 system_users 插 3 行（username/password/nickname/mobile/user_type=1/dept_id=103/status=0/tenant_id=1/creator/updater/deleted=b'0'），得 id 159/160/161；再 INSERT INTO system_user_role SELECT u.id, 165 ... 关联角色 fire_watcher；联表复核 role_code=fire_watcher 且 role_tenant=1，角色 165 当前 48 条菜单。
6. 登录链路验证：PC /system/auth/login 走 generate-login-nonce 后仍被 captchaVerification 拦住（脚本无法通过图形验证码）；改用免验证码的 /system/auth/mobile-login 做对照——正确密码返回「该账号为 PC 端账号，请使用电脑端登录」（证明密码通过、user_type=1 生效），错误密码返回「登录失败，账号密码不正确」，形成对照闭环。
7. 清理临时文件 _temp/VerifyHash.java。

## Notes
- 「给管理员加重置密码功能」这类需求要先盘点框架现成能力再动手：本例后端接口、前端按钮、权限点三者齐全，真正缺口是角色未勾选该权限点，若直接开发就是重复造轮子。
- PC 登录有验证码时不要硬试 curl，用免验证码但同样经过 authenticate 的 mobile-login 做正误密码对照，可侧面证明密码哈希正确且不改动任何代码。
- bcrypt hash 复制粘贴虽可用，但逐账号重新生成成本极低且避免"多人共享同一串密文"的观感问题。
- 租户 1 无 tenant_admin 角色行，值守中心的运营视角只能靠 super_admin。
