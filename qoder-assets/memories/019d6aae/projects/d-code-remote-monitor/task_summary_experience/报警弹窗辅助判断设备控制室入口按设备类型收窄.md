## Task description
- Core requirement: AlarmAssistPanel 辅助判断行内"设备控制室"入口，只有 deviceType 为 transfer 的设备行才显示（之前按 transferDeviceId 非空即显示）
- Task background: AlarmAssistPanel.vue L55 原条件 `v-if="row.transferDeviceId"` 使所有父链上溯到用传设备的子设备也显示该按钮；用户要求收窄为仅用传设备自身行可见

## Execution process
1. 读 AlarmAssistPanel.vue 全文确认现状：按钮条件 `row.transferDeviceId`、链接容器条件 `row.cameras.length || row.transferDeviceId`、goConsole 逻辑依赖 transferDeviceId 做跳转参数
2. 读 alarmAssist.api.ts 确认前端类型定义（AlarmAssistDevice 有 type:string 和 transferDeviceId:number|null）
3. 读后端 FireWatchAlarmAssistServiceImpl.java 核实两个关键点：(a) L269 `vo.setType(device.getDeviceType())` — row.type 就是 deviceType 原值；(b) climbTransferDevice 对 transfer 设备返回自身 id，所以 transfer 行的 transferDeviceId 恒非 null
4. Grep "设备控制室" 全 firewatch 目录确认只有一处需改（AlarmPopupDialog 的只是注释、其他屏是顶栏导航不影响）
5. SearchReplace AlarmAssistPanel.vue：按钮条件改为 `row.type === 'transfer'`；链接容器条件同步改为 `row.cameras.length || row.type === 'transfer'`
6. SearchReplace alarmAssist.api.ts：transferDeviceId 注释从"可进设备控制室"改为"该设备可反控（自身是用传设备或父链上溯命中），值为用传设备ID"
7. ESLint 两文件零错误、vue-tsc 无新增相关报错
