## Task description
- Core requirement: 定位"大屏报警弹窗重复跳出"的根因，判定是数据库出现连续两条告警导致两次推送，还是前端接收后重复推送。
- Task background: 9-24 仅做过只读诊断（嫌疑链路未落地），修复动作未实施；摄像头告警经 DeviceAlertConfigServiceImpl.reportCameraAlert 落 eiot_alert_record 并推 firewatch-alert-new，duty-screen 按 alertId 去重弹窗。

## Execution process
1. 数据库取证（MCP server anwei_fire_remote_monitor_test / mysql_query）：eiot_alert_record 中 device_id=8（烟火算法摄像头 dn=BL094C4PCU38258，租户166）的"烟火事件报警"大量两两成对（相邻 id、alert_time 差 0.37~7.8s、create_time 差 0~1s），9 月共 22 对且集中在该单一设备。
2. 关键判据：成对记录 alert_image URL 完全相同；FileUtils.generatePath 用 SHA-256 内容哈希生成 URL → 同图必同 URL → 推断为上游对同一事件发了两次独立 HTTP 请求携带同一张抓拍图，而非后端/数据库双写。
3. 后端链路核查：reportCameraAlert 每次调用无条件 insert + notifyAlarmSaved（无幂等保护），2 次请求 = 2 条记录 = 2 次推送（两个不同 alertId）。对比 addDeviceAlertRecord/AlarmRecordService.saveAlarms 才有查重/去重窗口。
4. 前端核查：useWebSocket(@vueuse/core) 单条消息只触发一次 watch，排除"收1次弹2次"；但 alertShownIds 按 alertId 去重无法拦截两个不同 id；onHandleNow 处置会 delete(id)，且 fetchRecentAlerts 每 10 秒轮询未处置告警，构成次要放大路径。
5. 本地日志不可作证据：server-console.log 仅 818 字节、server-48081-console.log 只覆盖到 8-17，均无 9 月下旬摄像头告警记录。
6. 修复方案讨论（用户决定自行改后端）：确认框架有 IdempotentRedisDAO(setIfAbsent SETNX+TTL) 但全仓无业务先例；最终选查库方案——Mapper 新增 selectRecentCameraAlert(deviceId, alertImage, fromTime, toTime)（照搬 selectActiveAlert 的 LambdaQueryWrapperX + LIMIT 1），service 在 insert 前检查命中则 return；窗口取 ±10s（常量 CAMERA_DEDUP_WINDOW_MS）；低频场景不加锁。
