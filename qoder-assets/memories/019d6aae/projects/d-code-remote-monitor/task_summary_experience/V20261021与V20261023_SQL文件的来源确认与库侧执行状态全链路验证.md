## Task description
- Core requirement: 用户询问 V20261021__maintenance_plan_window.sql 和 V20261023__alert_record_merge_order_status.sql 是否是最新程序里添加的，以及是否还有其他未被提及的SQL变更
- Task background: 用户关注的是“程序比数据库多出来的部分”，即代码已更新但数据库尚未同步的DDL；需确认这两个文件的引入提交、实际执行状态，并盘点是否存在其他遗漏的迁移

## Execution process
1. 通过 git log 定位两个SQL文件的引入提交：V20261021 来自 93815c1（2026-10-21），V20261023 来自 40d5ad2（2026-10-23）
2. 使用 MCP 查询 information_schema.COLUMNS 验证两库字段存在性：target_tenant_id/start_time/end_time 和 handle_status 注释均已更新，说明 A7 已执行；order_status 在生产库仍存在，B段 DROP COLUMN 未执行；测试库无 order_status 列，A5/B段在测试库会报错
3. 使用 mysql.exe 连接生产库，查询 eiot_alert_record.order_status 的列属性（NULL 允许、默认 NULL）及近3天告警插入数（80条），证明新代码不写该列且插入正常
4. 扫描 10-23 后的提交，确认无新增 DO 字段或表结构变更需求
5. 通过 grep 和 MCP 查询确认生产库真正缺失的是 fire_maintenance_unit 和 eiot_call_record 两张表，对应 V20260827 建表段
