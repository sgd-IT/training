按原型 V3（alarm-assist-prototype-v3 工程包）把「辅助判断」区复刻到两个大屏的内联报警弹窗，已完成 UI 复刻（演示数据版）。

## Task description
- 核心需求：用户要求"把前端的报警弹窗修改了，直接复用就好，修改点就是当前使用的报警弹窗"，即把原型 V3 的辅助判断区块加进现有报警弹窗。
- 背景：后端空间管理刚起头（FireSpaceDO/FireSpaceMapper，alarm-assist 接口尚不存在），前端 duty-screen 与 monitoring-center 各有一套同款深色内联实时告警弹窗（WS 推送 + alertQueue + 倒计时自动关闭），弹窗数据里有 id（告警记录 ID）与 deviceId，可作为将来辅助查询主键。

## Execution process
1. 现状调研：确认两屏弹窗结构同款（body 结束与底栏之间为插入位）、脚本弹窗状态区（POPUP_AUTO_HIDE_SECONDS 之后）与 style 末尾为另两处插入位；盘点出可复用的既有对接资产（getCamerasByDevice → /video-surveillance?cameraId=、monitoring-center 的标记误报/确认火警真实 API、设备详情页 eiot/deviceinfo/detail.vue）。
2. 口径确认（三轮反问）：数据来源=先嵌演示数据；范围=两个大屏都改；点击承接=本轮暂不接。
3. 采纳用户建议改为 9 步小步执行：扒样式 → duty-screen 模板/脚本/样式 → 检查 → monitoring-center 模板/脚本/样式 → 检查。
4. 两文件各三处插入（约 +45 模板 / +56 脚本 / +122 样式）：模板 assist-section（标题行 + 联系现场核实 + 展开/收起 + evidence-detail 列表 + SVG device-icon）；脚本 assistExpanded(ref true)、assistIconPaths（4 种设备 SVG path）、assistDemoList（原型场景一 5 条：报警中/未报警/可查看×2/未接入）；样式为 prototype.css 第 4 行主体 + revision.css 第 7-9 行修订合并后的最终效果。
5. 每步验证：类名冲突检查、读回实际文本确认嵌套、GetProblems、新变量定义唯一性交叉检查。

## Notes
- 原型样式分布：辅助区主体在 prototype.css 第 4 行的超长单行内，revision.css 只做覆盖（.assist-heading-v2 系列）；existing-frontend.css 里没有辅助区相关类，检索需按 assist/evidence/resource/device-icon 逐文件定位。
- 往模板插入几十行后，同文件 script/style 的行号会整体偏移，先前 grep 得到的行号失效，必须重新 grep 定位再改。
- SearchReplace 的 diff 渲染可能把重复的 </div> 闭合行错位对齐，看起来像嵌套错误；应以读回实际文本为准判断，不要凭 diff 视图重复修改。
- 两文件的辅助类名（assist-section/device-icon/dark-evidence-row/resource-name/evidence-state/assist-link）原先均不存在，无样式冲突；style 为 scoped scss，平铺 CSS 追加在文件末尾即可生效。
