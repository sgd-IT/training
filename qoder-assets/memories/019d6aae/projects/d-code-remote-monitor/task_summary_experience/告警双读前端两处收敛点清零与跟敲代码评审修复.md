## Task description
- Core requirement: 执行消防告警字段语义统一改造剩余的两处前端待收敛点（主机告警配置页标签偏差、设备详情告警记录筛选旧编码），并对用户按教程手敲的告警消息列表代码做校验评审与修复
- Task background: 双读改造前期已完成后端写侧三写与 list.vue 收敛；config.vue 页面选项 3=离线/4=反馈 与库内事实不符；detail.vue 告警记录 tab 筛选仍挂旧编码（火警/设备故障/电源故障）；用户在练习跟敲 list.vue 时把文件覆盖为自己的版本并引入多处错误

## Execution process
1. 查库核证：MCP 查询 eiot_alert_config 全部 18 条配置的 name+level，逐条对上库内编码为 1火警/2故障/3电源故障/4离线/5其他（level=3 全为"电源故障事件触发"、level=4 全为"装置离线事件触发"、level=5 为 PRT/CRT），确认页面标签"3=离线/4=反馈"是错的
2. views/eiot/alarm/config.vue：列名"告警等级"改为"告警类型"（该列语义是类型非等级），下拉选项 3/4 标签校正为"电源故障/离线"
3. views/eiot/deviceinfo/detail.vue：告警记录 tab 筛选下拉由旧编码（火警/设备故障/电源故障）改为一级/二级/三级，与告警消息列表口径一致；同行表格"X级"标签列核实新数据表现正常后维持不动
4. vue-tsc 基线对照：IDE 报出的两文件错误经与基线日志逐行 Compare-Object 确认全部为既有历史错误（行号位移 +1/+2 由新增注释导致），config 6/6、detail 10/10 条数持平
5. 用户跟敲版 list.vue 评审发现 5 处问题并修复（保留用户的命名与排版风格）：①三张映射表泛型写成大写 Record<String, String>（TS2344×3，须小写 string）；②isNew 判据多敲 .id 写成 row.alarmKind.id（旧数据 null.id 运行时抛异常，整个列表页挂掉，编译不报错）；③旧回退分支误取 String(row.alarmKind) 应为 String(row.level)（双读灵魂在旧分支，静默错误致旧数据类型列全空白）；④告警类型列 key 敲成空串未绑定 typeText；⑤告警等级展示列整列漏敲且旧数据占位符敲成空格 ' ' 应为 '—'
6. 修复后终验：vue-tsc 全量输出总行数 481 = 基线 481，list.vue 错误归零，config/detail 持平，零新增
7. 定稿文档《消防告警字段语义定稿.md》补录 F11（config.vue 收敛）、F12（detail.vue 筛选收敛）两条

## Notes
- "总行数多了 3 行"这类全局数字疑点必须用 Compare-Object 逐行 diff 查到底，不能只看单文件条数持平就放行——本次正是靠 diff 才揪出用户跟敲文件里的 3 条新增 TS 错误
- 列 key 与加工函数产出的字段名必须两头对齐（typeText/levelText），单看加工函数正确不够
- 手敲练习类错误的教学价值排序：编译能抓的（大写 String）远低于编译抓不到的静默错误（.id、旧分支取错字段）；验证顺序应先 vue-tsc 抓编译错、再跑页面抓运行时错
- 判空可用 != null 一并覆盖 null 与 undefined，比 !== null && !== undefined 双判更简洁
