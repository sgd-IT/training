## Task description
- Core requirement: 对三仓库（后端 anwei-fire-remote-monitor、前端 anwei-fire-remote-monitor-vue、移动端 anwei-fire-remote-monitor-mobile）最近3天作者 sgd 的提交 + 当前未提交变更做 ponytail-review，随后执行修复。
- Task background: 用户先询问 ponytail 六件套用途，再要求按最小改动原则审查近期代码；提交范围 Vue 2 笔、后端 15 笔、移动端 0 笔，另有三仓未提交工作区改动（Vue +530/-505、后端 +93/-22、移动端 +80/-7）。

## Execution process
1. 用 git log --author="sgd" --since="3 days ago" 逐仓盘点提交，git diff <首笔>~1..<末笔> --stat 划定范围；大 diff 落盘到 _temp 目录后分段 Read。
2. 产出 ranked findings：Vue AlarmPopupDialog 的 PAUSE_COUNTDOWN_ON_OVERLAY 常量、monitoring-center closePopup 薄包装、后端 FireDataCenterServiceImpl 四个 switch 计数方法、AlarmSemantics 四个 switch、detail.vue 空 validate()、移动端 duty/index.vue 跨天判断边界等，估算净减约 115 行。
3. 执行修复共 4 项落地：删除 AlarmPopupDialog 的 PAUSE_COUNTDOWN_ON_OVERLAY 常量并 inline；resolveWindow() 提取 today 变量避免两次 LocalDate.now()（顺带消除跨午夜竞态）；detail.vue 的 formRef.value.validate(() => {}) 空操作改为 TODO 注释；移动端 dutyTimeText() 的 endTime <= startTime 改为 < 修正 08:00→08:00 整24小时班误标"次日"。
4. 撤回 2 项评审建议：closePopup() 薄包装在 6 处调用中可读性更佳予以保留；AlarmSemantics 的 String switch 编译为 hash 跳转表、比 Map.get() 零装箱更快，改 Map 属反向优化。
5. 所有修改保持未提交状态，提交与否交用户决定（符合提交前确认约束）。
