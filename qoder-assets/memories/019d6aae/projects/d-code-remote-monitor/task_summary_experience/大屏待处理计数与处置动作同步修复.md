## Task description
- Core requirement: 修复大屏「待处理」统计数字在用户执行处置操作后不减少的问题
- Task background: 统计判据已统一为 `handle_status IS NULL OR handle_status < 3`，但 FireAlarmOrderServiceImpl 的所有处置入口（确认火警/标记误报/关闭工单等）只写 `read_flg=true` 而不更新 `handle_status`，导致处置后 pendingCount 不变；实时告警列表因判据含 `read_flg` 反而会消失，形成割裂。

## Execution process
1. FireAlarmOrderServiceImpl.java：在 `doHandleAlarmOrder` 和 `doMarkReadAndAppend` 两个落库点，各增加一行 `record.setHandleStatus(resolveHandleStatusByAction(action))`
2. FireAlarmOrderServiceImpl.java：新增私有方法 `resolveHandleStatusByAction`，定义 `confirm` → 2（处置中），`false_alarm`/`real_fire`/`close`/`manual` → 3（已闭环）
3. AlertOrderStatusResolver.java：修改 Java 分支逻辑，当 `handle_status=3` 时，若末段处置记录为“关闭工单”，仍返回 `closed` 以保留细分语义
4. AlertOrderStatusResolver.java：同步修改 SQL CASE 语句，将 `关闭工单` 的判断提到 `handle_status=3` 之前，确保新数据能被筛选命中
5. 编译验证：`mvn compile -pl module-eiot/module-eiot-biz` 执行成功
6. 数据库验证：使用 MCP 查询 test 库，确认当天 5 条告警的 `handle_status` 全部为 1 或 2，印证了“处置无法变少”的现场快照
