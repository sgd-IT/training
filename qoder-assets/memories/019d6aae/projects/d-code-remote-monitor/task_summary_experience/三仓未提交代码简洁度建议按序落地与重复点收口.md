## Notes
- 落地前必须重跑 git status/diff 并重读目标片段：检查报告与动手之间存在时间差，期间用户或并行会话可能已修同一处（本轮 status_group 即例），照旧 diff 硬替换会覆盖他人改动。
- SearchReplace 匹配失败往往不是格式问题而是内容已被改写，应立刻 Read 该区确认而非反复调整空白字符重试。
- 语言服务在连续编辑期间会给出中间态假报错（toCountMap undefined、GetProblems 报 not ready），最终结论只能靠 mvn 编译，且 BUILD SUCCESS 需再用 class/java 时间戳佐证。
- 收敛类重构的收益未必体现在行数：本次后端净增约 11 行（新增静态方法与解释性注释），真正的价值是判据单点化；汇报时应如实说明而非宣称减行。
- 接口字段语义变更（expire 从分钟数改毫秒时间戳）必须在交付说明里显式提醒下游，移动端尚未接入该接口。
