## Task description
- Core requirement: 用户提出"循环里操作数据库超过 1 次就会造成性能危机"这一判断标准，需要据此全仓体检并收敛同类写法
- Task background: 上一轮已修完告警列表 doPageFromAlertRecord 的应用层 N+1；本轮回扫同类模板，发现设备/空间/摄像头/远程控制台四条列表链路都在"去重后循环逐个 tenantService.getTenant(id)"，注释写着"避免 N+1"但实际只是把按行查降为按租户查

## Execution process
1. 用 multiline Grep（for(...) { ... selectById|selectOne|selectCount|getTenant( }）在 module-eiot-biz 定位到 5 处同构实现：DeviceInfoController#getDeviceInfoPage、AppDeviceInfoController#getDeviceInfoPage、FireSpaceController#listFireSpace、VideoCameraController#getCameraTree、RemoteConsoleServiceImpl#getDeviceTree
2. 盘点现成能力：grep getTenantMap 确认 TenantService.getTenantMap(Collection<Long>)（内部 selectBatchIds，一条 IN）已存在且 UserController 分页/导出早已在用，因此不新增接口方法
3. 五处统一改为"收集 tenantIds → TenantUtils.executeIgnoreWithResult(() -> tenantService.getTenantMap(tenantIds)) → 循环内 Map.get 回填"，保留原 executeIgnore 跨租户语义；同时放弃逐条 try-catch 吞异常（租户名批量查询走同一个库，真异常时主列表也查不出，继续吞只会掩盖问题）
4. mvn -o -pl module-eiot/module-eiot-biz -am compile 验证被用户取消，改动未编译验证
5. 用户改口"这是经验，后续我来改，只记录总结"，转为按 work-log skill 落盘：01-项目/消防远程值守系统.md 新增《列表接口租户名回填的 N+1 体检 · 2026-10-20》、03-踩坑手册.md 后端分区新增《循环内逐次查库（伪批量）》四行条目、00-履历总表.md 加索引行；06-面试素材.md 因同主题已有条目未重复添加
