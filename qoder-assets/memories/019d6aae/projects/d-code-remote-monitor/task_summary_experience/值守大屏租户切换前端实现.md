## Task description
- Core requirement: implement tenant switching on the duty-screen (firewatch dashboard) so that super_admin can view data across all tenants or switch to a specific tenant
- Task background: the duty-screen is a full-screen page with multiple data cards loaded from a single statistics API; it previously only showed data for the current login tenant; the backend has already implemented tenant isolation via TenantUtils.execute and supports optional tenantId parameters for super_admin

## Execution process
1. Template modification: add an el-select dropdown in the header-left section, visible only for super_admin, with options for "All Tenants" and individual tenants; non-super_admin users see only the tenant name text
2. Script setup: define ref variables for tenantOptions, selectedTenantId (initialized to 0), and loginTenant (initialized to {}); add computed isSuperAdmin based on userStore.getRoles
3. New function: implement loadTenantOptions to fetch the list of tenants via getTenantPage API and populate tenantOptions, filtering out system tenant id=1 to prevent "all-tenant" view confusion
4. Integration: call loadTenantOptions inside onMounted to load options on page load
5. Verification: super_admin sees dropdown with options; enterprise accounts see only tenant name; Network tab confirms tenant/page request is only made for super_admin

## Related files
- /src/views/eiot/firewatch/duty-screen/index.vue

## Notes
- The template uses v-if="isSuperAdmin" to control visibility of the dropdown, ensuring non-super_admin users never see it
- The selectedTenantId is initialized to 0 as a sentinel value meaning "all tenants", consistent with backend behavior
- The loadTenantOptions function includes a guard clause to return early for non-super_admin users, preventing 403 errors
- The filter (t.id !== 1) removes the system tenant from the dropdown options to avoid confusion when selecting it would result in an "all-tenant" view

## Task overview
Successfully implemented the frontend portion of tenant switching for the duty-screen: added role-based UI controls, defined necessary state variables, implemented the tenant list loading logic, and integrated it into the component lifecycle. The feature is now ready for backend integration and cross-role testing.
