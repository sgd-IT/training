## Task description
- 核心需求：修复排班 Excel 导入"后端成功 3 条、前端显示成功 0 条"的显示缺陷；并按用户要求把导入失败信息"偏用户化"展示（可对照行号的原因列表）。

## Execution process
1. 定位根因：duty/index.vue 直接读 res.successCount，而 request.upload 返回完整报文 {code,msg,data}（与 post 解包不同），字段全为 undefined → 显示"成功 0 条"。后端日志证据：3 次 insert 均 Updates:1、汇总"成功 3 条，失败 0 条"，即导入本身是成功的。
2. 新增 src/utils/importResult.ts：showImportResult(res) 兼容完整报文/原始响应体两种来源；全成功→ElMessage 轻提示；有失败→ElMessageBox 弹窗（maxHeight 300px 滚动、全失败红色/部分失败橙黄色、HTML 转义防注入、catch 吞掉关闭时的 reject），逐行列"第 N 行（名称）：原因"。
3. 排班页接入统一展示并修正解包；catch 不再重复弹通用"导入失败"（请求层已弹具体业务原因如"导入数据为空"）。
4. 巡检/隐患页同步接入（原实现把含失败的提示也当 success 绿提示、以 <br/> 拼 HTML），字段沿用 failDetails/reason。
5. 后端 ExcelImportUtils.processImport 修复计数虚高：处理器自行 addError 后 return 的行不再重复计成功（以 failCount 前后对比判断）。
6. 文案：createSchedule 未知入库异常的兜底提示由"请查看服务端日志"改为"请稍后重试或联系管理员"，技术细节保留在 log.error。
