## Task description
- 核心需求：为值守大屏"按租户查看数据"完成后端改造——统计接口支持可选 tenantId（仅 super_admin 生效）、响应回传登录租户 id 与名称；并评审用户手敲的实现代码。
- 任务背景：FireDashboardServiceImpl 原有 executeWithTenantAware（UserTenantResolver.resolveLoginUserTenantId + TenantUtils.execute）做租户隔离；前端 duty-screen 尚不传 tenantId；口径已定为仅 super_admin 有下拉，tenant_admin 与普通角色只显示租户名。

## Execution process
1. 输出最终版教程：合并三轮拍板口径（仅 super_admin 下拉；普通角色查询权限走 eiot:firewatch:dashboard:query + 菜单配置，禁止下发 system:tenant:query），给出改动清单、联调步骤与分角色验收矩阵。
2. 回答用户对伪代码的疑问：读 TenantDatabaseInterceptor.ignoreTable 源码证实"系统租户账号且上下文==登录租户→跳过过滤（看全部）；上下文≠登录租户→按上下文过滤；企业账号→恒按上下文过滤"，澄清 userTenantId 是租户 id 而非用户 id、else 分支非管理员区分。
3. 第一轮评审（git diff 实读用户改动）定位三处 P0：TenantUtils.execute 传空 lambda 导致 buildStatistics 在上下文还原后执行、切换完全无效；两个 @RequestParam 缺 required=false 使所有角色 statistics 直接 400；getRealtimeAlarms 改两参但 impl 与 module-ai 两处调用点未跟随导致编译失败。另记 P1：tenantName 误用 TenantContextHolder、VO 的 tenantId 无赋值。
4. 第二轮复查确认三处 P0 已修好，新发现 getRealtimeAlarms 的 tenantId 是"死参数"（executeWithTenantAware 不识别 override，buildRealtimeAlarms 方法体未使用），超管切换后告警仍返回全部租户；内部调用还把上下文租户塞进该死参形成埋雷。
5. 编译验证：先 clean 两个模块再 -am compile，module-eiot-biz 重编 540 文件、module-ai-biz 重编 22 文件均 BUILD SUCCESS，确认签名传播无遗漏。
6. 给出收敛方案：把白名单+切换抽成 executeWithTenantAware(Supplier, overrideTenantId) 共用包装，三个调用点各一行，规则只维护一处；死参数删除。

## Notes
- 最大盲区是"参数透传了但没接上"：签名一路改到底却没人使用它，行为看似正常实为巧合；检查办法是从入口追到底问"值进来了吗、在哪生效、没生效是漏了还是设计"。
- TenantUtils.execute 只是临时改 ThreadLocal 上下文并在 finally 还原，空 lambda 等于什么都没做；必须把要执行的查询放进回调并用带返回值重载。
- @RequestParam 默认 required=true，可选参数必须显式 required=false，否则连既有前端请求都会 400。
- 改接口签名必须一次清点全部调用点（含跨模块 module-ai），靠编译器兜底；增量 mvn compile 会误报 up to date，须 clean 后重编才算验证。
- 本次只评审后端，仓库同时存在其它在途改动（ChatController、AlertService、FireAlarmOrderServiceImpl 等），提交时需与本次功能分开。
