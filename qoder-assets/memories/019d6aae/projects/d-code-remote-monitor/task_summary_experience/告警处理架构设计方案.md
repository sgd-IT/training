## Task description
- Core requirement: Design an alarm processing architecture for IoT device messages from two integration methods (TCP remote monitoring component and AEP platform)
- Task background: Existing codebase has TCP GBT26875 component and AEP callback service, but no unified alarm handling; alarm records exist in eiot_alert_record table but are not auto-populated; frontend AlarmPopup is built but disabled

## Execution process
1. Analyzed existing codebase: GbtTcpComponent, AepCallbackServiceImpl, AlertRecordDO, FireAlarmOrderServiceImpl, AlarmPopup composable
2. Defined UnifiedAlarmDTO as the central data model with sourceType, alarmType, alarmLevel, deviceId, etc.
3. Designed AlarmParseStrategyFactory pattern with TcpGbtAlarmParseStrategy and AepAlarmParseStrategy implementations
4. Specified detailed parsing rules for TCP (TLD-based) and AEP (messageType/eventType-based)
5. Designed AlarmRecordService to handle deduplication (Redis), storage (eiot_alert_record), and WebSocket push
6. Specified frontend integration points: enable useAlarmPopup in duty-screen/monitoring-center, leverage existing webSocketSenderApi
7. Proposed phased implementation plan: Stage 1 (3 days) for core parsing/storage, Stage 2 (1 day) for real-time push
