## Task description
- Core requirement: 用户反馈"仅看今日的标签每次都显示是错误的，实时刷新也是"，即处置中心（views/eiot/firewatch/alarm-order/index.vue）顶栏两个标签常驻显示、无法取消。
- Task background: 「仅看今日」由大屏跳转带入的 URL 参数 today=1 驱动（v-if="isTodayOnly && !timeRangeFilter.length"）；「实时刷新」是无条件的静态 el-tag，背后无 WebSocket 也无轮询开关，实际 30 秒轮询隐式运行。

## Execution process
1. 定位根因：today=1 挂在地址栏后页面内任何操作（改筛选、翻页、点刷新）都不会清掉它，标签常驻且无取消入口，列表被永久限制在今天；handleResetFilters 只清空筛选控件而不动 route.query，重置对今日模式无效。
2. alarm-order/index.vue 模板：给「仅看今日」el-tag 加 closable，关闭事件调 clearTodayOnly；删除「实时刷新」静态标签。
3. 新增 clearTodayOnly：从 { ...route.query } 中 delete query.today，await router.replace({ path: route.path, query }) 用 replace 而非 push（避免后退又回到今日模式），置 alarmPageNo=1 再 refreshAlarms()。
4. handleResetFilters 改造：清空各筛选 ref 后判断 if (isTodayOnly.value) { void clearTodayOnly(); return; }，否则走原 refreshAlarms()。
5. 顺序修正：clearTodayOnly 定义在调用方之后存在 TDZ 风险，整体上移到 handleResetFilters 之前。
6. 校验：node .\node_modules\vue-tsc\bin\vue-tsc.js --noEmit 过滤 alarm-order，仅剩仓库既有 TS6133 未使用变量告警，零新增错误。

## Notes
- URL query 表达的"临时视图模式"必须同时提供退出入口（closable）并让重置逻辑覆盖该参数，否则模式不可逆；用 router.replace 而非 push 重写 query，避免后退栈里残留旧模式。
- await router.replace 后再发查询，可确保依赖 route.query 的 computed（isTodayOnly）已更新，否则本次请求仍会带上旧参数。
- 不带状态、不可交互、文案与实际机制不符的装饰性标签应直接删除，不要改写文案保留。
- 【本会话补充】后续批次已给该页补 tags-view 单标签合并 + query watch 机制（见《处置中心tags-view重复标签合并为单标签》），clearTodayOnly 的刷新已由 watch 承接，与本条第 3/4 步的显式 refreshAlarms 写法相比以最新代码为准。
