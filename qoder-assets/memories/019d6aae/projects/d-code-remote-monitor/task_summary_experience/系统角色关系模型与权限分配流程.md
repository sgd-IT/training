## 一、核心数据模型（RBAC）
系统采用标准的 **用户-角色-菜单** 三级 RBAC 权限模型，涉及以下核心表：

| 表名 | 作用 |
|------|------|
| `system_role` | 角色定义（名称、标识code、类型、状态、数据范围） |
| `system_user_role` | 用户-角色关联（多对多，**带 tenant_id 且参与租户隔离**） |
| `system_role_menu` | 角色-菜单关联（多对多） |

## 二、角色类型（RoleTypeEnum）

- **`SYSTEM`(1)` — 内置角色，不可删除/修改（如超级管理员、租户管理员）
- **`CUSTOM`(2)` — 自定义角色，管理员可自由创建编辑

## 三、已配置的角色清单

| ID | 名称 | code | 类型 | 说明 |
|----|------|------|------|------|
| 1 | 超级管理员 | `super_admin` | 内置 | 全局最高权限，不允许创建同名角色 |
| 154 | 只读用户 | `reader` | 自定义 | 只读权限 |
| 161 | 远程值守员 | `remote_duty_officer` | 自定义 | 移动端远程值守场景 |
| 165 | 消控室值班员 | `fire_watcher` | 自定义 | 消防值守端操作 |
| 167 | 小程序用户 | — | 自定义 | 仅分配 query 类基础权限 |
| 其他 | 值守主管、技术负责人、业主消防安全负责人、监管角色等 | — | 自定义 | 各类业务角色 |

注：**租户管理员（tenant_admin）不是固定 ID 的单行**——它在每次创建租户时于该租户下新建一行，每个租户各有一行，主键 ID 随租户递增；跨环境引用该角色应按 code 匹配而非按 ID。super_admin、reader 等种子角色的固定 ID 结论仍然有效。

## 四、角色关系链路

```
超级管理员 (ID=1, super_admin)
  └─ 全局权限，不受租户隔离限制
  └─ 管理所有租户的角色、用户、菜单

租户管理员 (code=tenant_admin)  ← 每个租户创建时各自生成一行
  └─ 权限范围 = 租户套餐(TenantPackage)定义的菜单集合
  └─ 可在租户内创建自定义角色并分配菜单

自定义业务角色 (远程值守员/消控室值班员/值守主管/...)
  └─ 由租户管理员创建和配置
  └─ 通过 system_role_menu 关联菜单/按钮权限
  └─ 通过 system_user_role 分配给租户内用户
```

## 五、权限分配流程

1. **角色→菜单**：`PermissionService.assignRoleMenu(roleId, menuIds)` — 管理员在后台为角色勾选菜单和按钮权限
2. **用户→角色**：`PermissionService.assignUserRole(userId, roleIds)` — 管理员为用户分配一个或多个角色
3. **数据权限**：角色还包含 `dataScope` 字段，控制数据可见范围（全部/自定义部门/本部门/本部门及以下）

## 六、多租户与角色的关系（关键陷阱）

- `system_role`、`system_user_role` 均带 `tenant_id` 字段（继承自 `TenantBaseDO`），且**不在 application.yaml 的 tenant.ignore-tables 白名单里** → 运行时查询自动追加 `tenant_id = 当前登录上下文租户`。
- **后果：给归属 A 租户的用户分配 B 租户的角色等于没分配**——平台租户界面"分配角色"弹窗能查到并勾选成功（操作上下文是租户1，关联行记在租户1名下），但该用户登录自己的租户（如企业租户166）后按 `tenant_id=166` 查角色关联一条都查不到 → 角色为空 → `hasAnyPermissions` 对每个权限点都判 false → 移动端/Web 所有带 `@PreAuthorize` 的接口统一返回 403「没有该操作权限」。
- 排查此类"明明配了角色却全无权限"问题时，先核对用户的 `system_users.tenant_id` 与所分配角色的 `system_role.tenant_id` 是否一致。
- 超级管理员（role_id=1）是租户1下的种子角色行；`hasAnySuperAdmin` 按角色 code=`super_admin` 判定超管直通，因此只有归属租户1的用户能被解析到该角色。

## 七、数据可见性增强维度

除上述RBAC外，系统还引入了基于用户 `area_code` 的数据区域过滤：
- 对于系统租户（tenant_id=1）下的「监管角色」（code=monitor_role），其数据可见范围会进一步受限于用户个人资料中的 `area_code` 字段（例如 test 账号 area_code="440000" 广东省）。
- 此时，查询结果会被过滤为 `tenant_id IN (广东省内所有租户的ID列表)`，而非全局所有租户。
- 非监管角色（如小程序用户 wx_user）则无此限制，系统租户账号可查看全部数据。
