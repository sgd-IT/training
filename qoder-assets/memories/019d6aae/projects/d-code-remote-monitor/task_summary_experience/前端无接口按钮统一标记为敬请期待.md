## Task description
- Core requirement: identify all frontend buttons that have no corresponding backend API interface and uniformly display "敬请期待" to indicate their unimplemented status.
- Task background: multiple UI pages (e.g., alarm-order, alarm-screen) contain action buttons whose handlers either call non-existent endpoints or fall back to mock data without clear user indication; this leads to confusion about feature readiness.

## Execution process
1. DevelopingTag component: updated the default label text from "开发中" to "敬请期待" in src/components/DevelopingTag/index.vue to serve as a unified visual indicator.
2. alarm-order/index.vue: for the 4 buttons with completely non-existent backend controllers (联动 /eiot/firewatch/linkage/execute, 上报 /eiot/firewatch/report/create, 派单 /eiot/firewatch/workorder/create, 复盘 /eiot/firewatch/review/create), added ElMessage.info('XXX功能敬请期待') at the start of each handler and inserted <DevelopingTag mini /> into their respective template tiles.
3. alarm-order/index.vue: corrected the URLs for the '复位' and '拨打' buttons to point to the real existing endpoints (PUT /eiot/firewatch/alarm-order/reset-device?id= and POST /eiot/firewatch/alarm-order/call?id=&phone=) instead of the non-existent ones (/eiot/firewatch/device/reset and /eiot/firewatch/call/make).
4. alarm-screen/index.vue: added deviceListIsMock logic to detect when the /eiot/firewatch/dashboard/alarm-devices endpoint returns no data, and conditionally render a <DevelopingTag> badge in the device list header.
5. callcenter.api.ts: deleted the unused and non-existent hasCallRecordVoice API function.
