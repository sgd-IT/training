## Task description
- Core requirement: 给「消控室值班员」角色（system_role id=165，code=fire_watcher，tenant_id=1）分配权限，先按 PRD-09 的 L1 值守员边界收敛，再按业主现场需求开放若干项。
- Task background: 该角色原有 106 条菜单/按钮，包含设备中心整棵树、规则引擎、告警配置写操作、排班增删改等管理面能力；且缺 iot:alert:edit 导致告警确认动作 403。前端 firewatch 页面除座机管理外均无 v-hasPermi，后端 checkIn/checkOut 只校验 duty:operate 不校验本人。

## Execution process
1. 盘点现状：查 system_role / system_role_menu / system_user_role，确认 165 有 106 条授权且当前未绑定任何用户；对照 PRD-09 得出必给/可选/不给三档清单。
2. 落迁移脚本 _sql/mysql/V20260827 之后的 V20261019__fire_watcher_permission_trim.sql：第 1 段补授基础集、第 2 段按 permission IN 列表逻辑删除收回管理面、附单条回滚示例；全部按 code+tenant_id 定位角色而非写死 ID，用 NOT EXISTS 保证可重复执行。
3. 测试库执行：补 3226（iot:alert:edit）1 条；按 30 个权限串收回 79 条；剩余 28 条。
4. 业主追加开放：设备控制 iot:device:ctrl(2934) 与指令下发 iot:device:instruction:send(3189)、维保单位/计划/合同三项 query、hazard:query+hazard:create、data-center:query、duty-phone:query、call-record:query+voice。
5. 关键补丁：发现只开按钮不可用，遂一并补父级 2814 设备中心、2827 设备管理、2828 iot:device-info:query（否则设备列表为空）、隐藏路由菜单 2931 deviceDetail/:id（远程控制 tab 在详情页，缺它点设备 404）。
6. 脚本追加第 3 段（先 UPDATE 恢复 deleted=b'1' 再 INSERT），因 NOT EXISTS 只看 deleted=0，对刚被逻辑删除的行直接 INSERT 会产生重复行。
7. 验证：active 合计 48 条，无重复行，一级目录 4 个 + 页面 19 个符合预期。

## Notes
- 只勾 type=3 按钮不勾其 type=2 页面与 type=1 目录，前端菜单树不会出现入口，授权看起来"没生效"。
- 设备控制的实际入口在设备详情页远程控制 tab，必须连带给出查询权限与隐藏详情路由菜单，单给控制权限点等于不可用。
- system_role_menu.tenant_id 需与角色行所属租户一致；165 属租户 1，企业租户账号即使被分配该角色也查不到关联，表现为全量 403。
- 本脚本只在测试库执行过，生产库需单独跑；客户端要重新登录才能看到新菜单。
- 设备控制已超出 PRD 原 L1 边界（原划 L2 值守主管），系统只有 remote_operation_log 留痕、无双人复核。
