## Task description
- Core requirement: 三项连续需求 ——（1）小程序"近7日告警趋势"改为近一月，并额外体现近一月火警趋势、故障趋势；（2）对新增的趋势图交互做设计审查并按结论改代码；（3）告警中心列表改为每页 10 条 + 上拉加载更多，并把搜索从本地过滤下推为后端模糊查询。
- Task background: 趋势图在小程序首页 pages/index 与数据报表页 pages/stats 各有一处，原首页取 dashboard/statistics 内固定 7 天的 alarmTrend，stats 页取 data-center/alarm-trend?days=7；图表组件是内置 uCharts 的 qiun-data-charts。告警中心 pages/alarm-center 原一次拉 pageSize=100 并在前端做关键字本地过滤，后端 AlarmOrderPageReqVO 无关键字参数。PC 大屏 duty-screen/monitoring-center 也消费 dashboard 的 alarmTrend。

## Execution process
1. AlertRecordMapper.countByDayInRange：SQL 增加按天聚合的 fire_count/fault_count，类型口径沿用项目既有双读规则 COALESCE(alarm_kind, CAST(level AS UNSIGNED))（1=火警、2=故障），与告警类型分布同源；确认月报 FireMonthlyReportServiceImpl 只读 alarm_date/alarm_count/handle_count，加列不影响它。
2. DataCenterRespVO.AlarmTrendItem 新增 fireCount/faultCount；FireDataCenterServiceImpl 趋势补零循环填充两列。
3. 首页 pages/index/index.vue：标题改"近一月告警趋势"，数据源从 dashboard/statistics 的 alarmTrend 切到 /eiot/firewatch/data-center/alarm-trend?days=30，避免动 PC 大屏共用的 dashboard 接口；stats 页 days 由 7 改 30。两页统一渲染告警(蓝)/火警(红 #e53935)/故障(橙 #f57c00)/已处置(浅蓝)四条 area 线，已处置默认隐藏可点图例开启。
4. uCharts 细节加固：xAxis.labelCount=6 抽稀 30 天横轴标签（内部 ratio=ceil(30/5)，末点强制显示）；因 fillSeries 只对未带 color 的系列按数组顺序分配 opts.color，隐藏某条线会让剩余线换色与图例不符，故在 defs 中给每个 series 显式绑定 color。
5. frontend-interaction-design skill 审查（模式 B）产出 P1/P2 报告并按用户要求落地：图例项加 padding+min-height 扩大可点区并加 hover-class 按压反馈；toggleTrend 加"仅剩一条时拒绝关闭 + uni.showToast('至少保留一条趋势')"保底；故障线改 lineType:'dash'+dashLength:8（uCharts drawAreaDataPoints 在 addLine=true 时用 eachSeries.lineType 走 setLineDash），图例故障项换成虚线小横杠；隐藏态文字加删除线；首页补 v-if="trendCategories.length" 与 .chart-empty"暂无数据"空态；.text-action 加 padding 扩可点区。
6. 告警中心 pages/alarm-center/index.vue：pageSize 100→10，新增 loadMore + 页面级 onReachBottom 翻页追加；列表容器由无固定高度的 scroll-view 换成普通 view（原 scroll-view 实际不滚动，滚的是页面本身，必须用页面级触底事件）；底部提示动态化"上拉加载更多/加载中…/没有更多了"；切换类型或状态筛选时重置第 1 页并 uni.pageScrollTo 回顶；追加前用 Set 按 id 去重防实时新告警插队造成翻页重复；单页失败保留已有列表不清空。
7. 后端补模糊搜索：AlarmOrderPageReqVO 新增可选 keyword；FireAlarmOrderServiceImpl.doPageFromAlertRecord 用 wrapper.and 组内 OR 匹配 name like / details like / device_id IN (SELECT id FROM eiot_device_info WHERE name LIKE ?)，并把 ALERT-123 或纯数字归一成 id 等值命中（parseAlarmNo），keyword 为空不进条件。前端删除 filteredList 本地过滤 computed，改为输入不请求、点"筛选"或键盘 confirm 才提交 searchKeyword，翻页携带同一 keyword，空态区分"没有匹配的告警/暂无告警"，占位符改"搜索编号/位置/设备名称"。
8. 验证：mvn -o -pl module-eiot/module-eiot-biz -am compile 两次通过；MySQL MCP 实测新趋势 SQL（test 有火警数据、近30天 fault 为 0 属数据事实，全库 kind=2 有 1664 条但集中在 8 月前）与搜索 SQL（"烟感" test 命中 100 条/prod 命中 33 条，约 210ms）；prod 趋势显示火警/故障与总量同量级，判定三条线共轴可读、无需双 Y 轴；三个 .vue 的 script 段提取为 _temp/*.mjs 后 node --check 全部 exit 0。

## Notes
- 首页趋势若继续复用 dashboard/statistics 会牵动 PC 大屏（duty-screen/monitoring-center 均读 statistics.alarmTrend），因此选择让小程序改调 data-center 同源接口，后端 dashboard 保持不动。
- 工程无 package.json（HBuilderX 工程），不能用 npm 起预览，效果只能在 HBuilderX 运行到微信开发者工具查看；qiun-data-charts 在 H5/APP 分支走 ECharts，series 上的 color 与 lineType 不被识别，虚线与锁色只在小程序端生效。
- alarm-center 页面写了 onPullDownRefresh 但 pages.json 未开 enablePullDownRefresh，下拉刷新实际不触发，本轮未动。
- PowerShell 下 mvn 传 -Dmaven.test.skip=true 会被拆参报"Unknown lifecycle phase"，去掉该参数只留 -DskipTests 即可。
- 搜索关键字含 %/_ 时 MyBatis-Plus 的 like 不做转义，会成为通配符；本轮按现有口径接受，未额外转义。
