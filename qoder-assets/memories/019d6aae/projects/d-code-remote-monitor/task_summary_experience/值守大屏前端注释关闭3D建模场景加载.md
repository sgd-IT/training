## Task description
- Core requirement: 用户要求"注释掉前端3d建模加载"，即临时停用三维场景的加载行为，改动以注释形式保留、便于后续恢复。
- Task background: 前端 anwei-fire-remote-monitor-vue 中唯一的3D建模加载入口在值守大屏 duty-screen/index.vue，由 SceneHost.vue 组件通过 iframe 挂载两套第三方交付产物（park=smart-park 园区三维场景、city=dongguan-map 东莞市三维地图），宿主侧还有 dongguanMapRef 视图控制调用与一组场景事件回调。

## Execution process
1. 定位：全仓 Grep `three|GLTFLoader|\.glb|SceneHost|smart-park|dongguan-map` 确认 src 下无直接 Three.js 导入，3D 加载只集中在 duty-screen 的 SceneHost 链路（public/park/v007/.../prototype.html 是独立原型页，不在改造范围）。
2. duty-screen/index.vue 模板第 5-17 行：整块注释 `<SceneHost>` 元素（含 ref="dongguanMapRef" 与各 @事件绑定），统一标记 `[已注释] 3D建模加载暂时关闭`。
3. 同文件脚本层同步注释三处：`import SceneHost from './components/SceneHost.vue'`、`const dongguanMapRef = ref(...)` 声明、handleViewCommand 内 `dongguanMapRef.value?.resetView()/zoomIn()/zoomOut()` 三个调用。
4. 顺带核查：另一处 `document.querySelector<HTMLIFrameElement>('.scene-host__frame')` 因 SceneHost 未渲染只会取到 null，原代码已有 `if (!frame) return` 兜底，无需改动。
5. 验证：Grep 复查残留 dongguanMapRef 引用全部位于注释行内；GetProblems 复跑后类型错误归零，仅剩 Warning。

## Notes
- Vue SFC 中被 HTML 注释包住的模板节点仍会被语言服务解析出 `ref="..."` 并报"找不到名称"类错误，属误报；判真实状态应以复跑 GetProblems 的结果为准，不要据此回滚或继续加守卫。
- 注释掉 `<SceneHost>` 后，其绑定的场景回调函数（handlePropertyPointsApplied、handlePropertyLabelsApplied、handleScenePointClick、handleSceneBack、handleSceneError）全部变为"已声明但未使用"Warning，这是预期结果：恢复3D加载时会重新用到，保留不删。
- 关闭后大屏不再有三维场景与场景内点位交互，视图放大/缩小/复位按钮成为空操作（调用已被注释），页面依赖 StaticSceneFallback 之外的静态背景呈现。
