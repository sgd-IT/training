值守大屏 duty-screen「稍后处置」（AlarmPopupDialog 左键）抑制口径：2026-10-16 用户拍板变更为状态驱动——fetchRecentAlerts 轮询回捞的一级告警按 a.handleStatus !== 1 过滤；凡落库为稍后处置（handle_status=1）的告警，任何页面、任何刷新、任何屏幕都不再进全屏弹窗，只在实时告警列表/待处理计数里可见，直到被去处置（2）或已处置（3）。defer 落库失败时状态停留在 0，该告警照常 60 秒周期重弹，防漏警由落库状态天然保证。旧的页面内存态 deferredAlertIds 方案（点一次静默一次、刷新恢复提醒）已废弃：其实现先在 10-15 的 caff3ff 提交中随工作区改动被移除，10-16 明确不恢复。组件内 isHeavyRepeatDue 机制未动，仅对未被稍后处置的一级告警生效。范围仅 duty-screen；monitoring-center 左键为「标记误报」、通知匣（二三级）均不受影响。实现位置：duty-screen/index.vue 的 fetchRecentAlerts 一级过滤条件与 onHandleLater 上方注释。
