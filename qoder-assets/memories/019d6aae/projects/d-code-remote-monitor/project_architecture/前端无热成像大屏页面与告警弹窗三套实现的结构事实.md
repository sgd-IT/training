消防远程监控前端（anwei-fire-remote-monitor-vue）告警弹窗与实时告警列表结构事实（2026-09-28 经全仓 Grep/Read 核实；2026-10-12 复核仍成立；2026-10-15 ws拉流改造再次核实引用链；后续会话核实 duty-screen 实时告警列表滚动口径）：

1. 项目内不存在名为"热成像大屏"的页面或文档；"热成像"仅是报警类型（alarmType=2 热成像事件报警）与摄像头类型（type=3）。用户口中的"热成像大屏推送的弹窗"实际指既有组件 src/views/eiot/firewatch/alarm-popup/index.vue。firewatch 下真实大屏页有 large-screen（安为智慧消防监控平台）、alarm-screen（安为智慧消防值守平台）、duty-screen（大屏值守台）、device-screen（设备控制室）、video-surveillance（视频监控）。

2. alarm-popup/index.vue 是白底卡片形态：顶栏「类型名 · 报警」+级别标签+已持续时长计时(HH:MM:SS)+队列；左栏视频区+告警图片缩略图；右栏位置/设备/时间/级别/描述信息列；底部备注快捷标签（误报/已派保安/现场核实）+输入框+「稍后处置/立即处置」。它目前仅被 duty-screen/index.vue 以 AlarmPopupPage 形式引用，且只作为点击告警列表项时的"详情弹窗"（viewAlarm → alarmPopupPageVisible），不是推送弹窗。

3. duty-screen 与 monitoring-center 各自另有一套页面内实现的"实时告警弹窗"（WS 推送驱动 + alertQueue 队列 + 倒计时自动关闭 + 语音播报），界面是深色卡片：抓拍图 + 单位/设备/位置/时间/详情 + 稍后处置/去处置。即同一页面存在两套外观与交互不同的告警弹窗，改造时须先确认改的是哪一套。

4. 上述第 3 点的内联弹窗结构在两文件中高度同款，可作互相定位模板：模板顺序为 header → alarm-popup-body（内含若干 alarm-info-row，末行为"📝 详情"）→ 底栏注释 `<!-- 底栏 -->` + alarm-popup-footer；脚本弹窗状态集中在 popupVisible/popupAlarm/popupCountdown/alertShownIds 一组，常量 POPUP_AUTO_HIDE_SECONDS 之后即为可插入位；样式追加在文件末尾 `</style>` 之前。向模板插入几十行会使同文件 script/style 行号整体偏移，先前 grep 的行号随即失效，必须重新定位。

5. 该内联弹窗自 2026-10-12 起在 body 与底栏之间多了「辅助判断」区块（assist-section，演示数据版，未绑点击事件），因此用户说"当前使用的报警弹窗"时通常指这套内联弹窗而非 alarm-popup 组件。

6. 3D 建模（三维场景）加载在前端 src 目录下只有 duty-screen 一个入口：由 duty-screen/components/SceneHost.vue 以 iframe 承载，配套 useSceneHost.ts / scene-url.ts / scene-types.ts / scene-protocol.ts / StaticSceneFallback.vue；src 内不存在任何 Three.js 直接 import 或 GLTFLoader 调用（Three.js 代码只出现在 public/ 下的第三方交付产物与 public/park/v007/v007-r001/assets/floors/prototype.html 独立原型页里）。因此停用三维加载只需在 index.vue 注释四处：模板中的 `<SceneHost>` 块、SceneHost 的 import、dongguanMapRef 声明、handleViewCommand 内三个 dongguanMapRef 视图控制调用，子组件文件本身无需改动。两处相关兜底事实：querySelector `.scene-host__frame` 取不到元素时已有 return 守卫；SceneHost 卸载后其事件回调（handleScenePointClick / handleSceneBack / handleSceneError / handlePropertyPointsApplied / handleLabelsApplied 等）全部变为未使用 Warning 而非错误。

7. 「查看视频」弹窗链路引用关系（2026-10-15 ws 拉流改造实测）：公共组件 AlarmPopupDialog.vue 被 duty-screen/index.vue 与 monitoring-center/index.vue 两屏各一处引用；而视频弹层 AlarmVideoDialog.vue 仅被 AlarmPopupDialog.vue 单点引用（openVideoDialog → AlarmVideoDialog，传 cameras: AlarmAssistCamera[]）。因此改造 AlarmVideoDialog 一处即可同时覆盖两屏的"查看视频"路径，无需分别动两个大屏页；AlarmAssistCamera 后端 VO（AlarmAssistCameraVO）仅含 cameraId/name/status，不含 deviceId/channelId/quality，ws 播放所需字段需另行补全。

8. duty-screen 实时告警列表的滚动能力完全来自公共类 .card-content 的 overflow-y: auto（滚动条已隐藏）：全仓 Grep 证实 .alarm-scroll / .alarm-inner 在 src 下没有任何独立样式定义，只是模板包裹节点。原先每 50ms 递增 scrollTop 的 startAlarmAutoScroll（连同 scrollPaused / alarmScrollRef / alarmAutoScrollTimer 与模板上的 ref、mouseenter/mouseleave 绑定）已全部移除，列表现为纯手动滚轮翻页；因此若要再改列表滚动行为，只需处理 .card-content 层级，不要在 .alarm-scroll 上加样式。另外 large-screen 的实时告警列表本无自动滚动，dashboard 虽有 alarm-scroll-container 引用但未启用，"大屏实时告警"默认指 duty-screen。
