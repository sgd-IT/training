消防远程值守生产环境（anwei-fire-remote-monitor）扩容评估的已核验事实：

1. **单实例 + 1GB 内存**：deploy/docker-compose.yml 里 server 只有一个容器副本，mem_limit: 1g，需承载 15 个协议组件 + Quartz。
2. **连接池口径在 deploy/config/server/application-prod.yaml**（不是 server/src/main/resources，那里 grep 不到 hikari/maximum-pool-size）：键为 max-active: 20、max-wait: 600000（600 秒）。池满时请求不快速失败而是挂起最长 10 分钟，是访问日志出现数百秒乃至 8034 秒 duration 的直接机制；大屏聚合统计与告警入库/推送共用同一连接池。
3. **nginx 为 HTTP/1.1**：deploy/config/frontend/nginx.conf 写作 listen 8888 ssl 且无 http2，浏览器同域 6 并发连接上限无法绕过，多块大屏轮询互相排队。
4. **智能空开指令走外部程序拉取，非浏览器轮询**：RemoteConsoleController 的 GET /valve/command/{deviceId}（"拉取并消费智能空开控制命令"）标注 @PermitAll，并在 platform.tenant.ignore-urls 忽略租户校验，由外部空开控制服务 ValveCommandTask 轮询消费。其访问日志特征为 user_id=0、user_type=2、UA 自报 Chrome/65、每小时恒定约 447 次、只命中该接口与 /app-api/open/camera-alert/report —— 判"某高频流量是否来自前端页面"可用这组特征区分。
5. **大屏数据通道三层叠加**：duty-screen/index.vue 同时开 useWebSocket(/infra/ws) + setInterval(fetchRecentAlerts, 10000) 调 /alert/recentUnprocessedAlerts + setInterval(loadData, 30000)（内含 dashboard/statistics、dashboard/realtime-alarms、property/page、duty-schedule/current-duty 四个请求），即 WS 只做新告警提示与今日警情卡刷新，列表数据仍靠 10 秒轮询兜底；alarm-screen 无任何 WebSocket 代码，纯 useVisiblePolling(loadData, 30000)。
