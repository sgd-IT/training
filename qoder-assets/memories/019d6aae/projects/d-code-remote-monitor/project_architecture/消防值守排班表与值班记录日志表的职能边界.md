消防值守（firewatch）值班域两张表的职能边界（本轮经前端页面与后端 Service 双向核实）：

- fire_duty_schedule（duty/index.vue）= 排班计划+考勤：一行代表某单位某天某班次由谁值班，含签到/签退/换班动作，数据来源人工排班。
- fire_duty_record（duty-record/index.vue）= 值班事件日志：一行代表值班期间发生的一件事，含 record_time、record_type、title、content、关联设备、正常/异常标记；通过 scheduleId 与排班关联，但不是排班的执行结果视图，二者字段几乎不重叠，命名相似易被误判为重复功能。
- 记录的生成方式不对称：后端 FireDutyRecordServiceImpl 仅有 createPatrolRecord / createHandoverRecord 两个自动写入口（巡查、交接班触发），其余 record_type（如 alarm 告警处理）只能靠页面手工"新增记录"补录——因此 patrol/alarm/handover 三类与巡检任务、火警处置、换班动作构成两套并行台账，存在重复录入风险。
- fire_duty_record 表已于本轮在开发库补建（DDL 对齐 FireDutyRecordDO），生产库仍缺；FireWatchDutyRecord 路由已在 remaining.ts 以 hidden:true 静态注册，仅作 duty 页跳转入口，不进侧边菜单。

适用边界：firewatch 值班域取数与页面改造；不适用：fire_handover_record 交接班独立表的统计口径。
