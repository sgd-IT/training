设备详情页（views/eiot/deviceinfo/detail.vue，接口 GET /eiot/device/get?id=）的取数结构事实（经读码核实）：

1. 主表为 eiot_device_info（EiotDeviceInfoDO），Controller 内 deviceInfoService.getDevice(id) 后直接 BeanUtils.toBean(DeviceInfoRespVO)，是单表直映射，无服务层聚合；页面大部分列一一对应物理列：别名=name、序列号=serial_no、设备唯一标识=dn、设备密钥=secret、固件版本=firm_version、型号=model、品牌=brand_code、协议=api_version、类型=device_type、是否显示=visible、在线状态=state、创建/激活时间=create_time/active_time。

2. 页面上两个"看起来是一列"的字段实际跨表：
   - productKey 显示格式为「产品名(product_key)」，产品名不在设备表，需 LEFT JOIN eiot_product ON product_key（ProductDO），复刻写法 CONCAT(p.name, '(', d.product_key, ')')。
   - 设备地址有两份口径：d.addr 是后端写入的空间快照串，d.space_id 才是实时指针，实时地址需 LEFT JOIN eiot_space（FireSpaceDO）按 building/floor/area/position 四段拼 CONCAT_WS('/', ...)；space_id 为空时页面退化为占位文案"请选择空间（楼栋/楼层/区域/详细位置）"，此时 addr 也为空，属正常数据状态而非查询写错。

3. state 为数值枚举：0=离线、1=在线、2=未激活、3=禁用，前端绿色"在线"对应 1。

4. 时间字段存在前后端口径差异：库列 create_time/active_time 为 datetime，页面展示的是毫秒时间戳，说明 VO/前端做过 epochMilli 转换，直接用 SQL 查到的 datetime 值与页面数字不一致不代表数据错误。

5. 所有关联必须带 deleted = 0 条件（含 join 侧的 p.deleted/s.deleted），否则逻辑删除的产品或空间会污染结果行。

6. "设备标签"不在 eiot_device_info 上，属独立关联表，单表查询覆盖不到。
