智慧消防远程监控系统在"传输安全"与"告警时限类调度"两处存在结构性空白（2026-10 对标盘点实测）：

1. **协议接入层无任何加密与设备身份认证**：对 `module-eiot/iot-components` 全量 grep `SslContext|TLS|SslHandler|Certificate|clientCert` 返回 0 匹配。GBT26875 国标 TCP、四信 FF 变体、私有 UDP、大华通用协议各组件均为明文 socket 接入，不存在一机一密/设备证书/双向认证。结论口径：边缘网关"协议归一化"已完成（组件解析后统一走物模型 PropertyReport 上报，平台层只见标准属性），但传输安全底线整层未实施——涉及等保/密评的交付场景属硬伤，纯内网园区可缓。

2. **告警超时升级链只有 PRD 没有代码**：`PRD-01-火警监测与处置.md` 已定义完整升级链（30s 复核倒计时、超时升级、三级升级自动通知 119，BR-F1.6/F1.7/F1.8），但实现侧缺失：`FirewatchScheduledTask` 仅含巡检超期（每天 00:05）与维修工单催办（每天 9:00）两类调度，无告警时限计时器；grep `119|监管|regulator|escalat|timeout.*upgrade` 在 module-eiot-biz 内除 IP 字面量与 ChannelTemplate VO 的 Schema 描述外零命中。短信能力本身存在于 alertconfig 域（AlertConfigSendSmsBatchReqVO 支持批量发送），属"未接上升级链"而非"需从零建设"。

3. **误报预防侧只有骨架**：值守大屏与监控中心的辅助判断区（烟+温+视频+水压多信号关联）当前为演示数据，后端 `alarm-assist` 接口未就绪，duty-screen/index.vue 内有明确注释标注。人工标记误报（order_status=false_alarm）已可用，即"误报处置有、误报抑制无"。

4. **远程控制能力超前于"只读采集"口径**：存在 remote-console 前端页面与对应后端 remote 接口域，可对主机下发操作，比"只读采集、不改动原系统联动逻辑"的通行合规口径更激进。评估"远程操作控制单人值守"类属地审查条件时需单独说明该能力边界。
