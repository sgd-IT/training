ICC 流媒体的上游"设备→NVR→流媒体"拉流在多个下游出口协议(RTSP/HLS/FLV)之间共享，RTSP 与 HLS 只是同一路上游流的不同封装出口。因此任一协议端(PC 的 WSPlayer/RTSP)拉流会使其他协议端(小程序 HLS)同时变热，跨协议提速已实测成立(热流下小程序 3-5s 起播)。相反，一段时间无人观看后 ICC 释放上游流，下一个客户端无论何种协议都要等约 15-30s 重新建流——这是小程序 HLS 起播 30-40s 的结构性根因，与切片时长和客户端缓冲无关。该机制决定了性能优化的正确切入口是让上游流保持活跃(预热/保活)，而非调整客户端或分片参数。ICC 流的空闲释放超时具体值尚未实测标定。
