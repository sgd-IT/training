duty-screen/index.vue 的数据装载结构：主链路是 loadData() 调 GET /eiot/firewatch/dashboard/statistics，一次返回 deviceStatus、todayAlarm、realtimeAlarms、alarmTrend、currentDutyList、properties；realtime-alarms、property/page、duty-schedule/current-duty 三个接口只在主接口失败或对应列表为空时才作为兜底发起（判断条件是 if (!propertyList.value.length) / if (!dutyList.value.length)）。statistics 响应对告警列表和物业列表同样是"有值才覆盖"（if (d.xxx?.length)）。地图点位是另一条独立链路：usePropertyMapData 调 /eiot/firewatch/property/list，自带 30 秒轮询，且只在 token 或登录缓存 tenantId 变化时自动作废快照。页面另有 setInterval(loadData, 60000) 定时刷新——值守大屏的主轮询周期是 60 秒，不是 30 秒；30 秒只出现在地图点位链路与 monitoring-center / alarm-screen 两个页面，勿混用（后端缓存新鲜期须按最慢的 60 秒周期取值才能盖住一整轮）。因此在页面上切换"要查看的租户"时必须：发请求前先清空 propertyList、enterpriseInfo、dutyList、alarmList，并手动调用 composable 暴露的 clearForSessionChange() + refresh()，否则兜底分支不会重新请求、新租户数据为空时画面会残留上一个租户的旧数字。

## Notes
- 补充宿主层与三维场景的分工事实（本轮经读产物核实）：duty-screen 的三维展示由 SceneHost.vue 以 v-if 挂载 iframe 承载，切场景时 useSceneHost.ts 的 mountScene/destroyScene 会销毁重建 iframe，两个 WebGL 上下文不会并存——即上述"旧数据残留"风险只存在于宿主的 Vue 数据层，渲染层不存在双场景并存的显存泄漏问题。排查大屏卡顿/GPU 占用时应先区分：数据装载与轮询在宿主 index.vue，三维渲染参数在 iframe 内的第三方交付包里（源码不在本仓库），具体档位与生效路径见 project_architecture「duty-screen两套3D场景交付包的渲染参数与quality档位在宿主侧的真实生效路径」。
