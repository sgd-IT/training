消防告警字段语义改造（读侧双读→写侧三写→前端收敛）的前后端静态验证命令链与环境约束：

- 后端：必须切到 JDK 21 再 mvn clean compile，默认 JDK 17 报"目标发行版"错误；以真编译输出为准（如 Compiling 542 文件 BUILD SUCCESS），不接受 IDE 增量提示。
- 前端：vue-tsc --noEmit 全量校验。本仓库存在一批既有历史类型错误，无法要求"零错误"，须用基线差分判定本次改动是否引入新错：
  Step 1: 改前把全量 vue-tsc 输出重定向存为基线日志文件；
  Step 2: 改后重跑同一命令生成新日志，先按被改文件统计匹配行数与基线对比（单文件条数持平是第一道筛查）；
  Step 3: 若所有被改文件条数持平但总行数仍不等于基线，不可放行——用 Compare-Object 对两份日志逐行 diff，分别列出"只在旧"与"只在新"的行；新增注释/代码会使后续错误行号整体位移，位移行在 diff 中成对出现可解释并忽略，"只在新"且无同内容"只在旧"配对的行才是真新增错误（只看单文件条数会漏检未被统计覆盖的第三个文件里的新增错误）；
  Step 4: 回到源码核实每条真新增错误行的成因再修复，不能凭错误码猜测是本次引入还是其他来源（如用户手敲覆盖）。
- 验收口径：本次改动文件 0 新增错误、总行数回基线才算通过。
