anwei-fire-remote-monitor-vue（Vue3 + Element Plus 2.9.1）的主题色现状与约束：

- 项目**没有**对 Element Plus 主色做任何全局覆盖：src/styles/index.scss、var.css、index.html 中均检索不到 --el-color-primary 定义，运行时取 Element Plus 默认蓝 #409eff；app store / Setting 面板可在运行时改写 documentElement 上的该变量。
- 存在**页面级局部覆盖**的先例：src/views/eiot/firewatch/alarm-order/index.vue 在该页根节点把 --el-color-primary 全套明暗变体覆盖为青绿 #199b96。因此"某页看起来不是蓝色"不代表全局主题变了，判断主题色须区分全局值与该页局部值。
- 由此产生的写法约束：单页做视觉重构时强调色应写 var(--el-color-primary)（及 --el-color-primary-dark-2 / light-9 等派生变量），而非硬编码新品牌色；ECharts 等 JS 侧配色通过 getComputedStyle(document.documentElement).getPropertyValue('--el-color-primary').trim() 读取并给回退值，注意该读取只在模块加载时执行一次，运行时改主题不会即时反映到图表。
- 弹层例外：dialog/drawer/MessageBox 被 teleport 到 body，页面级局部 primary 覆盖对其内部不生效，需给弹层挂专用类并用非 scoped 样式块补一份同套变量。
- 焦点态另有独立机制：src/styles/index.scss 含全站 :focus-visible { outline: 2px solid var(--el-color-primary); outline-offset: 2px } 兜底规则，因 primary 未被全局覆盖而表现为蓝色描边，且 outline-offset 使描边与控件之间留一圈白隙（区别于 border 紧贴内容盒）。element-plus/theme-chalk/el-input.css 完全没有 outline 声明，.el-input__inner 未做 outline:none 重置，原生 input 焦点环会透出并与组件库 is-focus 边框叠成双层框；文本输入元素在 Chrome 中鼠标点击同样命中 :focus-visible。**已落地的修法（本轮 SearchReplace + sass 编译验证）**：规则写成 :focus-visible:not(input):not(textarea)，排除项只需 input/textarea 两类原生标签即可——el-select / el-date-picker / el-input-number 内部都是原生 input，一并被排除，无需再追加 :not(.el-input__inner)。同文件 @media (forced-colors: active) 内的 :focus-visible { outline: 2px solid } 有意保留不排除，高对比模式下系统色描边是唯一可见焦点提示。改动后 Element 自身 .el-input__wrapper.is-focus 的贴边 1px 蓝框仍在，属正常聚焦反馈。移动端仓库 anwei-fire-remote-monitor-mobile 无任何 focus-visible / outline:2px 规则，手机端同类现象属宿主浏览器或小程序原生样式。
- 校验 index.scss 这类**顶层 scss 入口文件**（内含 @use/@import 第三方包）的写法：`node node_modules\sass\sass.js --no-source-map --load-path=node_modules src\styles\index.scss _temp_out.css`，缺 --load-path=node_modules 会因解析不到 element-plus 包路径而报错；产物用 Select-String 反查选择器确认规则正确生成后删除临时文件。
