消防值守各 Excel 导入功能（排班/巡检/隐患）的"下载模板"不是仓库里的静态文件：全仓检索无任何 .xls/.xlsx 模板产物，模板在下载时由 Controller 的 importTemplate 接口按导入数据模型类（如 ImportScheduleDataModel）的 @ExcelProperty 注解实时写出。

结构性后果：
- 要改模板的表头、列顺序或示例行，唯一落点是改 importTemplate 的示例构造代码与数据模型类的 @ExcelProperty，不存在可直接编辑的模板文件；用户此前下载到本地的旧文件不会被任何改动更新。
- 示例行日期必须动态生成（LocalDate.now().plusDays(1/2/3)）。一旦写死具体日期，随着"导入只收明天及以后"的行校验生效，官方模板自身会随时间过期而导不进去。
- 列结构（@ExcelProperty 定义）与示例内容是两层：只改示例内容不动数据模型类时，旧模板文件仍能正常导入，兼容性不受影响。
- 模板示例应走同一套业务口径（如全天班隔日换人演示张三→李四→张三），并在班次列同时示范中文名称与编码两种写法，让示例文件本身即是合法输入样例。

## Notes
- 【"仓库内无静态模板"的结论需复核】用户表述"线上的模板我用的是，本项目内应该也有的"，即用户认为其线上在用的模板在项目仓库内也存在一份。与前文"全仓检索无任何 .xls/.xlsx 模板产物"存在矛盾——可能原因：此前检索范围受限（二进制文档被 .gitignore 排除、目录未覆盖、或仅按扩展名精确匹配而漏掉其他格式）。下次涉及模板改动或核对时，应先在仓库内做一轮更宽的文件检索（含 resources/docs/template 等目录与被忽略路径）确认是否确有静态模板文件，再决定改动落点；若确证存在静态模板，则本记忆"唯一落点是改 importTemplate 代码"的结论需相应修正。
