## Usage Scenario
调用 work-log skill 产出总结、日报/周报、已有记录内容或面试题库时，决定以何种形式交付给用户。

## Usage Method
交付形态：用户提出"输出/文字输出/给我文字版"类要求时，默认读取目标文件后以代码块原样贴出全文，不做转述式概括；也不把一次性交付要求顺势升级为新的 skill 规范建议（例外见 Notes）。

标题层级与排版（2026-10-19 定版，现行唯一口径）：文件首行用 H1（# 履历总表 / # 项目名 / # 01-Java基础），H1 仅留给文件级标题；记录用 H2（`## <模块> · <日期>`），标题下跟 `> 项目：` 引用行；字段小标题用 H3（`### 【类型】`）单独成行突出；层级不跳级，小标题与正文之间、各字段块之间不留空行。

出题类交付（面试八股等）：用户说"你出文字版的给我，我做好发答案给你"时，只在对话里给题目清单与"答案至少要覆盖的点"，不给答案、不落盘；用户按编号回贴后再逐题写入对应 README 的 `## <题面>` 下，写不出的标【待补】。用户表示时间不够时应收敛题量而非降低筛选标准，并保留"只有 20 分钟就答这 N 题"的最低配档。

## Notes
- 把"文字输出"理解成"用文字转述内容"会导致用户二次纠正，必须按"原文直接贴出在对话里"执行
- 批量调整存量文件标题层级时只 grep 一二级会漏掉更深层级，必须先读全文确认完整层级再逐档顺延
- 用户可能分多轮逐步追加格式要求，每轮按最新要求重排并纯输出即可
- 旧规范"不使用 H1、最高从 H2 开始"已作废，仅作历史留痕，勿再按它执行
- "不顺势提议写入 skill 规范"仅适用于用户临时提出的交付格式要求；发现 skill 规则本身有真实缺口（如模式 B 缺按 %an 过滤提交归属）仍应在交付后单独提一句由用户拍板
- 用户说"存档"时写入 02-专题/ 并回读校验，对话里给文件链接与结构说明即可，无需整篇重贴
