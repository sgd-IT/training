消防远程值守的镜像发布是"构建机 + 服务器"两机分工，凭据落在不同机器上：

构建机（Windows 开发机）：负责生成 deploy/config/frontend/sba.htpasswd 并运行 deploy/build-push.ps1 打镜像推 Harbor。该 htpasswd 文件被 build-push.ps1 分发进前端镜像，服务器上不存在也不需要这个文件，服务器上永远不用跑 Windows 侧命令。

服务器（Linux 命令行）：只跑 ./pull-images.sh 与 docker compose up -d server / nginx-frontend，不在服务器上生成任何凭据。

生成 htpasswd 的命令选 node 而非 openssl：本机 where.exe openssl 查不到 openssl，而 node 在 D:\nodejs\node.exe；且该 node -e 命令外层用双引号包裹内层单引号、字符串里的 \n 由 JS 解析，因此 cmd、PowerShell、bash 三种 shell 下都能原样执行，构建机换成 Linux 也无需改写命令。同理不建议用 PowerShell 的 [IO.File]::WriteAllText，PS 5.1 下易写成 UTF-16 破坏文件。
