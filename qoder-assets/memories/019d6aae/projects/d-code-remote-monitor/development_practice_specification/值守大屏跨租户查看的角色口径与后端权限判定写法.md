值守大屏租户切换功能的最终角色口径与后端判定写法：仅 super_admin 可见租户下拉并可在全量视角与各租户间切换；tenant_admin 与其余角色（含 monitor_role、企业普通用户）只显示当前登录租户名称文本、无下拉；tenantId 查询参数只对 super_admin 生效，其余角色即使传参也必须忽略并按自身租户执行。项目支撑事实：前端 userStore.getRoles 存放角色 code（AuthPermissionInfoRespVO.roles 由 AuthConvert 用 RoleDO::getCode 转换）；后端严格白名单应使用 SecurityFrameworkService.hasRole(code)（框架 bean 名为 ss，PermissionServiceImpl.hasAnyRoles 是纯 code 匹配、没有超管直通兜底，这与 hasAnyPermissions 存在超管兜底的行为不同）；控制器层先例是 FirePropertyController 的 /property/list-all，用 "@ss.hasPermission(...) and @ss.hasRole('super_admin')" 加 @TenantIgnore 标注为"值守端大屏专用，仅系统管理员可访问"；tenant_admin 由创建租户时自动生成，权限等于租户套餐菜单集合。判定登录用户所属租户只能用 UserTenantResolver.resolveLoginUserTenantId()（读 system_users.tenant_id，不受请求 tenant-id header 影响），不能用 TenantContextHolder.getTenantId()——后者在 TenantUtils.execute(目标租户) 内部会返回被切换后的上下文租户而非登录用户租户。
