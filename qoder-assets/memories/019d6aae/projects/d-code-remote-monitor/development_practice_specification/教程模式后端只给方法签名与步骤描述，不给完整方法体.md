在 hand-typing-training 的文字教程（跟敲）模式下，后端改动的交付形态是"文字说明 + 方法签名"，不给可直接粘贴的完整方法体，也不给完整 if/return 控制流代码块。

依据：SKILL.md 红线2"纯后端业务逻辑以文字为主"与模式选择表"后端：文字 + 方法签名"；5.4 新手档三件套里的"可直接抄入的完整小块"只适用于前端块。学员画像本身就是"前端几乎零基础需可抄改小块，后端能看懂、自己写需参考"——把前端口径套到后端等于代写，学员已明确表达反感。

落地方式：给文件路径 + 行号锚点、方法签名、按步骤的动作描述（用哪个 API、传什么参数、结果存到哪个变量、拿去干什么）、单独成行标"坑："；实现体留给学员。仅当学员明确说"你帮我写"时才给完整实现，并说明关键决策点。前端与后端两种端不可混用同一交付口径。
