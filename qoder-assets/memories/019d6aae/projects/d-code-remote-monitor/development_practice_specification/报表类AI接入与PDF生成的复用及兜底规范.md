在需要大模型生成报表文本（如运行报告的"本月结论 / 问题与建议 / 下月工作计划"）时，本仓库遵循以下实践约束：

1. 提示词写死：system prompt 与输出格式要求作为常量固定在业务服务代码中（如 AI_SYSTEM_PROMPT），只有数据摘要按当期统计动态拼装；不允许把提示词做成可配置项或运行时拼接结构。
2. 优先复用系统既有能力而非引入新依赖：PDF 生成沿用仓库已有的 PDFBox + PdfReportUtils 方案，不引入 openhtmltopdf / JasperReports / poi-tl / 前端 jsPDF-html2canvas-print-js 等新引擎；用户表述"想用现成的"实际含义是"用系统里已有的实现"，需先盘点 pom 与部署形态（server 容器内存限 1G、纯 Java 服务）再确认，不可按字面直接加依赖。
3. AI 不可用不得阻断主流程：调用失败/超时/返回空时按段落回退（结论显示占位符、分析章节回退为留白手写区），保证报告始终可导出；当期数据为空（如告警数为 0）时直接跳过 AI 调用。
4. 改动范围最小化：新渲染能力只作用于目标报表，共享工具类采用新增方法而非改造旧方法，避免影响同工具类的其他调用方。

## Notes
- 补充（2026-10 月/季/年周期泛化实测）：第 1 条的"写死"约束不排斥**周期词模板注入**——三套 system prompt 仍以代码常量数组形式存在，按 periodType 选择其一并注入"本月/本季/本年度""下月/下季/来年"等术语，AI 输出的分段标记须同步跟随周期切换，否则解析切分会失配。
- 补充：第 2 条的复用性已二次验证——ReportPdfWriter 的绘制原语（gridRow/sectionRow/captionRow/gridTable/chartCell/signatureRow）与"月"零耦合，换周期只需参数化文案层，渲染层无需任何改动。
