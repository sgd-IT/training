消防值守（firewatch）模块菜单结构（测试库 system_menu 实测）：

- 父菜单 ID 3000，名称「消防值守」，type=1（目录），路径 '/eiot/firewatch'；同级相关目录还有 2852「告警中心」、3167「视频监控」、2814「设备中心」、2845「规则引擎」。
- 层级口径：type=1 目录 → type=2 页面（有 path + component，permission 一般填该页 query 串）→ type=3 按钮（只有 permission）。给角色授权时三层都要勾全，只勾按钮则前端菜单树不出现入口。
- 3000 下主要页面菜单：3001 监控中心（dashboard:query）、3002 火警处置（alarm:query）、3004 值班管理（duty:query）、3005 巡检任务（patrol:query）、3006 报警统计（无权限串）、3007 单位管理（property:query）、3008 企业信息（enterprise:query）、3160 维修工单（repair:query）、3196 维护保养、3208 隐患管理、3209 数据中心、3218 座机号码管理（duty-phone:query）、3223 通话记录（call-record:query）；3009 为值守端大屏。
- 权限串命名：eiot:firewatch:{功能域}:{action}，action 取 query/create/update/delete 及业务动作（duty:operate 签到签退换班、patrol:execute、repair:assign/complete/close、hazard:rectify/review/close、call-record:voice 录音下载）。维保三个按钮名字带"管理"但 permission 实为 maintenance-unit:query / plan:query / contract:query，仅只读。
- 跨模块配套点：告警消息页与大屏的确认处理/稍后处置/去处置校验 iot:alert:edit（菜单 3226，挂 3002 下），只授 firewatch 前缀会漏掉它；设备控制 iot:device:ctrl、指令下发 iot:device:instruction:send 在设备中心树（2814→2827→2934/3189），并依赖 2828 iot:device-info:query 出列表、隐藏路由菜单 2931 deviceDetail/:id 进详情页。
- 角色现状示例：小程序用户（167）仅挂 query 类权限；消控室值班员（165）按 L1 边界收敛后再按需开放。

## 数据可见性说明
- 系统租户（tenant_id=1）+ 小程序用户（wx_user）：无区域限制，可查看所有租户的 firewatch 数据。
- 系统租户（tenant_id=1）+ 监管角色（monitor_role）：受 area_code 限制，仅查看该区域内租户的数据。
- 为移动端演示账号推荐分配「小程序用户」角色以获得最广数据可见性。
