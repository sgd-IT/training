项目角色配置（system_role 表）分两类来源：

一、全局种子角色（SQL 初始化，固定 ID）
- ID=1: 超级管理员（super_admin），内置角色（type=1）
- ID=154: 只读用户（reader），自定义角色（type=2）
- ID=161: 远程值守员（remote_duty_officer），自定义角色（type=2）
- ID=165: 消控室值班员（fire_watcher），自定义角色（type=2）
- 其他自定义角色：值守主管、技术负责人、业主消防安全负责人等

二、每租户动态生成的角色（不是固定 ID 的单行）
- 租户管理员（code=tenant_admin，内置 type=1）：由 TenantServiceImpl 在创建租户时于该租户下自动新建一行，因此每个租户各有一行自己的 tenant_admin，主键 ID 随租户数量递增，不存在"全局唯一 ID=155"这种固定取值；其菜单权限等于该租户套餐（TenantPackage）配置的菜单集合。

RoleTypeEnum 定义两种类型：SYSTEM(1) 内置角色（super_admin、tenant_admin），不可删除或修改；CUSTOM(2) 自定义角色，管理员可自由创建编辑。判断角色身份时应使用 code 而非 ID，因为 ID 在多租户下不具稳定性。

## 数据可见性说明（新增）
- **系统租户（tenant_id=1） + 小程序用户（wx_user）**：无区域限制，可查看所有租户的 firewatch 数据（如 tenant 166 的 31207 条告警）。
- **系统租户（tenant_id=1） + 监管角色（monitor_role）**：受 `area_code` 限制，仅查看该区域（如广东省 440000）内租户的数据。

## Notes
- 实测补充（2026-10 建号任务）：「安为科技值守中心」（tenant_id=1）名下**没有 tenant_admin 角色行**，测试库里只有租户 166（role id=155）与 168（role id=170）存在 tenant_admin。因此值守中心侧的运营视角只能靠 super_admin（admin, user id=1），排查"该租户管理员看不到某功能"时不要假设租户 1 有 tenant_admin。
- 同轮实测：权限点 system:user:update-password（菜单 id=1007，父级为用户管理 100）当前仅分配给 role 155（租户166 tenant_admin）、164（业主消防安全负责人）、169（安全负责人）、170（租户168 tenant_admin）。若某角色看不到「重置密码」入口，属角色未勾选该权限点，而非接口缺失。
