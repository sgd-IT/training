duty-screen 是一个独立的全屏 Vue 页面，不包裹在主管理后台布局中；其路由定义在 /src/router/modules/remaining.ts 中，直接挂载到根容器。因此任何需要在大屏登录后触发的全局逻辑（弹窗、提醒等）必须挂在 App.vue 而非 Layout.vue，否则永远不会触发。

消防巡检任务管理界面位于 /eiot/firewatch/patrol 路由下。

侧边栏菜单渲染来源（实测补充）：store/modules/permission.ts 中 `this.routers = cloneDeep(remainingRouter).concat(routerMap)` —— 菜单 = remaining 静态路由 + 后端动态菜单的合并结果。由此得到三条可利用的结构事实：
1. remaining.ts 里注册的路由只要不带 meta.hidden 就会出现在侧边栏，且**不参与后端菜单权限过滤**，所有登录角色可见；适合承载"面向全部使用者、无需按角色配权"的页面。
2. Menu 组件的 useRenderMenuItem 先按 `!v.meta?.hidden` 过滤，再由 hasOneShowingChild 判定：父路由 + 唯一显示子路由会被合并成**单个菜单项**，标题与图标取子路由的 meta，index 由 pathResolve(父path, 子path) 得出（子 path 为空串时即父路径本身）。
3. 排序副作用：静态路由 concat 在动态菜单之前，故 remaining 中显示的页面会出现在侧边栏**最上方**；若需插入业务分组中间，只能改走后端 system_menu 表方案（插菜单 + 角色分配）。
