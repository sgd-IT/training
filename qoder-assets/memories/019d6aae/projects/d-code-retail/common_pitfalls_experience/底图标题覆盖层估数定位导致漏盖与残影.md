Bug class：用 HTML 绝对定位覆盖层盖住背景切图上的原文字时，覆盖层位置与宽度靠估数导致盖不准（漏出装饰元素或原文字尾端）。

Root cause：两个可验证成因——(1) 对底图做亮度扫描定位原文字时阈值过宽（如仅按 RGB 之和 >500 判定），会把卡片边缘的高光装饰线一并计入，量到的 x 起点接近 0，据此反推的 left 偏大而漏掉左侧三角装饰；(2) 覆盖层用横向线性渐变收尾，实心段比例过小（如 72% 起羽化）叠加 min-width 不足，使原文字最宽处落在半透明区，透出残影。

Fix pattern：先用接近白色的分量阈值（R、G、B 三者各自均高于约 195）扫描出原文字真实像素区间，再按图片原始尺寸与卡片显示尺寸的比值换算，把覆盖层的 left/top 收到能同时包住文字与其装饰前缀；覆盖层总宽取"原文字右端换算值再加一段余量"，并把渐变实心段终点推到超过该右端值，只在末端保留一小段羽化避免硬边。

Reusable lesson：不要凭视觉反复微调覆盖层的 left/top/min-width，因为缺少底图真实像素区间时会来回震荡且始终露出残影；必须先扫描量准原文字区间再一次性换算。适用于"背景切图自带标题、前端用覆盖层改写文案"的大屏/海报类页面；不适用于标题本身由 DOM 文本渲染、或底图允许直接重绘替换的场景。
