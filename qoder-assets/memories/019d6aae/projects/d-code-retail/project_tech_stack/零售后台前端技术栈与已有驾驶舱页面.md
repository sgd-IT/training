零售后台前端工程 anwei-fireworks-retail-admin 的技术栈与现成大屏资产：采用 Vue3 + Vite + Element Plus + ECharts 6 + @iconify/vue + UnoCSS。已存在监管驾驶舱页面 src/views/regulator/cockpit/index.vue（浅色商务风，含 KPI、趋势、分布、超量排行、提级清单）。路由机制为 constantRoutes 静态路由 + 后端菜单动态路由，permission.ts 对未登录请求强制重定向到登录页；登录成功后的默认落地路径由 login.vue 的 redirectUrl 与 permission.ts 共同决定（改默认首页需同时改这两处）。dev 环境前端跑在 80 端口、base API 为 /dev-api，vite 代理到 localhost:8080；验证码开关由后端 /auth/code 返回 captchaEnabled 控制。做演示大屏时可复用本地 ECharts 与 @/api/fireworks/regulator 既有接口，避免依赖外网 CDN 与新增后端；用户机构名可取 store/modules/user.ts 中的 deptName（需自行从 UserVO 映射进 store）。注意 UnoCSS 类名命名空间会污染自定义布局类名。

## Notes
- "改默认首页需同时改 login.vue 与 permission.ts 两处"已不准确：现实现是登录成功后在 login.vue 里无条件 push('/screen')，并删除了读取 URL redirect 参数的响应式变量与 watch，permission.ts 无需再改（详见"登录页默认落地页会被地址栏 redirect 参数静默覆盖"一条）；但已登录状态直接打开根路径仍走 router 里 '/' → '/index' 的重定向。
- "用户机构名可取 store 中的 deptName"目前处于闲置状态：大屏顶栏的机构名展示已被删除，deptName 字段仍保留在 store 中但暂无消费方；大屏改为按角色区分零售店展示——管理员(superadmin)/监管(regulator)显示可切换的零售店下拉框，其他角色只读展示自身绑定零售店名称，数据过滤统一用 store 中的 retailId。
- Element Plus 版本为 2.14.3，el-select 的 :teleported="false" 可用（大屏定尺寸缩放舞台下必须关闭 teleport，否则下拉面板跟随 body 而不参与整体缩放）。
