## Task description
- Core requirement: 演示大屏三项连续迭代——(1) 内容区底部留出空间，避免中间栏"报警趋势/核定药量"卡片压住底图装饰框；(2) 未处置告警列表支持手动滑动并可点击条目跳转后台报警管理；(3) 左上角新增零售店筛选下拉（默认全部零售店），且仅管理员/监管角色可筛选，其他角色只读显示自身绑定的零售店名称
- Task background: 大屏为 1920×1080 定尺寸缩放舞台，内容区 .screen-container 用 calc 百分比高度硬算，中间栏 flex:1 自适应；监管接口 /fireworks/regulator/* 六个均已支持可选 retailId 参数（为空即全部零售店聚合）；后台报警管理页 /alarm 已支持按 alarmNo 定位

## Execution process
1. screen/index.vue `.screen-container`：height 由 calc(100% - 113px) 改为 calc(100% - 138px)（margin-top:-60px 不变），底部留 25px，中间栏卡片不再触底压住底图装饰框；左右栏固定高度卡片本就离底约 40px，不受影响
2. RightColumn.vue：告警容器 overflow: hidden → overflow-y: auto，并按大屏深色风格定制 4px 细滚动条（青色滑块、悬停变亮、深蓝轨道）；保留原有自动轮播与 @mouseenter 触发的 stopScroll，滚轮操作时天然暂停
3. RightColumn.vue：告警条目加 cursor: pointer + hover 高亮（背景与描边转亮），点击执行 router.push('/alarm?alarmNo=xxx')，复用后台报警管理页既有的告警编号定位能力（与监管总览"查看详情"同一跳法）
4. screen/index.vue：新增 getRegulatorRetailOptions 拉取零售店选项；selectedRetailId 用字符串 'all' 作哨兵值（空串会被 el-select 当成未选中）；改完角色口径后拆成 canFilterRetail（角色判定）+ retailIdParam computed（可筛选角色用下拉值，否则强制用 userStore.retailId），切换后 loadAll() 全量重拉 5 个接口，60s 轮询沿用当前选中值
5. ScreenHeader.vue：左上角加 el-select 并设 :teleported="false"（面板随大屏整体缩放，避免位置/尺寸错位），样式用 :deep 定制深色面板；角色判定最终上移到父组件经 canFilter prop 传入，组件内 v-if="canFilter" 渲染下拉、v-else-if="boundRetailName" 渲染只读胶囊（店铺图标 + 从 retail-options 按 retailId 反查的店名）
6. ScreenHeader.vue：按要求删除机构名 enterprise-name-top 节点及其 orgName computed 与样式，但保留外层 .left-group 包裹——否则非筛选角色该区域为空时 space-between 会把右侧时间/按钮挤到左边
7. 校验：pnpm.cmd exec vue-tsc --noEmit 结果 total=3（均为存量错误，screen 模块零新增）；grep package.json 确认 element-plus 2.14.3 支持 teleported

## Notes
- 角色判定最初写在子组件里（本地 RETAIL_FILTER_ROLES + showRetailFilter），后因"其他角色要显示自身零售店名"需要同一份判定同时决定 UI 形态与请求参数，改为父组件统一计算并以 prop 下发，避免两处角色清单漂移
- 角色 key 取自 sys_role.role_key，本次认定"管理员"=superadmin、"监管"=regulator；渠道管理员(channel)是否需要筛选未确认，调整只需改数组一项
- 未绑定 retailId 的非筛选角色：不显示店名胶囊，且请求不带 retailId（即看全部），此边界需产品确认
- /alarm 属后台动态菜单路由，无该菜单权限的角色点击告警条目会落到 404（已向用户提示，可选做跳转前权限判断或补菜单权限，暂未实现）
- store/modules/user.ts 中此前为显示机构名补的 deptName 字段现已无消费方，保留备用
