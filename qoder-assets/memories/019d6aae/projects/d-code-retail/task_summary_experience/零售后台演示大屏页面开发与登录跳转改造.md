## Task description
- Core requirement: 在零售后台前端做"演示大屏"方案——保留原线上大屏（fireworks-admin.gdawkj.com #/dashboard）的布局观感，周边卡片内容全部换成监管总览接口数据，去掉大屏首页/企业管理等菜单按钮，仅保留一个进入管理后台的入口，登录后直接跳大屏
- Task background: 线上站点为 Vue2 + Element UI，与本地 anwei-fireworks-retail-admin（Vue3 + Vite + Element Plus + UnoCSS）不同栈，不能直接搬代码；本地已有 src/views/regulator/cockpit/index.vue 与 @/api/fireworks/regulator 六个接口封装；原站组件源码通过解析同源静态资源 /static/js/1.js 模块 Dwms/zIwT 与 CSS 模块 E768/4LOf 反查获得，28 张切图已下载到 dashboard-assets

## Execution process
1. 前期调研：用 Browser 子代理从登录态受限的站点里 fetch 同源 JS/CSS 分片，还原出 header（dashboard.vue .top）、video-container（realVideo.vue）结构与全部布局 CSS、DOM↔data 绑定关系、三栏比例 1:2.4:1、1920×1080 舞台 + scaleX/scaleY 等比缩放方案
2. 资源迁移：把 14 张切图（bg/com-bg/title/img/day1/safty/monitor/analysis/unprocessed/inventory/yellow-bg/today-alarm/total-alarm/green-bg）复制到 src/assets/screen/；发现各卡片底图自带标题文字（安全生产天数/实时监测概况/告警分析/未处置告警/核定药量），故采用"底图保留 + HTML 覆盖层写新标题"的方式，yellow-bg.png 实为金色球装饰图不可作卡底板
3. 新建 src/views/screen/index.vue：screen-page（fixed 全屏）→ screen-stage（1920×1080 + transform scale 居中）→ screen-header + screen-container 三栏；Promise.allSettled 包 safeLoad 做接口失败静默降级；60 秒 setInterval 轮询，onMounted/onUnmounted 配对清理
4. 新建 4 个子组件：ScreenHeader（deptName + 秒级时间 + 进入管理后台 + 退出下拉）、LeftColumn（今日报警圆环 + 8 项 KPI 2×4）、CenterColumn（视频区静态底图 + 报警趋势堆叠柱 + 超量店铺排行）、RightColumn（今日/近30天 + 等级环形图 + 未处置清单自动滚动）
5. router/index.ts 在 constantRoutes 增加 /screen 独立路由（不套 Layout，不进侧边菜单）；login.vue 的 redirectUrl 默认值与 permission.ts 已登录访问根路径两处同时改为 /screen；store/modules/user.ts 补 deptName 字段（UserVO 已有）
6. 类型检查 pnpm.cmd exec vue-tsc --noEmit：首跑报 5 个 screen 内错误，原因是 safeLoad 的 loader 参数类型写成 () => Promise<{data:T}> 与 AxiosPromise<T> 不兼容，改为接受返回 T 的 loader 后归零（仅剩 3 个存量错误）
7. 实测验证：启动 vite dev（80）+ mvn install 构建 + java -jar 启动后端（8080），用 playwright-core 驱动系统 Edge 无头登录并截图，探针采集 getBoundingClientRect/getComputedStyle

## Notes
- 首轮截图整体偏左、右栏只有 318px：布局根类名用了 container，被 UnoCSS preset 生成的 .container{max-width:1536px} 工具类截断，改名 screen-container 后三栏恢复 406:974:406
- 图形验证码识别多次失败（干扰线严重），最终改从 Redis 直读 global:captcha_codes:<uuid>（值为 JSON 序列化需去引号），uuid 由 page.on('response') 拦截 /auth/code 取得

## 后续调整说明
- "所有角色可看"已取代原先"演示前需在角色管理勾选监管总览"的做法：RegulatoryController 类级注解由 @SaCheckPermission("fireworks:regulator:statistics") 改为 @SaCheckLogin，非超管账号不再 403；后台侧边栏该菜单仍受菜单权限控制。
- 登录跳转结论有更新：仅把 login.vue 的 redirectUrl 默认值设为 /screen 不足以生效——从根路径进入时 permission.ts 会带上 ?redirect=%2Findex，登录页优先跳 redirect 参数导致回到后台首页。现改为登录成功后固定 push('/screen')，并删除了 redirect ref 与其 watch；因此"改默认首页只需同时改 login.vue 与 permission.ts 两处"的说法已不准确。已登录状态直接打开根路径仍进后台首页（/ 的 redirect 仍为 /index），如需也进大屏要另改 router/index.ts。
- 缩放策略已由"等比缩放居中"改为 X/Y 独立缩放铺满视口（scale(w/1920, h/1080)，left/top 归零），非 16:9 窗口不再有黑边但会有轻微拉伸；上文"1440×900 等比缩放居中留白对称"的描述对应旧实现。
- 布局尺寸又有迭代：内容区 .screen-container 已加上 margin-top:-60px + height:calc(100% - 113px) 使整体上移贴近 header（上文步骤 3 的"三栏紧贴 header 高度 173px"对应旧实现）；两张卡的 .card-title 覆盖层也已按底图实测像素重定位（left 22px / top 6px / min-width 240px / 渐变实心段 78%）。具体数值以"演示大屏内容区上移与卡片标题覆盖层像素校准"一条为准。
