Conclusion: 在固定分辨率舞台的大屏布局里让内容区整体上移贴近 header 时，选择"负 margin 上移 + height 同步补回被减掉的像素"（margin-top:-Npx 配 height:calc(100% - (原偏移-N)px)），而不是只改负 margin 的纯平移。

Rationale (trade-off): 补回高度能让内容仍铺满到屏幕下沿、不产生底部空白带，观感更完整；代价是其中采用 flex:1 自适应高度的那一栏会随之长高 N px，而固定高度的卡片栏会在底部露出背景空隙，两处副作用同时出现需要向用户说明。

Rejected alternatives: 纯平移（只设负 margin 不动 height）——各栏尺寸完全不变、改动最小，但会在屏幕底部留下 N px 空白，在整屏驾驶舱场景下比"局部变形"更显眼，故被否；直接缩小 header 高度则会影响 header 自身切图与文字排版，也未采用。

Applicable / expiry conditions: 适用于外层为定尺寸 stage（如 1920×1080 缩放舞台）、子区域用 calc 百分比高度硬算且部分卡片为固定高度的大屏页面；当布局改为整体 flex 撑满、或各栏都改成自适应高度、或要求内容尺寸严格不变（如逐帧对齐录屏/截图比对）时，应重新评估并优先选纯平移。

## Notes
- "补回高度铺满到底"这一取向已被后续迭代部分推翻：本条所指的 screen/index.vue `.screen-container` 后来从 calc(100% - 113px) 再减 25px 改为 calc(100% - 138px)，即主动在屏幕底部留出空白，因为补满后 flex:1 的中间栏卡片下沿会压住大屏底图自带的底部装饰框线，观感问题比"底部留白"更严重。因此本条的适用边界应收紧为：仅当底图下沿没有需要露出的装饰元素、或内容确实需要贴到屏幕边缘时才补满高度；若底图本身带有边框/装饰线属于视觉的一部分，宁可少补几像素、把留白当作设计余量。调整留白的通用做法仍是改减数（减数 = 原偏移 + 期望底部留白像素）。
