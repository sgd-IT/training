hc-standard 两套 MySQL 环境的业务数据实况（serverName 可用性与落点判定口径见"线上正式库与测试库的MCP访问服务名及数据形态差异"）：
1. 隐患数据：正式库约 92 条含 id=731；测试库 50 条（max id≈688）、无 731。
2. 区域树：两库 area_id 完全一致（537液氯气化/566邻醛/613对酚/625再生/649氯化锌/665中控楼）。
3. 风险单元：ID 两库一致，但测试库少一个液氯储罐气化装置（be90445b…）。
4. 检维修作业措施：测试库原本只有液氯下 1 条（0f5be454…），氯化锌下的 f37a15d7…（编码10026）是测试造数插入的。
5. 园区平台 API 基础地址 PlatementBaseApi.HTTPSTR="http://111.4.80.39:8092" 是 static final 硬编码常量，全工程唯一、无配置项覆盖，测试库提交也会真推到该地址；用测试库做端到端测试前必须先确认该 IP 是园区测试环境还是生产环境，否则污染园区数据。
6. hc-standard-test MCP 服务曾从工作区服务列表移除（目录消失、调用报 code=50001），执行SQL前须先确认当前可用MCP服务。
