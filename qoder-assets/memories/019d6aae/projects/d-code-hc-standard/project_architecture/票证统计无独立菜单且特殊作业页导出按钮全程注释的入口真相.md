特殊作业票（workSpecial）PC 端的能力分布与真实入口边界：
- 需求侧所称"票证统计"在系统中没有独立菜单。经线上库 sys_menu 实查，该能力唯一挂载点为【作业管理】(menu_id 2470, path=ticket) → 【特殊作业】(menu_id 2666, path=workSpecial, component=base/workSpecial/index, perms=base:workSpecial:list)，即路由 /ticket/workSpecial 的台账列表页。同级兄弟菜单为作业报备(2654/TicketBb)、票证视频(2684/workVideo)，另有 visible=0 仍显示的历史遗留项"作业申报-废"(2524)、"特殊作业-废"(2390)。
- 关键反直觉事实：ruoyi-ui/src/views/base/workSpecial/index.vue 的整个工具栏（新增/修改/删除/导出/上传）自初版提交起即为 HTML 注释状态，操作列仅剩"删除"。因此前端 handleExport()、后端 GET /base/workSpecial/export、以及按钮权限 base:workSpecial:export(menu_id 2671) 三者全部存在，但 UI 上没有任何可触发导出的按钮 —— "接口与权限齐备"不等于"功能可达"。
- 结论口径：PC 端特殊作业页面当前实际可见能力只有台账列表查看（搜索条件仅"作业编号"一项 + 分页 + 行内删除）；如需导出数据，现阶段只能携带登录态直接调用后端接口，无页面入口。
- 排查方法：RuoYi 菜单为数据库动态菜单，仓库内无菜单初始化 SQL，定位任何功能的真实入口应查 sys_menu 并按 component/perms/menu_name 检索后 LEFT JOIN parent_id 取上级名称，不能依据代码中的路由或功能树资料推断菜单名。

## Notes

- 上述"UI 上没有任何可触发导出的按钮""无页面入口"两项结论已不再成立：后续会话已在 index.vue 操作列新增「导出」按钮（配 api/base/workSpecial.js 的 exportPdf，responseType blob + file-saver saveAs），并在 BaseWorkSpecialController 新增 GET /base/workSpecial/exportPdf/{outerId} 以 Content-Disposition attachment 流式返回作业票 PDF，点击即由浏览器下载、文件名取作业票号。被注释的是**顶部工具栏**（新增/修改/Excel 导出/上传），行内操作列现已含"导出 + 删除"两个按钮。判定该页面能力可达性时须区分"顶部工具栏仍注释"与"行内导出已可用"，不可再整体沿用"仅有列表查看"的旧口径。

- 最新修正（PDF 导出全链路验证会话实测）：上一段 Notes 中"顶部工具栏仍注释"的说法也已过时——Grep index.vue 实测确认顶部工具栏当前已恢复渲染，含"导出"按钮并绑定 handleExport（对应 Excel 台账导出，权限 base:workSpecial:export）；操作列现为"预览 | 导出 | 删除"三个按钮（预览=handlePreview 走 /print 在线查看，导出=handleExportPdf 走 /exportPdf 下载）。回答"导出入口在哪"类问题时必须区分两处同名"导出"：顶部=Excel 台账、行内=PDF，二者均已 UI 可达，不能再引用正文"无任何可触发导出的按钮"的初版结论。
