hc-standard 项目 base_risk_task 启用任务（deleted=0 AND status=0）实测共 68 条，按应检人分 12 组：

- 7 天周期只有两组：夏翔飞（user_id 835，10 条，work_type=3 操作负责人，液氯气化仓库）、瞿彬+彭亨清（395,839，1 条，氯化锌生产装置）。
- 月/季/半年集中在袁志明（862，月3+月6，10 条）、朱文浩（696，月3，9 条）、佘艳信（718，天1+月1）、廖兴国+尹恒、周程（716）、牛富强（682）。
- 小时/天1 班次类：文茂华+全正华+冯中卫（小时8）、黄雪晴+李小姑+马燕（小时12，锅炉房）、张艳军+文建新+尹超杰（小时1/2，液氯储罐气化装置）、李家洲+张丛海（天1）。
- 全部 68 条 work_start_time 均为 00:00:00，APP 侧可见时间为凌晨；要改成白天派送必须同步修改 work_start_time，仅改日期无效。

数据质量陷阱：同一组三人（张艳军/文建新/尹超杰）的 check_user_id 在库中存在 5 种排列顺序（734,736,747 / 734,747,736 / 736,734,747 / 736,747,734 / 747,734,736），按 check_user_id 精确 GROUP BY 会把同一组拆成多行导致人数统计偏少。按人员维度做筛选或汇总前应先对 ID 排序归一化。（check_user_id 的 like 包含匹配机制及其误命中后果见「移动端排查任务待检可见性由单接口与check_user_id模糊匹配决定」，本条不重复。）
