园区平台的作业票 workStatus 是固定枚举，仅认 0=未开始、1=已验收、2=进行中、3=未验收、4=已删除，没有中断/暂停态。本系统一旦新增超出该集合的本地状态（如 base_work_special.workStatus=5 表示中断，字典 b_workstatus），必须在向平台推送前把状态归一回 2（进行中），否则平台侧校验直接拒绝。

实现上的不变量：归一只在内存实体上做，即重新查出实体后 setWorkStatus("2") 再调 api.startTicket(push)，绝不能把这行写回数据库，否则本地中断态被覆盖、状态机失效。BaseWorkSpecialServiceImpl.pushWorkStatusAsRunning() 即为该模式的具体承载方法，中断与恢复两条链路共用。

关联约束：中断记录本身不推平台（平台无对应字段），只存本地 base_work_interrupt 表；推送结果仍按既有 updateSyncStatus 写 sync_status='1'/'2'，推送失败不回滚本地状态，这与 startWork 的既有行为保持一致。
