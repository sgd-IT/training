ActivityAddHiddenDanger（移动端隐患录入页）经实测确认的结构事实：
1. 措施列表缓存：mListMeasure 非空时打开管控措施下拉不再发请求，后台新插入措施后下拉看不到；必须重新选一次隐患区域触发 onAreaChanged 清空 mListMeasure（同时已选措施也被清空），再打开下拉才会拉到新列表。
2. 必填校验为静默失败：缺"整改标准"或"整改建议"时点底部"添加"按钮页面不动，只弹约 2 秒的瞬时 toast（"请填写整改标准"），截图需在读回时控制在点击后 ~1.2 秒内才能捕捉；隐患描述、发现时间、类型、类别、级别、责任部门、责任人、落实截止时间同为必填。
3. 入口路径：工作台 → 其他工具区 → 添加隐患。"隐患治理"页是无新增按钮的空列表页，"问题上报→右上角上报"是另一个简易上报表单（字段为问题区域/检查类型/照片描述），均不是隐患录入 ActivityAddHiddenDanger。
4. 提交成功后的行为：弹"隐患添加成功，是否添加举一反三"对话框（取消=不添加）；本地写入 base_hidden_trouble，code_number 格式 YH-yyyyMMdd-NN，find_user_name 取当前登录账号昵称。
5. 改造后表单顺序：隐患区域置顶 → 类型 → 类别 → 级别 → 装置单元 → 管控措施 → 责任部门/人/时间；区域选中父节点只做下钻需再点"暂不选择"才真正设 areaId 并触发联动；措施下拉项显示带"单元名 · 措施名"前缀，长列表需在弹窗内滚动。
