## 使用场景
用 adb 在 MuMu 模拟器上驱动长表单 + 多层弹窗的 App 流程（填表、选人弹框、保存）。

## 使用方式
- 每步操作前先 `adb shell uiautomator dump` 拉 XML，用正则取目标控件 bounds 中心坐标再点，比按截图估算可靠得多（实测按截图估 y 偏差 80px 即点不中）。
- 弹窗内点"确定"后等 2~3 秒再操作下一步，并重新 dump 确认真实页面状态。
- Toast 只存在约 2 秒且不进 logcat：须在点击命令后立即同条命令内 screencap，再 pull 回本地读图取证。
- 长表单滚动后坐标全部失效，滚动与点击不要放进同一条命令连续执行。

## 注意事项
- 弹窗关闭瞬间会"点击穿透"到底层控件：同一条命令里连点两次确定，第二次常落到下层表单可点行上（实测误开"作业部门/风险辨识"选择框），导致表单状态错乱。
- hc-standard DialogWorkPeopleMultiple 的真实规律（本轮修正旧结论）：**列表项点击本身不会重排**，在同一维度内连续勾多人是稳定可行的；勾选丢失的唯一原因是点了"全部"或岗位类维度——该分支走 setSearchPeople→setData→mAllPeople.clear() 重建，把已勾的人清空。只在"本公司/承包商"两个维度间切换（走本地 applyData）勾选才保留。
- 因此跨企业凑齐"内外各一人"的正确姿势：全程停留在默认"全部"维度内滚动勾选，或先在"承包商"勾外施队人再切"本公司"勾内部人；切勿中途点"全部"或岗位名。
- 结论更新：adb 盲点可以完成"多选人 + 保存"这类长流程，前提是每次点击前重新 dump 取坐标、并避开会触发重新请求的维度切换；接口层直调仍是穷举多分支断言的首选，UI 用于取证交互组件与文案。
