Conclusion: 移动端标题栏要同时容纳页面级状态操作与次要操作时，采用"新增次要文字槽位 + 样式弱化"方案（title.xml 在 tv_right 左侧加 tv_right_secondary，透明底 + @color/blue 文字），而不是新建下载图标位图，也不是把下载塞回某个内容 Tab。

Rationale (trade-off): 项目 res 下无任何语义正确的下载图标（ic_home_dl 是配电箱设备图、ic_home_down 是下拉箭头，用作下载会误导），新绘矢量/位图图标会引入跨 density 资源维护成本且与既有纯文字标题栏风格不一致；用同规格文字按钮配不同底色即可表达主次，改动集中在公共组件一次生效于全部票型详情页。代价是标题栏横向空间被占用，长标题会变窄。

Rejected alternatives: 1) 新建 ic_download 矢量图标——语义更清晰但需新增资源文件并核对各 dpi，且本仓库标题栏从无图标先例，属不合理的一致性破坏；2) 把下载入口移到「基本信息」Tab 底部——语义同样正确，但 8 个票型 Fragment 各自有独立布局都要改，成本最高；3) 保留在现场会签页只降权改样式——最省事但只消除歧义，不解决"整票能力挂在单一环节 Tab"导致的发现性问题。

Applicable / expiry conditions: 适用于 other1 移动端 XHeadView 右侧单槽位被流程状态按钮占用、又需追加页面级辅助操作的场景；若后续引入统一图标库或把 XHeadView 右侧改为溢出菜单（…）承载多操作，应回退为图标/菜单形态而不再叠加文字槽位。次要槽位必须默认 visibility=gone 并由 refreshRightSpacing() 动态管理右边距（与主按钮并存 10dp、单独存在 15dp），否则会成为最后一个可见子项贴屏幕边。
