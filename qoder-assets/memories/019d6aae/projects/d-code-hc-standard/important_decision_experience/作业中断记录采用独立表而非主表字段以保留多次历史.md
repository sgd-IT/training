Conclusion: 作业票中断信息采用独立表 base_work_interrupt（一次中断一行，含 workId/interruptTime/resumeTime/reason），不在 base_work_special 主表上加 interruptTime/resumeTime/reason 三个字段。

Rationale (trade-off): 一张票常有多次中断（动火一天停两三次），主表字段方案后一次会覆盖前一次、历史全丢；独立表可完整列出"停了几次、每次多久、什么原因"，且按预估频次（每票约 3 行）体量极小，代价只是多一次关联查询和一张表。

Rejected alternatives: 1) 主表加三列——实现更省事、无需新表，但只保留最后一次中断，检查场景无法出示完整轨迹，属合理但收益不足的方案；2) 完全不做中断记录只改状态——满足状态流转却无任何留痕，甲方验收不过。

Applicable / expiry conditions: 适用于"同一业务对象的一类事件会发生多次且需全部留痕"的记录设计（同类如复检、补录、异常暂停）；若确认业务上一张票至多只会中断一次，或该信息只需在票面呈现最新一条，可回退为主表字段以免新增表带来的 mapper/domain/权限改动。本决策仅约束本系统本地留痕，园区平台无对应字段故不推送。
