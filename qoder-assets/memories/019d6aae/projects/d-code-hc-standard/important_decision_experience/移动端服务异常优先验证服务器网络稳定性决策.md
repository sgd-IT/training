Conclusion: 在移动端"服务异常"诊断中，优先验证服务器侧网络稳定性（而非客户端配置），作为根因排查的第一假设。
Rationale (trade-off): 客户端配置错误（如IP写错）和服务器网络不稳定都可能导致连接失败；但服务器侧问题具有全局性（影响多个接口、多个时间点），且日志可交叉验证；而客户端问题通常孤立、不可复现，验证成本更高。
Rejected alternatives: 先检查客户端 `HttpInterface.java` 是否配置错误 → 合理但低效，因该文件已被确认正确；先检查手机网络 → 合理但无法复现，且无日志佐证。
Applicable / expiry conditions: 适用于后端日志存在多接口并发失败、且时间窗口高度集中的场景；当单点故障（如仅一个API失败）或客户端日志明确报错时不适用，此时应转向"最近换程序引爆旧隐患"的 git 变更史定位法。
Notes: 本次任务中，该决策被成功应用：通过分析后端日志，发现 `refreshVideo` 接口在 15:23~15:27 期间发生多次并发连接超时，与用户报告的"服务异常"现象时间高度吻合，从而确认了服务器侧网络稳定性问题是根本原因。
