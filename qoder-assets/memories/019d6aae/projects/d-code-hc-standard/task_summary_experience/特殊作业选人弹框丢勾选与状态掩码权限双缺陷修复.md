## Task description
- Core requirement：修复上轮盘点出的两个缺陷——问题一「监护人选人弹框切维度丢勾选」采用 A+B 组合方案；问题二「详情接口按 curOperatorId 掩码 workStatus 导致 APP 看不到操作按钮」，用户拍板可操作口径为「监护人 + 开票的人」。

## Notes
- 两套体系（人员库 base_contractor_people 与账号库 sys_user）跨表关联务必实测命中率再定键：手机号看着合理实则两边不一致，姓名才是稳定口径，选错关联键会让整个权限判定失效。
- 权限校验必须置于业务校验之前，否则业务条件凑巧满足时非授权人可绕过权限拦截，属"形同虚设"型缺陷；排查这类问题看返回的是权限拒绝还是业务报错即可判断顺序对错。
- domain 若用手写 getter/setter（非 Lombok），新增字段必须同步补访问器，否则 setXxx 调用在 devtools 增量编译下静默不生效、接口返回恒 null，极易误判为"后端没重载"。
- /other1/ 在 .gitignore 第 56 行，APP 三处改动不进 git，交付需另行同步；正式库须执行同一份 DDL 且与 jar 同批上线（mapper 显式列清单，缺列即报列不存在）。
- 遗留未测：PC 端详情抽屉未同步处理 viewOnly；编辑票改 jhr 不会重算 guardianUserIds；其余 7 票型仅动火真机跑过；外施队人员无 sys_user 账号故其监护人身份反查不到 ID 无法登录操作（账号体系现状限制）。
