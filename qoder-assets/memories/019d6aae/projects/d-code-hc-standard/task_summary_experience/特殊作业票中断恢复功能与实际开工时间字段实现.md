## Task description
- 核心需求：为特殊作业票新增"中断作业/继续作业"能力（需求34，用户选定B方案：中断原因选填），并新增"实际开工时间"字段以区分报备的计划开工时间。
- 任务背景：workStatus 原为平台固定枚举 0未开始/1已验收/2进行中/3未验收/4已删除，平台侧无中断态；startWork/endWork 原先只切换 workStatus，不落任何实际开工时间戳；作业票主表 base_work_special 列名为驼峰风格，mapper 用显式列清单而非 select *。用户同时明确"先不考虑中断超30/60分钟要重新检测"，故中断不做气体重测联动。

## Execution process
1. 新建 DDL 脚本 ruoyi-admin/src/main/resources/sql/add_work_interrupt.sql：建表 base_work_interrupt（id/workId/interruptTime/resumeTime/reason/createBy/createTime/updateBy/updateTime，KEY idx_work_id），并在 b_workstatus 字典插入 5=中断。选择单独建表而非在主表加三列，因一张票可能多次中断，主表字段会被后一次覆盖而丢历史。
2. 新建 DDL 脚本 add_work_actual_start_time.sql：base_work_special 增加 actualStartTime datetime 列（AFTER workStartTime）。
3. 新建 BaseWorkInterrupt domain + BaseWorkInterruptMapper 接口/XML：insertBaseWorkInterrupt、resumeLatest（update ... where workId=#{workId} and resumeTime is null order by interruptTime desc limit 1，借 MySQL 的 update+order by+limit 规避同表子查询 1093 报错）、selectByWorkId。
4. BaseWorkSpecialServiceImpl 新增 interruptWork(outerId, reason) / resumeWork(outerId) / selectInterruptList(outerId)，并抽出私有 pushWorkStatusAsRunning()：查实体后临时 setWorkStatus("2") 再调 api.startTicket，使中断态不落平台；推送结果仍按原有 updateSyncStatus 写 '1'/'2'，推送失败不回滚本地状态（与 startWork 既有行为一致）。
5. 补两处状态校验防绕过：startWork 只允许 workStatus=0 时开工（否则中断后再点开始会覆盖 actualStartTime 并向平台推错误状态）；endWork 拒绝在 workStatus=5 时结束（必须先继续作业把中断记录收尾）。
6. ApiSpecialController 暴露 /interruptWork（reason 用 @RequestParam(required=false)）、/resumeWork、/interruptList。
7. APP 侧：HttpInterface 增三个接口；ActivityHotWork.setRight() 将 case "2" 拆为独立分支——进行中显示「中断作业」、状态5显示「继续作业」，setTopRightButton 增加对应 status 分支，中断弹 AlertDialog+EditText 采集选填原因；FragmentJobSlipGas.isEditable() 白名单加入 "5"（否则中断态下添加按钮隐藏，出现"要求重测却不给录"的死循环）。
8. 后端 mvn -pl ruoyi-common,ruoyi-system,ruoyi-admin -am compile 三次均 BUILD SUCCESS。
