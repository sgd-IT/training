## Task description
- Core requirement: 评估甲方"排查任务固定每周一早上8点派送"需求的合理性，并针对当前派送时间漂移缺陷给出可执行的整改方案与效果验证
- Task background: base_risk_task 上 work_type=3 的任务共 10 条（task_num 1~10，全部挂同一风险单元"液氯气化仓库"），周期 7 天、work_start_time=00:00:00；派送由 sys_job 104（TaskList.addRiskTaskRecord，cron `0 10 0 * * ?`）生成 base_risk_task_record。用户观察到每个操作人派送时间有的半年有的三个月且不固定，要求判断"固定周一8点"是否合理并给出整改思路。

## Execution process
1. 需求合理性判定：拆分"派送时刻"与"排查周期"两个维度——7天周期任务固定周一8点合理；月/季/半年周期若改成每周派一次等于把频次提高数倍属业务规则变更须甲方书面确认；推荐语义为"周期不变、只把派送日统一到对应周期首月的第一个周一08:00"。
2. 历史取证（前序轮次）：确认所有记录 create_time 时分秒均为 00:00:00（时刻符合配置），但相邻间隔出现 5/6/4 天（应为 7 天），轨迹 周四(01-29~07-23) → 周二(07-28~09-22) → 周一(09-28~10-05) → 周五(10-09~10-16)，锁定 base_risk_unit.update_time=2026-10-08 11:02:58 启用重置导致变周五。
3. 定位漂移两条必然路径：生成侧 TaskList.java 天/月/年分支的 plan_time/create_time/task_next_time 全部以"程序运行当天"为基准（getTimeOfBeforeDawn / getDayOfBeforeDawn(3,0)），查出的 taskNextTime 字段整个类里一次都没用；启用侧 BaseRiskTaskMapper.xml 的 updateStatusByUnitId 在 status=0 时无条件写 task_start_time=CURDATE(), task_next_time=CURDATE()，该方法被人工 changeStatus、autoSyncUnitStatus（06:00/23:30）、insertBaseRiskUnitLog 三个入口调用。
4. 提出两步走方案：第一步只修偏移（不依赖甲方确认）——TaskList.java 递推基准改取 item.getTaskNextTime() 并用 while(planDate<=now) 跳过积压轮次只补最近一轮；BaseRiskTaskMapper.xml 删除 status=0 的 CURDATE() 重置；TaskHandleMapper.xml 的 taskNextTime 加 DATE_FORMAT(a.task_next_time,'%Y-%m-%d %H:%i:%s') 否则 String 映射带 .0 尾巴致 parseDate 返回 null 触发 NPE。第二步固定周一（依赖甲方确认月/季/半年取哪个周一）。
5. MCP 断连处置：首轮 CallMcpTool 报 not found MCPHost severName（tgr-gz-vue/mcp_server_mysql/anwei-* 均失败，且 mcps 目录下 anwei-* 的 tools/ 为空），先基于既有数据离线推演；用户提示后重试 tgr-gz-vue 即恢复，落点 SELECT DATABASE() = tgr-gz-vue / @@hostname = anwei1-0001。
6. MCP 实数据验证修复效果：查询确认 10 条任务 cur_next 全为 2026-10-23 00:00:00（Friday）、cycle=7、work_start_time=00:00:00；单元 status=0 且 in_stop_window=0。用 SQL 按新逻辑递归算出未来 5 期派送日均为 Friday（10-23/10-30/11-06/11-13/11-20），plan_time 顺延 7 天。
7. 三场景对比推演：启停一次（修复前变周六、修复后仍周五）、job 漏跑一天补跑（修复前整体后移永久生效、修复后日期不变仅晚生成）、长期停用跨多轮后恢复（修复前从启用当天重算、修复后 while 跳过过期轮次只生成最近一轮且不补历史）。

## Notes
- 关键判读结论：**修复上线的时点决定任务稳定在星期几**。改代码不会自动把日期拉回周一——现有锚点已是 2026-10-23 周五，若不单独执行 UPDATE 对齐 task_next_time，修复后只会稳定在周五。
- 甲方说的"周一早上8点"含两件事：日期对齐周一 + 派送时刻从 00:00:00 改 08:00:00（后者需同步更新 base_risk_task.work_start_time，否则只是日期变了时间仍是凌晨）。
- 系统只有 小时/天/月/年 四种周期单位（前端下拉与平台 RiskTaskSaveEntity.checkCycleUnit 均只认 1~4），不存在"周"单位，因此"固定每周几派送"无配置能力，7天周期的星期只能靠初始锚点碰巧落在某天。
- base_risk_unit_log 列名为驼峰（riskUnitId/stopTime/activationTime/sync_status），用 start_time/end_time 查询会报 Unknown column。
- MCP 服务可能整轮不可用（not found MCPHost severName），不要据此断定本项目库连接已下线——先重试原服务名，全局 mcp.json 里的配置仍在即可恢复；恢复后仍须 SELECT DATABASE(), @@hostname 核实落点。
- 首次派送日 = 任务创建次日（task_start_time 写死明天 00:00），新建 7 天任务的星期由创建那天决定，无法指定。
