## Task description
- Core requirement: 对照需求目录"3.3 作业票线上签发与审批模块"的 10 个功能点（作业申请/逐级审批/票证签发/开工核验/过程监控/器材核验/许可管理/离线同步/票证归档/票证统计），核验当前项目已有实现的差异；用户中途明确"这不是改造，只看现有存在的"。
- Task background: 作业票链路横跨 PC 端(ruoyi-ui)、移动端(other1 Android)、后端(ruoyi-system/ruoyi-admin)三处，需逐环节取证后输出纯现状对比报告。

## Execution process
1. 后端主链取证：BaseWorkSpecialServiceImpl 全文通读，确认 saveWorkSpecial(创建即推平台 workStatus=0)、startWork(双重校验)、endWork(完工+生成Word上传)、refreshVideo、rePushBatchToPlatform 五段逻辑边界。
2. 开工核验双重校验定性：第一道 selectWorkStepFinish 统计 base_work_step 中 personFileId 为空且 content 不以"其他安全措施"开头的条数；第二道 selectWorkApproveFinish(outerId,0) 统计 base_work_approve 中 fileId 为空且 wanGong=0(现场会签)的条数；查 wanGong=1 的完工验收校验在源码中被注释，开工时不生效。
3. 逐级审批定性：节点由 base_work_approve_config 按票证类型初始化（动火6/受限3/高处5/盲板3），服务端 updateBaseWorkApprove 不校验前后顺序，唯一顺序约束在 APP 点"开始作业"时检查前 n-1 节点已签；无驳回/退回/超时。
4. 器材核验定性：PlatementTicketNewApi.saveOrUpdateTool 接口已封装但全项目零调用点，推送作业票时 tools 恒为空数组，无台账表与录入界面 → 判为未实现。
5. 离线同步定性：APP 全环节实时调接口，无本地暂存队列与断网重传；后台 /push/workSpecial、/push/workVideo、/push/riskTask 属数据补偿工具，不等于离线同步。
6. 票证归档落盘定位：printWorkSpecial 写入 {ruoyi.profile}/print/{随机UUID}.docx（application.yml 配置 ruoyi.profile=D:/ruoyi/uploadPath）；ResourcesConfig 将 Constants.RESOURCE_PREFIX=/profile 映射到该磁盘目录且 SecurityConfig 对 /profile/** permitAll，可 HTTP 直链访问；库内不记录文件名，仅存平台返回 fileId 于 base_work_special.system_file_ids，PC/APP 均无查看入口。
7. 报备→申请链路定性：base_ticket_bb 为登记制无审批状态字段；APP 有 ActivityWorkReportList/ActivityWorkReport 独立报备入口，建票表单 tv_report 按钮可选报备带出信息存 prepareId，但前后端均无"无报备不许建票"校验；PC TicketBb 页面 CRUD 完整而 workSpecial 页面新增/修改/上传按钮自初版即注释，PC 无法发起作业申请。
8. 环境受阻处置：当前会话 mcps 目录仅有 anwei_fire_remote_monitor_test/browser-use/fetch/Framelink-MCP-for-Figma/genui/sequential-thinking，项目 .qoder/mcp.json 为空，无 MySQL MCP → 改由 Mapper XML、domain 类、SQL 文件取证。
9. docx 需求源文件提取失败：人员定位及相关需求清单.docx 经 Expand-Archive 报"找不到中央目录结尾记录"，且 python 不可用 → 放弃文档明细，按功能名称比对并声明验收标准缺失。

## Notes
- 核验类任务的结论必须区分"接口已封装"与"业务已落地"：saveOrUpdateTool 有 API 无调用点，若只看接口存在会误判为已实现；须以调用点检索结果为准。
- "本地无归档入口"不等于"本地无文件"：Word 实际落盘在 profile/print/ 且可通过 /profile 静态映射直接访问，只是文件名随机 UUID 且不入库，无法从系统反查对应票证。
- 用户提出"对比/核验"时不要默认转为改造方案：本轮曾盘点完现状即准备切方案模式，被用户纠正为"只看现有存在的"，应先确认意图再决定是否出改造设计。
- PowerShell Expand-Archive 不识别 .docx 扩展名需先复制为 .zip；本例改名后仍因文件非标准 zip 失败，说明该路径不可靠，需求文档缺失时应直接向用户索取而非反复尝试解压。
