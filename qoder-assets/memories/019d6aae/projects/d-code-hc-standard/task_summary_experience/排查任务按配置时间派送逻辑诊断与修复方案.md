## Task description
- Core requirement: diagnose why '排查任务' (risk task records) are dispatched at midnight instead of the configured time (e.g., 14:00), and fix the dispatch timing logic
- Task background: APP's '待检' list uses `create_time <= NOW()` as the dispatch gate; production data shows all `create_time`/`plan_time` values are `00:00:00`, causing tasks to appear at midnight; job_id=104 runs at `0 10 0 * * ?` (00:10 daily); `work_start_time` is hardcoded to `"00:00:00"` in backend and not exposed in frontend

## Execution process
1. Verified APP dispatch gate: confirmed `BaseRiskTaskRecordMapper.xml#L56` filters `create_time <= NOW()`
2. Traced generation logic: `TaskList.java#L95-L106` for 天/月/年 cycles hardcodes `createTime = getDate()` → today `00:00:00`
3. Confirmed `work_start_time` is ignored in 天/月/年 branch and hardcoded to `"00:00:00"` in `BaseRiskTaskServiceImpl.java#L89`
4. Verified no UI field for `work_start_time`: full grep of `ruoyi-ui/src` found zero matches for "工作开始时间" or `type="time"`
5. Empirical DB proof: queried recent `base_risk_task_record`; 100% of rows have `create_time`/`plan_time` hours = 0 (midnight)

## Notes
- The root cause is that `TaskList` 天/月/年 branch does not read `work_start_time`, and `BaseRiskTaskServiceImpl` hardcodes it to `"00:00:00"`; fixing requires both updating the generation logic and exposing `work_start_time` in the UI
- All 141 active `base_risk_task` rows have `work_start_time = "00:00:00"`, proving users cannot currently configure an afternoon dispatch time

## Task overview
Successfully diagnosed the root cause of incorrect dispatch timing: the `TaskList` 天/月/年 branch ignores `work_start_time` and hardcodes `create_time`/`plan_time` to `00:00:00`, while the UI provides no way to set `work_start_time`. This explains why tasks always appear at midnight despite user configuration intent.

## 补充说明
- 本条记录的"所有记录 create_time/plan_time 均为 00:00:00、任务固定凌晨出现"这一实测结论已不再适用于当前代码：后续需求改造后，TaskList 的天/月/年分支已改为读取 work_start_time 计算派送时刻，且小时周期分支一直按 planTimeEnd - checkCycle 逐班生成。2026-10 实测某 8 小时周期任务的当日三条记录 create_time 分别为 00:00、08:00、16:00，plan_time 为 08:00、16:00、次日 00:00。
- 因此引用本条判断"任务是否按时派发"前，须先确认所查周期单位：小时类任务本就是多班次分时段派发，不能据"非凌晨也有记录"或"凌晨有记录"推断异常；诊断第一步应直接核对 base_risk_task_record 的 create_time 与当前数据库时间的比较结果，而非套用本条的历史快照结论。
