## Task description
- Core requirement: 针对特殊作业 8 类票型的会签签字分工需求（外施队签操作人/负责人部分、其余公司签），先输出全量节点清单，再按用户要求收敛为"统一节点"，最终回答"是否存在某一套节点可覆盖其余全部票型节点并统一应用到所有票证类型"。
- Task background: 节点数据来自正式库 base_work_approve_config 实测（source_type 11-18 对应动火/高处/临电/受限/吊装/动土/断路/盲板，wanGong=1 为完工验收）；系统原本无"签署方"概念，一个账号可把全部节点签完，需为甲方确认提供可直接勾选的口径表。

## Execution process
1. 用 tgr-gz-vue 只读 MCP 实查 base_work_approve_config，取得 8 类票型共 28 个会签节点 + 8 个完工验收节点及 sort 顺序，形成按票型分列的确认表（含应签方草稿与歧义标记）。
2. 交叉验证 source_type 与票型编码：Grep ruoyi-common 的 SourceType.java，确认 ZY_DH/ZY_GC/ZY_LD/ZY_SX/ZY_DZ/ZY_DT/ZY_DL/ZY_MB 依次对应 11-18，另发现 19 检维修、25 一般作业在配置表中无会签节点行。
3. 按用户"就统一的节点"要求做去重归并：12 个唯一节点，结论为外施队实际只需签 1 个节点（作业负责人意见，吊装名为作业指挥意见），其余含完工验收均由公司签；"操作人"仍无任何节点。
4. 覆盖性判定：逐一比对后确认现有 8 套节点中无任一为超集，最接近的是动土票（负责人+所在单位+宽泛部门会签+审批部门），但缺审核部门意见与当班班长意见。
5. 以动土为底补 2 个节点，构造 7 行统一超集：作业负责人意见 → 所在单位意见 → 当班班长意见 → 有关水电气工艺设备消防安全等部门会签意见 → 审核部门意见 → 审批部门意见 → 完工验收，并完成原 12 节点到新 7 节点的映射验证（无缺口）。
6. 明确两个待甲方取舍点：是否保留当班班长意见（决定 7 行或 6 行版）；临电的用电单位/配送电单位意见是否并入部门会签意见。
7. 落地约束交底：改配置仅对新开票生效、旧票节点已定型；每类票型必须恰好 1 行 wanGong=1 且排在最后（APP 依赖最后一行做签字自动完工、动火火种残留挂该节点）；打印与平台推送按节点名动态渲染，无需改造。

## Notes
- "哪一套能覆盖其他"这类问题必须先做逐节点映射验证再给结论，直接凭印象挑最大集合会漏掉审核部门意见、当班班长意见这类单票型独有节点。
- 节点名称语义歧义（所在单位、用电单位、作业指挥 vs 作业负责人）不能由开发侧判定，必须在确认表里显式标出并让甲方逐行勾选，否则后续签署方校验规则建立在错误映射上。
- 签字权限现状证据链：SignatureAdapter 按 workStatus 锁定按钮（未开始阶段前 n-1 节点可任意顺序签且可重复覆盖，进行中/未验收仅末节点可签），服务端 updateBaseWorkApprove 只记当前账号昵称不校验身份，非本人非管理员打开他人票时状态被掩码导致全锁——三者叠加才构成"一人全签"的完整解释，单说"没有校验"不够准确。
