## Task description
- Core requirement: 用户问"我自己可以用测试数据库测试吗"，随后要求注释掉园区平台推送、在 MuMu 模拟器移动端亲自走一遍隐患录入，只看本地落库数据是什么样。
- Task background: 区域→装置单元防错改造（base_area_risk_unit + getAreaRiskUnits + 移动端区域优先表单）此前只落在正式库，本机后端 master 已切到测试库 192.168.250.160，测试库缺表；园区 API 地址 PlatementBaseApi.HTTPSTR="http://111.4.80.39:8092" 是 static final 硬编码常量、全工程唯一、不区分环境，测试库提交也会真推园区。

## Execution process
1. 盘点配置定位风险：Grep application-druid.yml 确认 master 生效行为 192.168.250.160（正式库行被注释）；查全局 C:\Users\Administrator\.qoder\mcp.json 发现两个 MySQL MCP——tgr-gz-vue 连 220.203.23.144 正式库只读，hc-standard-test 连 192.168.250.160 测试库且 INSERT/UPDATE/DELETE=true 但无 ALLOW_DDL_OPERATION；SELECT @@hostname 实测两库落点分别为 anwei1-0001 与 WINDOWS-3D9R3V5，确认此前所有 SQL 都执行在了正式库。
2. 推送拦截：在 BaseHiddenTroubleServiceImpl.uploadWithState 里 api.saveCheck 调用前插入 if (Boolean.TRUE) { log.warn("[临时调试-已拦截推送] ..."); return; } 阻断块，一处覆盖新增(0)/申请关闭(1)/驳回(2)/确认关闭(4)四个推送场景，本地落库不受影响；mvn -o -DskipTests -pl ruoyi-admin -am compile 通过。
3. 测试库建表：用户给 hc-standard-test 加 "ALLOW_DDL_OPERATION": "true" 后 MCP 短暂重连（报 code=50001 still connecting，Start-Sleep 8 秒后重试成功），CREATE TABLE base_area_risk_unit（COLLATE=utf8mb4_general_ci）+ INSERT 6 条区域映射；测试库比正式库少一个液氯储罐气化装置单元，液氯车间只配 1 个映射。
4. ADB 自动化：PATH 无 adb，经注册表 InstallLocation 定位 D:\Tool\MuMuPlayer，Get-ChildItem -Recurse -Filter adb.exe 找到 nx_main\adb.exe；adb connect 127.0.0.1:7555 连上 V2203A；APP com.sckj.other1 v1.1.90 当日 17:33 已更新为新包。
5. UI 操作链：screencap+pull+Read 截图定位坐标，input tap/swipe/keyevent 4 逐步操作；入口为工作台→其他工具→添加隐患（"隐患治理"页是空列表、"问题上报→上报"是另一简易上报页，均非目标）；验证表单顺序"区域→类型→类别→级别→装置单元→管控措施"、选氯化锌车间后装置单元自动带出并锁定、措施下拉按单元过滤且带"氯化锌生产装置 ·"前缀。
6. 补测试措施：测试库氯化锌单元下无"检维修作业"，从正式库 SELECT 模板记录 f37a15d7cdf511f1944cfa163e9c1bea（risk_measure_code=10026，risk_event_id 两库一致），INSERT 到测试库并置 sync_status='1' 防定时任务外推。
7. 缓存刷新：新措施插入后下拉仍无该项——mListMeasure 非空即不发请求，必须重新选一次区域触发 onAreaChanged 清空缓存才拉到新列表；下拉弹窗还需在弹窗内 swipe 滚动才能看到第 11 位的检维修作业。
8. 提交与必填项：两次点击"添加"失败分别因缺"整改标准"和"整改建议"（toast 需在点击后 ~1.2 秒内截图捕捉）；补齐后提交成功，弹"是否添加举一反三"点取消。
9. 落库核验：测试库 base_hidden_trouble 新增 id=689（YH-20261022-01，area_id=649 氯化锌车间，measureId=f37a15d7...，measureId_str="氯化锌生产装置 · 检维修作业"，sync_status='0'、sync_result=null 证明未推送）；反查 measure→event→unit→obj 得单元=氯化锌生产装置、hazardCode=420510077704、deviceLevel=900（非重大危险源），对照旧 731 误挂液氯气化仓库（420510077002、一级重大危险源）证明改造有效。
