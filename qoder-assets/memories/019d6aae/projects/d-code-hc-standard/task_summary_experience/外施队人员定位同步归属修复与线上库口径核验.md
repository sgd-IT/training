## Task description
- Core requirement：用户指示"你看线上库"后确认外施队（承包商企业）人员进入园区人员定位基础信息表并与作业票 operatorId 同源的可行性，随后要求"执行，记得把推送注释"，即落地定位同步改造且不得打开园区推送。
- Task background：上一轮基于测试库（192.168.250.160）得出"外施队不在定位系统、sync_id 为雪花不可用"的判断；线上正式库（220.203.23.144）实际数据形态未知，且 syncContractorPeople 存在把命中人员改挂 contractor_id=1001 的破坏点。

## Execution process
1. MCP 落点甄别：项目 mcps 缓存目录只列出 hc-standard-test（连 192.168.250.160，返回 db=tgr-gz-vue、host=WINDOWS-3D9R3V5），并非线上库；改读 SharedClientCache/extension/local/mcp.json 发现同名服务 tgr-gz-vue 指向 220.203.23.144:3306 且 enabled，直接以该 serverName 调用 mysql_query 成功取到线上数据（缓存目录未列出该服务不代表不可用）。
2. 线上取证结论：base_contractor 有 1001 源洹（company_type=1）+1039 华直/1040 盛廷建设/1041 晟玮机械（type=2）；三家承包商企业名下人员数为 0；1001 名下 136 人 sync_id 与 outid 完全相等（sync_ne_out=0）、132 人有定位卡；practitioners.sync 与 locationTask.getLocation 均为每 10 秒 status=0（启用）。
3. operatorId 形态×结果分组统计（线上 base_work_special）：UUID 成功 72 条/失败 12 条/未推 21 条，雪花成功 0 条/失败 39 条 → 线上口径本来就是 sync_id=outid，测试库的雪花形态不代表线上。
4. 发现两类失败样本：DZ-20260923-0002 与 GC-20260923-0001 报"作业人员信息格式错误，多人用英文分号隔开"，其中 operatorId 已用逗号连接多人；核对工作区 PlatementTicketNewApi.transformOperatorInfo 已实现分号拼接，属本地未提交改动待部署。
5. BaseContractorPeopleMapper.xml#updateBaseContractorPeopleByPhone：SET 改为只回填 position_card_no，dept_name 仅在本地为空时补，去掉 contractor_id/status/id_card_no 覆盖，WHERE 补 del_flag='0'。
6. BaseContractorPeopleServiceImpl#syncContractorPeople：接口返回空数组时直接 return（原逻辑会先清卡）；注释掉 clearPositionCard() 全表清卡；手机号未建档时只打日志跳过，删除按 1001 兜底 insert 与 worktype 写进身份证号的分支。
7. ruoyi-ui/src/views/base/contractorPeople/index.vue：实读发现列表页"新增"按钮已存在（非注释状态），只需 submitForm 新增分支置 this.form.status = 3（选人 SQL 要求 status=3），并删除修改分支强制 status=1 的重置（编辑一次即从选人列表消失）。
8. 编译验证：mvn -pl ruoyi-system -am compile -DskipTests 通过，target class 文件时间戳更新；GetProblems 因语言服务器未就绪无法给出诊断。
9. 推送处理：PlatementBaseApi.PLATEMENT_PUSH_ENABLED 保持 false，本次未新增或打开任何园区 HTTP 推送调用；syncContractorPeople 末尾 AliMQTTClient.pushType 属内部 websocket 通知 APP 刷新人员列表，非园区推送故保留。

## Notes
- 用 MCP 服务名判库别不可靠：hc-standard-test 与 tgr-gz-vue 默认库名同为 tgr-gz-vue，必须 SELECT @@hostname / DATABASE() 实测落点；项目 mcps 缓存目录未列出的已启用服务仍可直接调用。
- 前一轮基于测试库的"外施队不在定位系统""sync_id 是雪花所以 operatorId 必失败"两条判断在线上库均不成立，跨环境结论必须先切库重取，不能沿用旧库数据。
- 语言服务器未就绪时 GetProblems 无输出，Java 改动须回落 mvn 编译 + class 时间戳双重确认。
- 线上 practitioners.sync 为 10 秒启用态，一旦录入外施队人员约 10 秒即真实推送到园区从业人员库，本地联调不会复现该行为，验证节奏须按线上口径安排。
