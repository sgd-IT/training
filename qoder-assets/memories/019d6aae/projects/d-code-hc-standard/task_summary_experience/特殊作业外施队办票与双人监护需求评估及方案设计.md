## Task description
- Core requirement: 对甲方提出的两项特殊作业需求（43：外部施工队可独立办理作业票；44：强制要求双人监护且内外各一人）进行系统性评估，并给出落地口径与执行方案。
- Task background: 需求涉及 PC 端、移动端、后端及园区平台对接；核心卡点在于 APP 选人组件 DialogWorkPeopleMultiple 的数据源 getWorkPeopleList(contractorId,...) 仅支持单 contractorId 查询，导致无法同时选择公司内部人员与外施队人员；现有数据中承包商企业名下无人员，需前置录入。

## Execution process
1. 盘点取证：使用 tgr-gz-vue 只读 MCP 查证 base_contractor_people 数据，确认 1001（源洹实业）有 136 人，1039/1040/1041（三家承包商）人员数为 0；实查 base_work_approve_config 获取 8 类票型会签节点；确认 company_type 字段（1=内部、2=承包商）是现成的内外判定依据。
2. 根因定位：需求 43 的真实卡点是 APP 选人范围受限于 contractorId 单值，而非账号体系缺失；需求 44 的实现前提是必须放开选人范围，否则无法选出“公司1人”。
3. 方案设计：提出后端接口扩展（支持多 contractorId）、APP 弹窗增加单位切换、监护人软提示校验三步走方案；明确数据准备（PC 端恢复 contractorPeople 新增按钮并录入人员）为前置依赖。
4. 执行路径：确定执行顺序为：① 恢复 PC 端人员录入入口 → ② 后端接口扩展 → ③ APP 选人弹窗改造 → ④ 监护人软提示校验。
5. 交付物：产出包含逐条评估、总量估时、关键路径排期与甲方确认清单的《需求澄清清单》。
