## Task description
- Core requirement: 检测需求27"一次报备可同时勾选多种作业类型"的实现完成度，并回答"作业票和报备类型是否都支持多选"
- Task background: 需求备注称园区接口每条只接受一种作业类型，多选上传方案待定；需盘点PC/APP/后端/DB四层的实际实现状态

## Execution process
1. PC端(ruoyi-ui/views/base/TicketBb/index.vue)：作业类型改为多选 typeLevels(类别-级别组合)，同类别限一个级别(选新级别自动替换旧)；单选走 addTicketBb，多选走 batchAddTicketBb(/base/TicketBb/batch)
2. APP端(other1 ActivityWorkReport + Dialog_WorkType)：多选弹窗同样同类别互斥；多选走 batchAddTicketBb
3. 后端(BaseTicketBbServiceImpl)：双端点(PC /batch、APP /batchAddTicketBb)按类型拆分为多条独立单类型报备，共享 batchNo(DateUtils.dateCodeNu...)、列表组装"同批"摘要 batchSummary；每条按园区要求单类型逐条上报(即需求备注"多选后如何上传"的解法：本地拆单+平台逐条收)
4. DB：base_ticket_bb.batch_no 列(varchar64,注释"一次提交按类型拆单的同批标识")正式库已就绪；变更清单已登记
5. git：9-21~9-24共4个提交(核心拆单/双端接口/PC多选/表单管理修复)均已入库
6. 生产实测缺口：base_ticket_bb 88行(72有效/16删除)中 batch_no 非零计数为0，且报备自2026-09-13后再无新增 → 功能从未在生产端到端跑过
7. 作业票侧结论：一张票一个类型(不支持多选)——8类各有独立入口/表单/编号前缀(DH/GC/SX)/审批流/安全措施/平台逐张报送；PC workSpecial为管理页新增也是单类型文本项；便利在报备层(报一次拆N条单类型报备各生成各票)
