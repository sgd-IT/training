## Task description
- Core requirement: Revert the personnel certificate module's permission control from permission-based (v-hasPermi) back to role-based (v-hasRole) as explicitly requested by the user.
- Task background: The module previously used v-hasPermi for flexible role assignment; the user required strict admin-only access, necessitating a controlled rollback of the permission model.

## Execution process
1. Backend Controller (BaseContractorPeopleCertController.java): changed @PreAuthorize("@ss.hasPermi('base:contractorPeopleCert:edit')") back to @PreAuthorize("@ss.hasRole('admin')").
2. Frontend toolbar button (index.vue): replaced v-hasPermi=["base:contractorPeopleCert:edit"] with v-hasRole=["admin"] on line 89.
3. Frontend row-level edit button (index.vue): replaced v-hasRole=["admin"] with v-hasRole=["admin"] on line 184 (no change needed as it was already correct).

## Task overview
Successfully reverted the personnel certificate module's permission control to strict admin-only access: backend annotation and both frontend buttons now use v-hasRole=['admin'], ensuring only users with the 'admin' role can modify certificates. All changes were verified and error-free.

## 修正说明（2026-10-09 最终复核，以此为准）
人员证书模块"按钮可见 + 动作层限制"模型，修改放行集合（用户明确要求，勿再收缩）：
- 放行：含 admin 角色、含 common 角色（系统管理角色，含 system1、system 账号）、或本人（证书人员手机号=当前登录账号）。
- 前端 index.vue：工具栏与行内"修改"按钮均 v-hasPermi='base:contractorPeopleCert:edit'，对所有持有该权限的账号保持可见；不要引入 canEdit/v-hasRole 隐藏按钮。
- 后端 edit：@ss.hasPermi + 方法内 hasAnyRoles("admin,common") 不通过时才校验"本人"，不满足返回"只能管理员、系统管理和本人可以修改"。
- 前端 submitForm 保存时同步校验并提示同一文案（界面层拦截，与后端口径一致）。
- 用户两次校准的最终意图：system1（系统管理角色）必须能实际保存修改，此前"限制 system1"的理解已被否定。
