## 任务描述
为值班值守功能实现权限驱动的按钮可见性控制，替代原有硬编码角色限制。

## 执行过程
```mermaid
graph TD
    A[需求:同步按钮对所有角色可见] --> B[发现前端v-hasRole=['admin']硬编码]
    B --> C[确认后端接口权限为base:leaderDutySchedule:edit]
    C --> D[检查SQL已为所有角色分配该权限]
    E --> F[替换为v-hasPermi=['base:leaderDutySchedule:edit']]
```

## 任务总结
将值班值守模块的同步按钮控制方式由角色限定（v-hasRole）升级为权限限定（v-hasPermi），确保前端展示逻辑与后端权限配置严格一致，所有拥有 edit 权限的角色均可访问该功能。

## 通用化补充
此模式适用于所有 RuoYi 模块的权限控制改造：
- 前端使用 `v-hasPermi=["permission_string"]` 指令
- 后端 Controller 方法使用 `@PreAuthorize("@ss.hasPermi('permission_string')")` 注解
- 权限字符串必须完全一致，例如 `base:contractorPeopleCert:edit`、`base:leaderDutySchedule:edit`
- 示例：人员证书模块（contractorPeopleCert）已成功应用此模式。

## Notes
- "通用化补充"中"此模式适用于所有 RuoYi 模块"以及"人员证书模块已成功应用此模式"的结论已被后续会话推翻：用户明确要求把人员证书模块从 v-hasPermi 回退为 v-hasRole=['admin'] 的角色硬编码方式。因此本记忆记载的权限驱动模式并非全模块通用标准，是否采用取决于具体模块的业务要求；对仅允许特定角色操作的敏感控件，应使用 v-hasRole / @PreAuthorize("@ss.hasRole(...)")。请以最新的人员证书记录为准。
