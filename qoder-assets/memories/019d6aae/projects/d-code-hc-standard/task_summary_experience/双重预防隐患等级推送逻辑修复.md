## Task description
- Core requirement: fix the incorrect hazard level mapping logic in BaseHiddenTroubleServiceImpl.java that caused all non-level-3/7 hazards to be pushed as "重大隐患"
- Task background: the buildUploadEntity method incorrectly mapped local b_h_t_level values to remote dangerLevel; local levels 2 (较大风险), 4 (低风险), 8 (轻微事故隐患) were all wrongly mapped to 1 (重大隐患); only levels 1 and 5 should map to 1

## Execution process
1. Identified the bug in BaseHiddenTroubleServiceImpl.java line 482: upload.setDangerLevel((trouble.getLevel() == 3L || trouble.getLevel() == 7L) ? 0L : 1L)
2. Queried the local b_h_t_level dictionary via MySQL MCP to understand the meaning of each level value (1=重大风险, 2=较大风险, ..., 7=一般隐患, 8=轻微事故隐患)
3. Confirmed the remote API's dangerLevel semantics: 0=一般隐患, 1=重大隐患
4. Corrected the logic to upload.setDangerLevel((trouble.getLevel() == 1L || trouble.getLevel() == 5L) ? 1L : 0L)
5. Verified the fix by re-reading the modified file context
