## Task description
- Core requirement: 用户反馈"移动端选择的时候没有显示合理"，要求隐患录入的装置单元选择变得合理，并配套可维护的归属配置。
- Task background: 此前移动端表单顺序是"先选管控措施、再让人自己挑装置单元"，且单元列表是全公司全量；库内不存在区域到装置单元的任何映射（base_area 只有空的 equipment_id），后端对区域与措施的组合零约束，导致隐患被挂到错误装置并被园区平台判定关联重大危险源。

## Execution process
1. 新建映射表脚本 ruoyi-admin/src/main/resources/sql/base_area_risk_unit.sql，字段 area_id / risk_unit_id / order_num / remark，唯一键 uk_area_unit(area_id, risk_unit_id)。
2. 后端新增 com.ruoyi.base.domain.BaseAreaRiskUnit、BaseAreaRiskUnitMapper（接口 + XML，list 查询 left join base_risk_unit 与 base_risk_obj 带出 deviceName）、IBaseAreaRiskUnitService、BaseAreaRiskUnitServiceImpl：resolveByAreaId 从录入区域沿 base_area.parent_id 逐级向上找**最近一条**已配置映射（深度上限 20 防环），配了子区域则以子区域为准，未配则继承祖先；insert 时 orderNum 为空默认 0。
3. BaseAreaRiskUnitController 提供 /base/areaRiskUnit 的 list/getInfo/add/edit/remove 以及 GET /resolve/{areaId}，权限标识 base:areaRiskUnit:*。
4. ApiHiddenController 新增 POST /api/hidden/getAreaRiskUnits?areaId= 供 App 调用。
5. BaseHiddenTroubleServiceImpl 注入 IBaseAreaRiskUnitService，提交时对 area → unit → measure 做一致性校验：仅当该区域解析出非空映射时才拦截，映射为空回退放行（灰度策略）。
6. App 侧 HttpInterface 增加 getAreaRiskUnits；RiskUnitBean 增加 riskUnitId 字段并新增 unitIdOf()（优先取 riskUnitId，兼容全局单元接口返回 id 的老口径）；ActivityAddHiddenDanger 新增 onAreaChanged / loadAreaRiskUnits / checkTaskUnitAgainstArea，unitDisplayName 在装置名与单元名相同时不重复拼接；改区域即清空已选措施；问题上报预填区域路径用 viewBinding.getRoot().post() 延迟触发避免 onCreate 期弹 loading 异常。
7. 布局 activity_add_hidden_danger.xml：把 item_unit（隐患区域）从第二张卡片移到第一张卡片最前，删除重复分隔线，形成"区域 → 类型 → 类别 → 级别 → 装置单元 → 管控措施"顺序。
8. 前端新增 api/base/areaRiskUnit.js 与 views/base/areaRiskUnit/index.vue（el-tree-select 配 normalizer 处理 areaId/children、装置单元下拉 pageSize 1000）。
9. 菜单脚本 base_area_risk_unit_menu.sql：以 MAX(menu_id)+1 为基址插入 1 个 C 菜单 + 4 个 F 按钮（parent_id 指向该 C 菜单），并按项目约定 CROSS JOIN 授权给所有 status='0' 且 del_flag='0' 的角色，NOT EXISTS 去重。
10. 更新 sql/待上正式库变更清单.md 第 3 节记录建表与菜单脚本及执行顺序。
11. mvn -o -DskipTests -pl ruoyi-admin -am compile 两次通过。
