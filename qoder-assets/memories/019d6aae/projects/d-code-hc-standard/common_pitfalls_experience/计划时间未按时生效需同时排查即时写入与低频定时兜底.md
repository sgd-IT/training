Bug class: 录入的计划生效时间与实际状态变更时间不一致（出现小时级甚至约24小时延后），并伴随提前生效。

Root cause: 此类偏差几乎总是两处独立成因叠加，只查其中一处必然漏诊。其一是写入路径无条件即时生效——新增记录的服务方法不比较用户输入的 stopTime 与当前时间，直接更新主表状态并联动子任务，导致未来的计划立即生效；其二是到点校正依赖低频定时任务——自动启停逻辑挂在每天固定几个时点的 @Scheduled 任务上（如 23:30、6:00），实际切换时刻被吸附到下一个调度点，最大延迟接近调度周期。

Fix pattern: 写入侧改为条件生效（仅当计划时间 <= now 才立即改状态，未来时间只落库不改状态）；调度侧把纯本地状态校正拆成高频独立任务，与含外部推送的同步任务分离，保持原同步节奏不变。

Reusable lesson: Don't 只提高定时任务频率或只改写入判断就宣布问题修复，因为双成因下任一改动都只消除一半偏差；instead 同时核对"新增/编辑记录时的即时状态写入分支"与"定时任务的调度时点集合"两处代码。适用于存在"按计划时间自动切换状态 + 定时任务兜底"结构的模块（如 hc-standard 风险单元 base_risk_unit_log / autoSyncUnitStatus）；不适用于状态由人工单次操作直接确定、无定时兜底的场景。
