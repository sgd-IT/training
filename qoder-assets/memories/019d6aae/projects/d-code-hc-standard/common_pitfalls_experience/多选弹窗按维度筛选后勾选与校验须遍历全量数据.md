Bug 类：多选弹窗切换"分类维度"后，已勾选的人被静默丢弃、或校验误报人数不足。

根因（两类并存，改动前先分辨所在分支）：
① 回传/校验遍历"当前显示的列表"，而按维度筛选时该列表只含当前一类人员，另一类已勾选的 bean 不在其中；
② 维度项分两条代码路径——走本地过滤（如 applyData，复用同一批 bean，setShow(true) 保留）与走重新请求接口（如 setSearchPeople → setData 内 allPeople.clear() 重建全部 bean 且 show 全为 false），后者会直接清空所有已勾选状态；同维度内连续点击列表项不会重排，勾选本身是稳定的。

影响：切到"本公司"后点确定，之前勾的"承包商"人员不会回传；人数统计也会少算，弹出错误的"至少 N 名"提示。

修复模式：setData 时把全量 bean 存到 allPeople，展示层按筛选条件渲染到 visibleList；勾选回传、规则校验一律遍历 allPeople，只有 RecyclerView 绑定用 visibleList；维度切换统一改走本地过滤，禁止因筛选项而重发请求重建 bean。

适用边界：任何"列表可分组/可筛选 + 多选累加"的弹窗都适用，包括分组标题行（header 需在点击回调里拦截，且不参与统计）。
