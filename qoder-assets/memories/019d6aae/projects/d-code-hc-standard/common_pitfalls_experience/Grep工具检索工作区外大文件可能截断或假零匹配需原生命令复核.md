Bug 类：用 Grep 工具检索工作区外的大文件（如桌面上数百 KB 的 sys-info 服务日志）时，返回结果可能被截断（同文件同模式只返回前若干条匹配，漏掉文件中后段的匹配），甚至出现"假零匹配"（文件中确实存在的字符串返回 0 匹配）。
根因：外部大文件疑似走非标准扫描路径，存在结果上限或异常处理，具体机制未明；与 .gitignore 无关（文件在工作区外）。
修复模式：当检索结果与预期不符（结果为 0 或明显偏少）时，改用原生命令复核：findstr /C:"literal" 文件路径 做精确匹配，配合 (… | Measure-Object).Count 计数；或 Select-String -Path 文件 -SimpleMatch；多模式分开统计。本次实证：同一日志文件同一模式，工具返回 0 匹配但 findstr 统计出 42 处。
教训：对"日志中不存在 X / 共 N 处"这类关键结论，必须用原生命令二次确认后再下结论，不能只凭工具单次结果。适用边界：工作区内常规源码检索结果正常，疑似仅在大型外部文件上触发。
