Bug class: 周期性派单任务的执行日逐日后移（星期漂移），被误判成"周期配置不生效"或"定时任务没跑"。

Root cause: 周期推进的基准取"程序运行那一天"而不是上次的计划时间，同时存在外部入口（状态启用/停启联动）会把下次执行时间无条件重置为当天。实测 hc-standard 液氯气化仓库 10 条 7 天周期任务轨迹为 周四(01-29~07-23) → 周二(07-28~09-22) → 周一(09-28~10-05) → 周五(10-09~10-16)，各段内部严格 7 天、只有段首间隔变成 5/6/4 天；三次段首与 base_risk_unit.update_time、base_risk_unit_log.activationTime 以及 updateStatusByUnitId 写入的 `task_next_time = CURDATE()` 逐一对齐（如 10-08 11:02:58 启用 → 10-09 起永久变周五，且不会自行回到原星期）。

Fix pattern: 生成侧把递推基准换成"下次执行时间字段本身"（错过周期需循环补生成），启用/停启联动侧去掉对下次执行时间的无条件重置（只在首次建档初始化，或引入真正参与计算的锚定起始日字段）；存量数据须单独对齐一次锚点，否则改完逻辑仍从旧基准继续滚。

Reusable lesson: Don't 一看到"日期不固定"就去查 cron 表达式或断定调度器漏跑，因为 cron 正常时该假设会引向无效改造；应先按执行日聚合相邻记录间隔做指纹判定——**段内等距、仅段首一次突变 = 基准被外部写入口重置**（去比对主表 update_time 与子表启停/联动记录时刻），**全程等距但相对预期整体偏移 = 首次锚点选错**，**整段间隔不规则且伴随缺日 = job 漏跑**。适用于任何"按计划时间自动递推 + 存在状态启停联动"的周期任务模块（如风险单元排查任务、值班排班、定期巡检）；不适用于单次人工触发、无下次执行时间字段的状态机。
