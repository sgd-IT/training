Bug 类：园区平台"分析对象"（/openapi/risk_device/saveOrUpdateBatch）同步被**整批拒绝**，报"危险源编码重复"，导致一批装置数据长期推不上平台。

根因（2026-10-10 sys-info 日志实证）：本项目存在两个不同风险装置共用了同一个 hazardCode（420510077703）——对羟基本甲腈装置与污水预处理平台。平台侧 hazardCode 唯一，批量接口遇重复键时不做部分成功而是整批退回；因此同批次里本身完全正常的装置（含氯化锌生产装置等共 5 个）也一并同步失败，sync_status 长期停在未成功状态。表现为"很多装置都推不上去"，容易被误判为平台接口故障或鉴权问题。

修复模式：先按 hazardCode 分组反查本地库找出重复归属（GROUP BY hazard_code HAVING COUNT(*)>1），只修正其中一台装置的编码使其业务上真实唯一，再重推该批次；不要改推送代码、也不要怀疑平台。校验口径：修完后看该批次返回是否从"编码重复"整批报错变为逐条成功，且无关装置的 sync_status 同步转好。

Reusable lesson：Don't 把"批量推送整批失败"归因于推送链路或平台可用性，因为平台对唯一键冲突的处理是整批退回，真正缺陷在本地存量数据的编码重复；instead 先做唯一键重复性反查再谈改造。Applies when 任何 saveOrUpdateBatch 型平台接口返回"XX重复/已存在"类整批错误；does not apply to 单条推送报字段缺失/必填为空的场景（那是各条记录自身数据问题，须逐条修）。另注意：本类历史数据债会随每次自动同步反复重试而持续占用日志，排查时应区分"当前新引入的失败"与"存量重复导致的常驻失败"。
