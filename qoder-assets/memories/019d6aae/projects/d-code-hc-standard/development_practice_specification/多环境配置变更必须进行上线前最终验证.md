涉及多环境配置（移动端 API 地址、后端数据库连接等）的变更，必须在上线前/Git 提交前的最终验证阶段执行回切核验，确认所有配置已从开发/测试地址改回生产地址，防止服务调用错误或数据写入错误库。该实践源于用户对生产环境安全的明确关切："不影响到生产环境运行吧"。

回切核验范围不止配置文件，还须覆盖代码内的推送总开关与硬拦截分支（如 skipPush / mockSuccess、`if (Boolean.TRUE) return` 之类的调试兜底），以及实际打包产物里的配置（避免开发配置随 jar/APK 带上线）。

核对方式必须以读盘证据为准：逐文件确认当前未注释的生效行（同一常量常有多条候选地址处于注释态），不能凭记忆或在编辑器视图假定；改动未按 Ctrl+S 落盘时重新打包出的仍是旧地址。移动端 API 生效点在 HttpInterface.java 的 IP 常量，后端数据源生效点在 application-druid.yml 的 master 段。

对"是否入库"的取舍：编译前提类配置（新增依赖的 pom.xml）不入库会让他人拉取后编译失败，此时应主动向用户提示并由其拍板例外入库，而非机械套用配置文件排除约定。适用于所有包含多环境配置的项目；当配置管理方式改为集中式外部化配置时需重新评估本流程。
