业务层推送操作必须添加结构化日志：每条日志需包含可定位的关键业务字段（如 outerId、workNo），并标注明确语义标签（如 [推送作业票-保存]、[推送视频-开工]），确保推送行为全程可追踪、可审计。

## 适用范围扩展
日志改造（含设备类组件，如水听器的日志优化）必须以「后期可追溯」为验收标准：关键节点（入口、外部调用前后、结果判定、异常分支）都要留痕，且每条日志须携带能唯一定位到具体设备/业务对象的字段（设备编号、报文流水号、时间戳），禁止只打印无上下文的描述性文本；异常路径必须完整输出堆栈与上下文参数，否则生产环境无法回溯问题。
