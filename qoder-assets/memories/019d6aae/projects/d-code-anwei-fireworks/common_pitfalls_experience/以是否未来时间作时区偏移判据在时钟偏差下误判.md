Bug class: 时区偏移判据对时钟偏差敏感导致时间还原错误（表现为记录比实际早整 8 小时，或修复后数据仍被静默丢弃）

Root cause: 采集端/客户端与云端服务器、设备三者时钟不可能精确同步（现场实测设备比采集机快 30~48 秒）。用"加 8 小时后是否晚于当前时间"来判断"设备是否已在北京时区"，会把"正确还原后的时间 + 几十秒钟差"当成未来时间而判定不该加 8，结果上报 UTC 值；反向地，原始无条件 +8 又会让钟差把合法时间推成云端的"未来"而被丢弃。两类故障同源：判据本身依赖了不可靠的本地时间比较。

Fix pattern: 判断是否需要时区偏移改用"时差量级"而非"是否未来"——当 |当前时间 - 事件时间| 大于一个明确阈值（如 4 小时，足以区分 8 小时级时区差与分钟级钟差）才施加偏移；偏移之外单独再加一道一次性的防未来兜底（若结果仍晚于当前时间则取当前时间），保证不会因钟差被后端"未来时间"校验丢弃。参考实现位置：netsdk 采集端 EventHandler 人闸事件时间处理。

Reusable lesson: 不要用"计算结果是否晚于当前时间"来推断数据的时区属性，因为几十秒级的时钟偏差就足以翻转判断，必须用时差量级阈值判时区、并单独加防未来兜底保数据不丢。适用于任何"设备/采集端时间字段需还原为北京时间再上报，且接收端会拒绝未来时间"的链路；不适用于三方时钟由 NTP 严格同步且偏差可忽略的环境，也不适用于事件时间无需时区还原的数据源。
