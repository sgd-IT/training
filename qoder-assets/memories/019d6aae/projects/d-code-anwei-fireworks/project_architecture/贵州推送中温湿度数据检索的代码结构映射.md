贵州推送系统中，温湿度数据检索逻辑由以下三个核心方法构成，形成明确的 extension-point map:
- ZBSS (监测指标实时数据): saveInfoTargetRealtime() in PushingGZDataService.java queries Temperature and Humidity tables using device codes from em_device_info where device_type IN (3, 4, 8)
- ZBBJ (监测指标报警): saveInfoTargetAlarm() in PushingGZDataService.java queries em_early_warning_info_push_record for warning_type=0 (humidity) or warning_type=1 (temperature)
- BJCZ (报警处置): saveInfoTargetDisposal() in PushingGZDataService.java queries the same em_early_warning_info_push_record table for disposal records
All three methods are triggered sequentially by UploadGZScheduledJob.java. The implicit invariant is that device_type=3 maps to temperature sensors, device_type=4 to humidity sensors, and device_type=8 to combined temp+humidity sensors — this mapping drives all downstream data retrieval.
