netsdk 采集端（fireworks-dhsdk-local 分支）接收的大华门禁/闸机事件中，SDK 回调给出的事件时间字段是 UTC 化的值，比北京时间早 8 小时；而设备本身的 Web 管理页（如出口人脸设备 10.153.27.12 的系统管理→时间设置）显示的时间与时区配置（UTC+8）都是正确的。因此 EventHandler 里对事件时间做 +8 小时偏移是还原北京时间的正确做法，不能因为"设备已在北京时区"就取消该偏移。

配套约束：云端后端 prod 分支 DaHuaService 对晚于服务器当前时间的 eventDate 会静默丢弃，而现场设备时钟可能比采集机/云端快几十秒，故 +8 后仍需一道"结果晚于当前时间则取当前时间"的防未来兜底；判断是否应加 8 应用"与当前时间的时差量级"（偏差约 8 小时才加），不可用"是否未来"作判据。

适用边界：仅针对 netsdk 大华 SDK 事件回调的时间字段；其他厂商设备或 HTTP 直传数据的时间语义需单独确认。
