netsdk 大华采集端（fireworks-dhsdk-local）与平台后端在闸机数据上的职责划分（已实测验证）：

1. 人闸进出方向由平台侧决定：DaHuaService 按 em_gate_device_info 的 device_type（1=进/2=出）判定 in_out_state，匹配条件是上报 devSno 包含表内 device_code；采集端无需也无法为人闸配方向。因此新企业接入时必须核对 em_gate_device_info.device_code 是否为真实设备 SN——若被填成中文名称（如"人脸识别进"），contains 永不命中，该设备人闸记录 in_out_state 恒为 NULL。
2. 车闸进出方向由采集端决定：后端 saveCarInoutRecord 的方向会被 setInOutState(recordVo.getStatus()) 覆盖为采集端上报值，而该上报值来源是现场 application-prod.yml 中每台车闸的 per-device carInOrOut（车辆入口=1、车辆出口=2），代码遍历 dh.configs 按 deviceCode 匹配，未配置才回退全局 dh.carInOrOut。EventHandler 内不存在设备 SN 到方向的映射表。
3. IP 音柱不属于采集端配置范围：音柱由平台语音播报服务直接调用其 IP 接口控制，application-prod.yml 的大华设备 configs 列表里不登记音柱 IP 是正常状态，排障时不应在采集端找音柱配置。

改造方向字段时的下手位置随之确定：改人闸方向动设备管理表/后端，改车闸方向只动现场 yml 并重启采集端。
