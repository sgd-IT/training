## Task description
- Core requirement: determine whether Guizhou (贵州) push of "联网指标信息" (network indicator information) involves temperature/humidity tables and locate the corresponding code.
- Task background: Guizhou push uses 6 data types: ZBDY (indicator definition), ZBSS (realtime indicator data), ZBBJ (alarm), BJCZ (disposal), RYCRJL (person entry/exit), CLCRJL (vehicle entry/exit); ZBSS, ZBBJ, and BJCZ are the ones pulling from actual temperature/humidity data sources; device types 3 (temperature sensor), 4 (humidity sensor), and 8 (temp+humidity sensor) drive the flow; PushingGZDataService.java is the core implementation class.

## Execution process
1. Searched codebase for "贵州推送联网指标温湿度" → identified PushingGZDataService.java, SetGZUploadInfo.java, and UploadGZScheduledJob.java as key files.
2. Confirmed saveInfoTargetRealtime() (ZBSS) queries Temperature and Humidity tables for latest realtime readings.
3. Confirmed saveInfoTargetAlarm() (ZBBJ) and saveInfoTargetDisposal() (BJCZ) query em_early_warning_info_push_record for humidity (warning_type=0) and temperature (warning_type=1) alarms.
4. Verified device type mapping: 3 = temperature sensor, 4 = humidity sensor, 8 = temp+humidity sensor.
5. Identified UploadGZScheduledJob.java as the scheduled job entry point that triggers all push methods.
