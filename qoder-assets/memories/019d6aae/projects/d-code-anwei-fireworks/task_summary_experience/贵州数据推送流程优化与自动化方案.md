## Task description
- Core requirement: 优化贵州数据推送流程，解决当前对接流程过于繁琐的痛点
- Task background: 贵州推送采用SFTP文件上传方式，需处理复杂的编码转换、ZIP打包、附件管理；当前测试阶段需手动修改access_status状态，操作繁琐易错；不同数据类型使用不同的access_status值（0/1），缺乏统一管理

## Execution process
1. 贵州推送access_status环境配置化：生产环境默认使用access_status=0过滤未推送数据；测试环境通过配置项`monkey.gz_access_status_filter=1`可切换为重推已推送（access_status=1）的数据
2. GZ数据推送测试状态自动化初始化：通过SQL脚本或代码配置驱动的方式批量设置待推送记录的状态，禁止手动逐条修改
3. 贵州推送access_status查询参数化：将所有硬编码的access_status=0查询条件重构为通过Spring @Value注入的配置属性`gzAccessStatusFilter`，实现配置驱动开发
4. 统一修正PushingGZDataService.java中全部13处数据推送方法的access_status查询条件，将错误或临时使用的.eq(accessStatus, 1)全部改为.eq(accessStatus, 0)
