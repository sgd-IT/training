## Task description
- Core requirement: 将 fireworks-dhsdk-local 采集端车闸进出方向的来源由代码内硬编码映射改为现场配置文件按设备指定，并完成提交推送；同时核对新接入企业（company_code=3708324436）的设备 IP-角色-编码对应关系，交付设备管理表脏编码修正 SQL。
- Task background: 先前实现为 EventHandler 内静态 CAR_IN_OUT_MAP 按设备 SN 登记方向 + 全局 dh.carInOrOut 兜底，每接一家新企业都要改代码重打包，导致新企业两台车闸未登记时方向全部回退"进"。用户明确要求本次不做硬编码。

## Execution process
1. src/main/java/com/netsdk/config/DhConfig.java：新增 per-device `carInOrOut` 字段（车辆入口=1、车辆出口=2），未配置时回退全局 dh.carInOrOut 以兼容存量配置。
2. src/main/java/com/netsdk/module/handler/EventHandler.java：删除静态 CAR_IN_OUT_MAP 硬编码映射；getCarInOrOut 改为遍历 dh.configs 按 deviceCode 匹配各设备自身的 carInOrOut，匹配不到才回退全局值。
3. 新企业设备清单三方核对一致（现场照片 / yml 配置 deviceCode / em_gate_device_info 登记）：人脸识别进 10.153.27.13→CC0D710PAJA7853（id=299，device_code 被误填为中文"人脸识别进"）、人脸识别出 .14→CC0D710PAJ57A7C（id=300）、车辆道闸进 .12→CA07FB9PAJDE262（id=301）、车辆道闸出 .11→CA08799PAJ5FBB8（id=302）、音柱 .10 不需进采集端配置（平台直接调用音柱接口）。
4. 交付 anwei_mon_fireworks 库修正 SQL：SELECT 前置确认 → UPDATE em_gate_device_info SET device_code='CC0D710PAJA7853' WHERE id=299 AND company_code='3708324436' AND device_code='人脸识别进'（影响行数须为 1）→ SELECT 后置验证；命令行执行需加 --default-character-set=utf8mb4 否则中文条件匹配不到。
5. 按单文件最小单元分两次提交（先 DhConfig 后 EventHandler，保证每个提交可独立编译），提交信息用 UTF-8 无 BOM 临时文件经 git commit -F 传入：025725b9 `feat(dhsdk): 配置支持按设备配置车闸进出方向`、b7a2a4d2 `refactor(dhsdk): 车闸方向改为按设备配置读取，移除硬编码映射`。
6. 快进推送 origin/fireworks-dhsdk-local（5bb2fd64..b7a2a4d2），并用 git ls-remote 确认远程 SHA 等于本地 HEAD；pom.xml 及 jar 的工作区改动按惯例不提交。

## Notes
- 删除硬编码映射的固定迁移代价：所有已上线企业的现场 application-prod.yml 必须为每台车闸补 carInOrOut（旧企业同样要补），否则该企业车闸方向退化为全局值；排障时应先看现场 yml 而不是找代码里的映射表。
- 提交前必须先向用户展示待提交文件完整清单与每条提交的标题+正文全文，得到明确"确认"后才执行 add/commit/push；构建配置文件（pom.xml）与未跟踪杂项不进提交。
- em_gate_device_info.device_code 若被填成中文名称，后端 devSno.contains(device_code) 永不命中，该设备人闸记录 in_out_state 恒为 NULL，接入新企业时需逐条核对是否为真实 SN。
