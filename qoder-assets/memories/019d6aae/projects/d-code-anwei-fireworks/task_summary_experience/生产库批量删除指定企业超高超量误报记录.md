## Task description
- Core requirement: 删除今天与昨天（2026-10-28 ~ 10-29）"超高超量"类型的误报警记录
- Task background: 前端"报警管理"页面被雷达每约 2 分钟误触发的超高报警刷屏；需先确认数据源表与企业范围，再在腾讯云 CDB 生产库上安全清除历史噪声。用户截图企业为贵州省修文县日用杂品公司

## Execution process
1. 数据源判定：SHOW CREATE TABLE 比对后确认页面数据源为 anwei_mon_fireworks.em_alram_info（alarm_type=3 即超高超量），而非 remote-monitor 库的 eiot_alert_record（近两天仅 42 条，字段体系不同）
2. 范围盘点：按 alarm_type / warning_instance_type / processing_status / push_type 分组统计，今昨两天 type=3 共 863 条，其中 2 条已被人工确认为真实警情（warning_instance_type=1）、1 条未消警，全部 push_type=0（未推送省平台，删除不影响上报对账）
3. 企业映射：company_code=5201237772 对应贵州省修文县日用杂品公司，其 store_num 为 XWRZ-CK-05（534 条）与 XWRZ-CK-4（208 条），设备为 192.168.3.120/121 两台雷达
4. 就删除范围征询用户，选定"仅该企业（742 条）"，排除其他企业 121 条与已确认真实警情
5. 备份受阻与绕行：CREATE TABLE ... SELECT 被 GTID 一致性拒绝；改 LIKE + INSERT ... SELECT 又被 MCP 的 SCHEMA_INSERT/DELETE_PERMISSIONS 拒绝；最终改用同一 CDB 上开启 ALLOW_DELETE/ALLOW_INSERT 的 anwei_mon_fireworks MCP 服务执行
6. 建备份表 anwei_mon_fireworks.bak_em_alram_info_type3_20261029（CREATE TABLE LIKE 原表）并 INSERT 742 条
7. DELETE FROM em_alram_info WHERE company_code='5201237772' AND alarm_type=3 AND warning_date >= '2026-10-28 00:00:00' AND warning_date < '2026-10-30 00:00:00' AND processing_status=0 AND warning_instance_type IS NULL，影响 742 行
8. 校验：目标范围剩余 0、备份表 742、其他企业 type=3 仍为 121 条、楚雄已确认真实警情未动；清理误建的跨库空备份表

## Notes
- MCP 返回的 datetime 带 Z 后缀是驱动层 UTC 序列化，库内实际存北京时间，判断"今天/昨天"边界须以库内本地时间为准
- work-log 目录下的 md 文件在磁盘上是 Qoder 加密存储格式，只有 Read 工具能解密显示；用 PowerShell 按 GBK/UTF-8 读写会破坏密文且不可逆，此类文件禁止用 Bash 追加内容
- 清库只消除历史噪声，雷达阈值/安装角度问题未解决仍会持续产生新记录，需另行排查或在采集侧做报警抑制
