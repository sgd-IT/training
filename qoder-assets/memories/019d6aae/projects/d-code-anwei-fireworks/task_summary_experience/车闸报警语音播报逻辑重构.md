## 任务描述
修复车闸报警语音播报失效问题：车闸数据通过同步方式写入数据库（有syncId，device_code为车牌号码），原save方法仅判断当前entity的syncId导致跳过播报。

## 执行过程
```mermaid
graph TD
    A[定位问题:车闸响不了] --> B[分析同步机制差异]
    B --> C[确认车闸:syncId必有+device_code为7/8位车牌]
    C --> D[确认人闸:syncId可为空+device_code非车牌长度]
    D --> E[设计新逻辑:查最近3分钟报警类型4记录]
    E --> F[实现分流:有syncId直接播报+Redis去重；人闸无syncId走本地逻辑；车闸无syncId不播报]
    F --> G[注入RedisUtils+添加常量+重构save方法+新增4个辅助方法]
    G --> H[编译验证BUILD SUCCESS]
```

## 任务总结
成功修复车闸播报问题：在AlramInfoServiceImpl中新增handleIllegalIntrusionAlarms等4个方法，通过device_code长度（7/8位=车闸）和syncId有无实现三路分流，使用Redis setNx防止重复播报，扫描窗口与过期时间统一为3分钟。
