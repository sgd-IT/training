山东SD平台数据推送采用两阶段状态确认机制（access_status：0=待推、1=已提交待校验、2=校验通过）：
- 第一阶段：HTTP请求成功返回batchId后，立即将对应记录的`access_status`更新为1（表示已提交，等待校验）
- 第二阶段：延迟3秒查询批次结果，若`errorCount=0`则将`access_status`更新为2（校验通过），并清空`sync_reason`
- 失败处理（重要修正）：各推送方法的查询条件都是 `.eq(access_status, 0)`，因此失败记录绝不能停留在1——凡需重推的记录必须显式重置为0（全批失败整批置0；部分失败仅定位到的"第N条"置0），同时把平台错误文案写入`sync_reason`留痕。旧版本"errorCount>0保持1等待下次重推"的说法是错误的，保持1会导致下轮扫不到、数据永久丢失。
- 定位不到具体条目的部分失败：只写`sync_reason`不置0，防止已成功记录重复入库。
