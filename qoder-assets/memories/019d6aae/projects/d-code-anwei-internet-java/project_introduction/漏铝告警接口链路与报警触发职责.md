项目作为铝液泄露（漏铝）告警接收方，提供两套关联的设备上报接口，构成完整告警链路（共享 deviceSn 标识）：

- `/lyxl/push`（POST, application/json，JiagoVideoLeakageController.receiveDeviceStatus + DeviceStatusPushDTO）：周期性上报终端SN、time（必须 14 位 yyyyMMddHHmmss）、整体 status 及子设备状态列表 data（type 仅 1/2）。**status=0 是报警事件的唯一创建入口**：解析铸造井 → 查复位按钮与铸造中信号 → 满足条件时调 videoEventUp 生成/复用 msgId；status=1 为正常心跳，短路返回不产生报警。语音告警推送（createRecordAndPushMsg）在 push 阶段执行，音柱播报（sendIpVoice）也在 Controller 内每次 push 独立调用。
- `/api/lyxl/file`（POST, multipart/form-data，参数 deviceSn/time/id/file）：**只做音频证据补传**——从 Redis Hash 池（field=设备time）精确或就近匹配 msgId，hdel 消费后按 msgId 定位报警记录并 setEventVideo 绑定视频URL；若池中无匹配 msgId 直接返回"未找到对应的msgId"，不会创建任何报警。

入库时机（易被误解的关键事实）：videoEventUp **不再写库**，action_status 为空或 0 时只把记录暂存到 Redis（前缀 lyxl_pending_alarm:，TTL 10 小时）；全链路唯一的落库点是音频上传后的 setEventVideo → saveOrUpdate。因此 mon_aluminum_leakage_alarm_record 里能查出来的一行必然带 video_url，列表不会出现"暂无音频"的空行；反之音频不到（上传失败、匹配不上、retry 600ms 内 PENDING 未就绪）则该次报警彻底丢失，无任何兜底任务会把 PENDING 刷进库。

msgId 复用窗口（当前实现）：Controller 生成 msgId 前查 Redis 索引 `lyxl_well_msgid:{castingWellId}`，不存在则新建 UUID 并以固定 120 秒 TTL 写入（不随后续 push 续期），存在则复用同一 msgId —— 一次物理事件收敛为 1 个 msgId + 1 条 PENDING，alarm_time 即首次 push 的时间，消息推送也只 1 次。早期版本用 getOne 查数据库判窗口，而记录此刻在 Redis 里，导致复用长期失效、每次 push 各堆一条 PENDING，该缺陷已由 Redis 索引方案取代。

历史口径修正：早期需求曾描述"只要接收到音频文件立即无条件触发告警并推送APP、不做任何前置判断"（经 PushManager 发送），该逻辑已被现有实现取代，排查时不可再以此推断行为。

语音播报要求：报警成立时通过丹唛派克播报固定文案"警告，{companyName}发生漏铝"，companyName 由配置动态填充；是否播报受 dmpk.isopen 控制。音柱去重尚未接入，同事件仍会 N 次响。

companyName 配置化的跨项目边界：`loulv.companyName`（LoulvProperties）前缀只属 monkey-aluminium-api 项目；anwei-internet-java 工作区全库检索无 loulv 配置，其漏铝相关配置前缀为 `monkey.leak.*`（MonkeyLeakProperties）与 `dmpk.*`（DMPKEntity），核对 anwei-internet-java 漏铝部署配置时应按这两个前缀检查，不要按 loulv.* 查找。

运行环境与数据依赖：服务端口 9090（客户现场本地化部署），/api/lyxl/** 已配置放行；现场 spring.redis.database=1 而开发环境为 8，配对池与 PENDING 跨环境互不可见。prod/现场均配 monkey.leak.leakAlarmNormal=1、leakAlarmDemo=1、preSignalDelayEnable=false，即一次 status=0 推送即可产生报警，无需连续多次。报警能否建档还取决于 iot 库数据：range 信号点位、em_device_realtime 实时值、num in (ax0024, ax0048) 冷却水泵至少一条 d_value=1，三者缺一 signal 即为 0 并静默跳过整段创建逻辑；复位按钮点位（resetEncoding，如 ax0033）残留 d_value=1 会拦截全部声音漏铝报警。
