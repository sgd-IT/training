结论：嘉果设备状态推送（/lyxl/push）的水听器子设备日志采用"每次推送全量打印明细"方案（格式 subDevices:[水听器001=1, 水听器002=0]），而非"仅状态变化时打印"。

理由（权衡）：全量记录保证任意时刻各子设备状态都可直接查询，可通过相邻日志行比对自行还原状态变化时间线；实现完全无状态、不依赖 Redis 缓存上一帧状态，不存在漏记风险；代价仅为每行多约 40-60 字符，日志增量约 4%，与获得的追溯能力相比可接受。

被拒方案："仅在子设备状态发生变化时打印差异"——本身是合理的日志降噪手段，被放弃的原因是它需要有状态比较（内存或 Redis 保存上一帧），进程重启/多实例下会丢失基线导致漏记，且无法直接回答"某时刻该设备是什么状态"这类追溯问题。

适用/失效条件：在日志量可控（本场景推送频率约 3~5 秒一次、子设备数量个位数）且核心诉求是事后追溯的场景下成立；若未来推送频率或设备规模大幅上升导致日志存储成本成为瓶颈，需重新评估改为变化式记录或采样记录。
