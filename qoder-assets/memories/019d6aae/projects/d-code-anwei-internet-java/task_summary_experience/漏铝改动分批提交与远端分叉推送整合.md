## Task description
- 核心需求：将漏铝相关的工作区改动按最小单元分批 git 提交，并推送到 origin/master；用户最终只确认提交其中 3 个逻辑单元。
- 任务背景：仓库 d:\code\anwei-internet-java 工作区同时存在 6 组改动（铸造井解析、报警记录统一查询、嘉果状态上报、音频上传校验、离线缓存回写、mon_alarm_information 表模板字段），本地 master 落后 origin/master 2 个提交（1e651dd 本地化项目调整、26d6284 新增表与字段），处于分叉状态。

## Execution process
1. 逐项梳理 git diff 后拟定 6 个 Conventional Commits 中文提交（①fix(tb) 铸造井 equip_code 多编码匹配 ②fix(mon) 报警记录统一查询+音频上传后落库 ③fix(mon) 窗口内复用 msgId ④⑤⑥ 音频上传校验/缓存回写/模板字段），先向用户展示清单再执行。
2. 用户仅确认 ①②③，依次提交得 d0abd6d、46cb214、a5234a0；④⑤⑥ 保留在工作区未提交。
3. 说明"不提交不影响使用"的原理：commit 只写版本快照、不改工作区文件；并用 `mvn -q compile -pl monkey-monitor-api -am -DskipTests` 静默编译通过作为实证（-q 模式无 [ERROR] 输出即 BUILD SUCCESS）。
4. 指出配套风险：提交②把报警记录改为 Redis 暂存、音频上传后才落库，④⑤ 是 getVideoAlarmRecord 兜底查询的配套方，若从历史拉代码到别的环境会导致声音识别音频上传报 msgId 不存在。
5. 推送前用 `git diff --stat HEAD...origin/master` 定位远端独有改动文件，发现与本地 template 文件重叠。
6. `git stash push` 暂存工作区草稿 → `git rebase origin/master`（本地 3 提交变基为 94b07ca/8d153ae/757d3d8，无冲突）→ `git stash apply` 恢复。
7. 自动合并使 addField.txt 出现两套重复字段定义：远端 26d6284（yanglu）已加 is_upload_info/upload_id/alarm_id/action_alarm_id 且类型为 int(4)/varchar(255)，本地草稿为 int(2)/varchar(32)/varchar(36)；删除远端那 4 行、保留与 mon_alarm_information.txt 一致的本地版本。
8. `git push origin master` 成功（26d6284..757d3d8），用 `git status -sb` 确认无 ahead/behind，用 `git diff --stat "stash@{0}" -- <3个核心文件>` 空输出验证草稿恢复一致。

## Notes
- addField.txt 是表结构同步模板，同一字段被两个分支各加一次会产生重复 ALTER 语句，rebase 自动合并不会报冲突但必须人工去重。
- anwei-fire-remote-monitor-prod 这个 MySQL MCP 连的是 anwei_fire_remote_monitor 库，与本项目 dev 库 anwei_mon_aluminum_local 不同；同服务器可跨库查 information_schema.COLUMNS 核对字段是否真存在。
- `SHOW COLUMNS ... WHERE Field IN (...)` 在该 MCP 解析失败，改用 SELECT information_schema.COLUMNS 才可行。
- 本地 master 与远端分叉时禁止直接 push，需先 rebase/merge 整合；stash 备份可在确认后 drop。
