## 任务描述
实现铝液泄露监控系统中「上传音频文件即触发报警」接口，要求接收到multipart/form-data格式的音频文件后，不进行任何内容分析，立即向APP推送告警消息。

## 执行过程
```mermaid
graph TD
    A[需求:上传即报警] --> B[读取现状发现Service为空、DTO字段语义错误]
    B --> C[修正JiagoDeviceStatusVo：id字段注解改为'采集设备编号'并加@NotBlank校验]
    C --> D[编写JiagoDeviceService：注入PushManager，实现saveAudioFile→triggerAlarm→pushMessageToApp]
    D --> E[补全JiagoController：添加@PostMapping /api/lyxl/file接口，含deviceSn非空校验]
    E --> F[清理冗余import：移除未使用的JiagoDeviceStatusVo和@RequestBody]
    F --> G[多轮Read/SearchReplace验证并修复误删方法、缩进、缺失依赖]
```

## 任务总结
成功交付零判断告警接口：Controller严格按规范接收4个参数（deviceSn/time/id/file），Service收到文件后立即构造告警内容并调用PushManager推送，日志完备（INFO记录接收、WARN记录告警），DTO字段语义与校验准确。

## Notes
- 本条记录的「上传音频即无条件触发告警」行为口径已过期：现行实现中 /api/lyxl/file 只做音频证据补传，需从 Redis Hash 池匹配 msgId 才绑定报警记录，池中无匹配则直接返回失败且不创建报警；status=0 的 /lyxl/push 才是报警事件唯一创建入口。排查时以「漏铝告警接口链路与报警触发职责」为准，勿据此推断当前行为。
