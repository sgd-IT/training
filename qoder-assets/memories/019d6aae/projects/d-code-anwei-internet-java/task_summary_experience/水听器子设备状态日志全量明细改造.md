## Task description
- Core requirement: 完善水听器（子设备）状态推送的日志，使每条 /lyxl/push 推送都可后期追溯各子设备的在线/离线明细
- Task background: JiagoVideoLeakageController.receiveDeviceStatus 原日志仅打印 dto.getData().size()（子设备个数），不含具体哪台水听器异常，无法事后追溯报警时刻各子设备状态

## Execution process
1. JiagoVideoLeakageController.java 新增 import com.monkey.general.modules.mon.dto.DeviceStatusItemDTO（新方法签名显式引用该类型所需）
2. receiveDeviceStatus 日志行改造：由 "List<DeviceStatusItemDTO>:3" 改为输出 subDevices:[水听器001=1, 水听器002=0, 报警器003=1] 完整明细（type 1=水听器、2=报警器；status 1=正常在线、0=异常离线）
3. 新增私有方法 formatSubDevices(List<DeviceStatusItemDTO>)：格式化子设备列表，空列表输出 []
4. GetProblems 验证：无编译错误，仅 2 个历史遗留的 ResponseDataVo 原始类型泛型警告（与本次改动无关）
5. 设计决策：选择每次推送全量打明细而非"仅变化时打"——全量记录保证任意时刻状态可查、可通过相邻行比对还原状态变化时间线、实现无状态不依赖 Redis、不漏记；日志增量约 4%

## Notes
- 改动需重新打包 monkey-monitor-api 部署后才生效，当前运行版本仍是旧日志格式
- 部署后追溯用法：Select-String info.log -Pattern "subDevices" 查全部明细行；-Pattern "水听器002=0" 查某台水听器全部离线时刻；-Pattern "deviceSn:xxx.*水听器002=0" 限定单设备；status:0 同行的 subDevices 即报警时刻各子设备状态
- 配合音频上传接口已有的 deviceId 记录，形成"报警时刻各水听器状态 + 触发音频来自哪台设备"完整证据链
