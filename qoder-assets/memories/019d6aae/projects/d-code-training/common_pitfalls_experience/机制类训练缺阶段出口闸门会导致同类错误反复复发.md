Bug class: 学习计划中"机制掌握"缺少阶段出口硬闸门，导致欠账跨阶段累积。

Root cause: sgd 的 72 天计划把闭卷复述/机制检验主要集中在 Phase 5（Day 53-58），Phase 1-4 的验收只靠测试全绿和教练临时追问。实测证据：Day 9 复述检验 8/10 → Day 10（隔 11 个自然日）掉到 4/10；`Grouping` 空输入预测写成 `{0=[]}`，与 Q1 `countWithMerge([])` 是同一个错误的第二次复发；Day 5 测试 17 个一次全绿但多态概念追问 6 轮才通过，证明"全绿 ≠ 懂机制"。L 级综合日（Day 21 / 34 / 52）内容只有综合题 + 错题重写 + 复盘，没有讲机制的必过关口。

Fix pattern: 在每个 L 级综合日加一组闭卷机制题作为出口闸门（约 5 题，不出全绿不放行进入下一阶段），把"教练追问时才发现问题"升级为"阶段出口必须自证"；该做法不增加总天数，只让综合日耗时从 1 小时升到 1.5-2 小时。SQL 线同理需要在使用前插入落地锚点（Phase 2 起每天练 30 分钟 SQL，但首次真正使用要到 Day 42 的 MyBatis，中间 30+ 天只练不用）。

Reusable lesson: Don't rely on ad-hoc coach questioning as the only check for mechanism-level understanding because errors recur silently across phases and relearn cost compounds; instead gate every phase exit with a mandatory closed-book mechanism question set. Applies when designing or adjusting the exits of this multi-phase training plan (and any long-cycle self-study curriculum with staged checkpoints); does not apply to single-day drills whose goal is typing/muscle memory rather than mechanism recall. Expiry: once the plan's README has actually added per-phase closed-book gates, this pitfall no longer applies and should be re-checked rather than re-cited.
