## 任务描述
修复隐患确认关闭（status=31）时向园区平台推送businessState=4（验收通过）的实时推送逻辑，并新增按日期范围批量补推已关闭隐患的接口。

## 执行过程
```mermaid
graph TD
    A[需求:修复验收推送+补推] --> B[分析原upload() Bug：NoSuchElementException与ID不一致]
    B --> C[确定最小方案：仅operationType==4时推送businessState=4]
    C --> D[修改BaseHiddenTroubleServiceImpl：恢复调用+重写upload+加try-catch+新增pushClosedHiddenTroubles]
    D --> E[新增Mapper接口selectClosedHiddenTroubles及XML SQL：查status=31且update_time在范围内]
    E --> F[扩展PushDataController：添加/rePushHiddenTrouble接口]
    F --> G[扩展PushDataServiceImpl：将隐患补推加入rePushAllShuangKong流程]
    G --> H[补充IBaseHiddenTroubleService接口定义]
```

## 任务总结
成功实现隐患验收状态可靠推送：实时场景下，确认关闭即触发businessState=4推送；补推场景下，支持任意日期范围（如近30天）批量查询status=31隐患并逐条推送。所有改动经mvn compile验证通过，'一键全推'流程已包含隐患验收补推。
