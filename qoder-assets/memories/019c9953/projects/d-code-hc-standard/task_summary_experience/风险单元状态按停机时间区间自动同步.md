## 任务描述
实现风险单元停用/检维修状态的自动同步逻辑，使本地数据库状态与平台按时间区间（stopTime ~ activationTime）动态判断的逻辑保持一致。

## 执行过程
```mermaid
graph TD
    A[发现平台与本地状态不一致] --> B[定位差异根源：平台按时间区间判断，本地依赖手动status字段]
    B --> C[设计自动同步方案：过期恢复+当前停用双更新]
    C --> D[在BaseRiskUnitMapper.xml新增两个SQL：autoActivateExpiredUnits和autoDeactivateActiveUnits]
    D --> E[在Mapper接口、Service接口、ServiceImpl中逐层声明并实现autoSyncUnitStatus方法]
    E --> F[在SyncShuangKongTask定时任务和PushDataServiceImpl补推入口处调用该方法]
```

## 任务总结
成功构建时间感知的状态同步机制：通过两条精准SQL分别处理“过期恢复”和“当前停用”，并在定时同步与人工补推两个关键入口统一调用，确保本地base_risk_unit.status始终与平台时间逻辑一致。
