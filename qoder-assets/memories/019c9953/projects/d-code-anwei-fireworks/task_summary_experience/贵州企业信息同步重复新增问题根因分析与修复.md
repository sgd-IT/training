## 任务描述
解决贵州企业信息每次推送都在数据库重复新增的问题。

## 执行过程
```mermaid
graph TD
    A[用户反馈：贵州推送重复新增] --> B[定位核心方法convertAndSaveNetworkInfo]
    B --> C[分析匹配逻辑：原仅按companyCode和companyName匹配]
    C --> D[查数据库验证：本地companyCode是本地编码，非省平台编码；名称存在前缀差异]
    D --> E[根因确认：两步匹配均失败，必然走new Information分支]
    E --> F[设计修复：简化为仅按uploadCompanyCode+provincecode=52匹配，并加LIMIT 1防异常]
    F --> G[执行SearchReplace修改RequestGZMethod.java]
    G --> H[验证修复后逻辑：避免重复新增与重复推送]
```

## 任务总结
根本原因是贵州企业同步时匹配逻辑不严谨：未优先使用省平台唯一编码 `uploadCompanyCode` 进行匹配。修复方案是彻底移除冗余的 `companyCode` 和 `companyName` 匹配，仅保留 `uploadCompanyCode` + `provincecode=52` 的精确匹配，并强制 `LIMIT 1`，确保每次只匹配一条记录，从源头杜绝重复新增。
