> 打磨好的成果句，按能力主题分组；面试可讲要点见 06-面试素材.md。投递时按 JD 裁剪重排，不一份通投。

## 性能优化

- 独立完成大屏统计接口的缓存防击穿改造：拆“新鲜期（70s）/ key 存活期（300s）”双时间窗替代单一 TTL，使旧值兜底从死代码变为真实生效；以 JVM 内 Semaphore(2) + 非阻塞 tryAcquire 把重建并发限在 2 个线程、抢不到毫秒级返旧值，不再打穿 20 连接的 Druid 连接池；同步定位并修正一个从未生效的慢 SQL 日志配置——反编译 DruidDataSourceCreator 确认过滤器只在 `filters` 非空时挂载，而原配置写在 dynamic-datasource 不读的 `spring.datasource.druid` 下；将连接池 max-wait 从 10 分钟降至 30 秒，打满时快速失败而非干等。

## 架构与重构

- 独立完成租户级动态反控码的安全设计与三端落地：以 Redis 5 分钟 TTL 承载随机 6 位码，替换设备级静态二次确认密码；按登录用户租户定位反控码，避开跨租户切换导致的上下文错位；PC 管理员取码增加“重新输入登录密码”二次验证（BCrypt 比对、兼容三方登录无本地密码），移动端接口按 user_type 平台位准入，阻断已登录终端被借用越权取码。

- 主导消防告警四维语义统一架构设计与全栈落地：将 4 套并行漂移的告警语义（数字编码实为类型、英文级别、前端风险级、来源码）收敛为“类型/等级/来源/档位”四维正交模型，等级判据从散落 5+ 处收敛为单一语义层；设计“行级判据 + 读侧先于写侧原子切换”的过渡方案，支撑 31,563 条存量数据零歧义切换、全程可回退。

- 独立完成烟花仓库安全监测系统 MQTT 双链路（Paho v3 + EMQX 5）架构摸底：盘点 2 条独立连接、2 个订阅主题、3 处指令下发点，从代码痕迹还原订阅封装的三处历史故障补偿（重连重订阅 / 多线程 publish 死锁 / 回调异常断连），沉淀 6 条 MQTT 客户端使用规范，识别 publish 死代码、发布无重试补偿、连接日志明文密码 3 项设计债。

- 设计多来源告警统一接入框架：以统一消息模型 + 来源枚举 + 策略工厂收敛 TCP/UDP/AEP/摄像头四类告警入口，新来源只扩展枚举与实现、不改主流程，6 个文件 809 行从 0 到 1。

## 故障与稳定性

- 独立完成线上接口调用量异常的流量归因：以 UA + 来源 IP + 小时分布把 7 天 18.4 万次调用拆成人工操作、页面轮询、机器对机器三类，定量定位外部 Java 服务 8 秒一次的固定拉取（占 39%、均值 0.01 秒、零压力）与 7 张 60 秒轮询表叠加（深夜每分钟精确 7 次）；按“调用量 × 平均耗时”重排优化优先级，纠正“调用量榜首即最该优化”的排序倒置。

- 定位并修复告警去重窗口竞态与设备离线误判两类线上问题：去重改为原子占位 + CAS 刷新并指出剩余边界；在线判定按上报周期 × 2 统一口径，删除组件内存会话表，消除 1 小时上报设备的误判离线。
