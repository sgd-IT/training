# 14-设计模式
> 层级：14｜建立：2026-10-30｜状态：空
## 【本类范围】
创建型（单例、工厂、建造者）、结构型（适配器、代理、装饰、门面）、行为型（策略、模板方法、观察者、责任链、状态机）；重点不是背定义，而是“新增一类时改哪里”。
## 【高频考点】
- 策略 + 工厂：把 if/else 分支收敛成注册表，新增类型零改动
- 模板方法：流程骨架固定、步骤可变（导入、解析、上报）
- 责任链：多级过滤与短路（拦截器链、权限链）
- 门面：对外统一入口，对内聚合多子系统（推送统一门面）
- 状态机：状态与动作分离，避免状态值散落在业务代码
- 单例的正确写法与为什么优先枚举/静态内部类
- 什么时候**不要**上设计模式（过度抽象也是债）
## 【与项目经历的关联】
- 推送统一门面 + 二级/三级告警分流（06-面试素材“消防告警写侧与推送门面”）。
- 协议解析的工厂/注册表：按报文类型分派解析器，新增协议只加一个实现。
- 告警处置、隐患治理九态、上报同步三态：状态机建模的实战。
- 曾把 String switch 改 Map 又撤回：设计模式取舍的反面案例（important_decision）。
- 规则引擎替代策略工厂的判断（设备上报与告警触发通路）。
