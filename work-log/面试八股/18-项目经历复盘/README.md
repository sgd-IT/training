# 18-项目经历复盘
> 层级：18｜定位：主推方向（与 17 并列）｜建立：2026-10-30｜状态：空
## 【本类范围】
目标岗位是**后端为主 + AI Agent 工程师**，所以只打磨**两个必讲故事**：AI 落地（证明端到端 + 新先手）、后端故障/性能（证明底座）。架构取舍作为第三个故事，讲得清就加，讲不清宁可不讲。每个故事按“背景 → 我的决策 → 踩的坑 → 数字结果 → 复盘”组织，8–10 分钟能讲完。
## 【故事骨架】
- 必讲一（AI 落地，排最前）：Spring AI + RAG + 工具调用，含评测集、bad case 分类、成本与失败兜底；讲清“为什么这里不用微调 / 为什么不用 Agent”。
- 必讲二（后端深度）：告警列表慢查询 + N+1 → EXPLAIN → 复合索引 → 批量查询，前后耗时对比（06-面试素材 2026-10-20）。
- 可选三（架构取舍）：多租户隔离为什么放在拦截器而不是每个 Mapper；或大屏统计“拉长轮询间隔而不加缓存”的取舍理由与代价。
## 【面试口径红线】
- 1 年段位不写“主导架构”，用“这条链路从接口到页面是我独立做完的”证明独立性。
- 目标岗位是后端 + AI Agent 工程师：不要花半场讲前端页面细节，前端只作“能独立交付”的一句话佐证。
- 数字必须能说清口径（P99 还是平均、哪个接口、哪个时间段），说不清就换量级表达。
- 只讲自己做过的部分；同事完成的部分明确区分，不认领。
