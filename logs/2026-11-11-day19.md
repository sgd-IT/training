## 主题：三种协议（RESP / MQTT / AMQP）背后的**同一套骨架**

### 一、★ 三种协议，同一套骨架

```
RESP（Redis）   *3\r\n$3\r\nSET\r\n$1\r\nk\r\n$1\r\nv\r\n    ← 文本，长度前缀是 ASCII 数字
MQTT            固定头(1) + 变长整数 + 负载                   ← 二进制
AMQP 帧         type(1) + channel(2) + size(4) + payload + 0xCE ← 二进制
```

共性只有三件事：**长度前缀、大端序、变长整数。**

### 二、★★ 大端序（网络字节序）

```
0x12345678  →  12 34 56 78   高位字节先走（网络协议几乎全是大端）
```

写：从最高位开始，每次 `>> 8`，取最低那个字节。
读：反过来，每个字节 `<< 8` 累加。

### 三、★★ `byte` 有符号 → `& 0xFF` 是唯一出路

```java
(byte) 0xFF          → -1
(int) (byte) 0xFF    → -1        // 符号扩展
0xFF & 0xFF          → 255       // 先零扩到 int 再与
```

不 `& 0xFF` 的后果：**不报错，只是静悄悄地算错** —— 这种 bug 最难查。

### 四、★★ 变长整数（MQTT Remaining Length，1~4 字节，上限 268435455）

```
每个字节：低 7 位是数据，bit7 = 「后面还有没有下一个字节」
先写低 7 位，剩下的右移 7 位继续，直到剩 0
```

| 值 | 编码 | 说明 |
|---|---|---|
| 127 | `[0x7F]` | 塞得进 7 位，1 字节 |
| 128 | `[0x80, 0x01]` | 低 7 位是 0 → 第一字节 0x80（续位=1） |
| 16383 | `[0xFF, 0x7F]` | 两字节上限 |
| 16384 | `[0x80, 0x80, 0x01]` | 进三字节 |
| 268435455 | `[0xFF, 0xFF, 0xFF, 0x7F]` | 协议上限 |

### 五、★ 长度前缀算的是**字节数**，不是字符数

```java
"中".length()                 → 1     // 1 个 char
"中".getBytes(UTF_8).length   → 3     // 3 个字节
```

长度写 1、实际给 3 个字节 → 对端解析直接错位。
