## 主题：Stream 的**机制**，不是 Stream 的语法

### 一、★★ 惰性：没有终止操作，一行都不跑

```java
list.stream().map(x -> { System.out.println(x); return x; });   // 什么都不打印
list.stream().map(...).toList();                                // 这时才打印
```

| 类别 | 代表 |
|---|---|
| 中间操作（返回 `Stream`） | `map` / `filter` / `flatMap` / `peek` / `limit` / `sorted` / `distinct` |
| 终止操作（返回非 `Stream`） | `toList` / `collect` / `forEach` / `count` / `findFirst` / `anyMatch` |

中间操作只是**登记**；终止操作才真正开始遍历。

### 二、★ 短路：无限流能停下来的唯一原因

`Stream.iterate(1, n -> n + 1)` 是无限的，配上 `filter(...).findFirst()` 却能返回 —— 找到即停，后面的元素根本不生成。

- 短路操作：`limit` / `findFirst` / `findAny` / `anyMatch` / `allMatch` / `noneMatch`
- 反例：`iterate(1, n -> n+1).filter(n -> n > 5).toList()` **永远不返回**
  （`toList` 要把「所有」元素装进列表，而这个流没有「所有」）
  → 实测：`-Xmx64m` 下约 1 秒抛 `OutOfMemoryError: Java heap space`

### 三、★ 流只能消费一次

```java
Stream<String> s = list.stream();
s.count();
s.count();   // IllegalStateException: stream has already been operated upon or closed
```

集合**存**数据，流只是一条**管道**，走完一遍就废。要再走，重新 `list.stream()`。

### 四、map vs flatMap

```
map      一个元素 → 一个元素         Stream<List<Integer>>
flatMap  一个元素 → 一个流，再摊平    Stream<Integer>
```

`List<List<Integer>>` 做 `map(List::stream)` 得到的是 **`Stream<Stream<Integer>>`**（套了两层），
所以收不成 `List<Integer>`；`flatMap` 才是「拍平」的那个。

### 五、toList() ≠ collect(Collectors.toList())

| 写法 | 返回 | 能 add 吗 |
|---|---|---|
| `stream.toList()`（JDK 16+） | 不可变 List | ❌ `UnsupportedOperationException` |
| `stream.collect(Collectors.toList())` | 普通 `ArrayList` | ✅ |

### 六、★ `count()` 会跳过 `peek`（今天最反直觉的一条）

```java
List.of("a","b","c").stream().peek(log::add).count();                 // log.size() == 0
List.of("a","b","c").stream().peek(log::add).filter(x -> true).count(); // log.size() == 3
```

`count()` 跳过 `peek` 要**同时**满足两个条件：

1. 流的大小源头已知（`SIZED` 标记还在）
2. 中间操作**不改变元素个数**（`peek` 符合；`filter` 不符合）

加一个**恒真**的 `filter(x -> true)`（一个元素都没过滤掉），`SIZED` 就被清掉，
`peek` 立刻执行 3 次。**不是「filter 有没有真的过滤」，是「流还敢不敢断定自己有几个元素」。**
