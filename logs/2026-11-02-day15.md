## 主题：异常的机制，不是异常的 API

### ① Throwable 家族是两条平行分支

```
Throwable
├── Error                ← JVM 层面，不该 catch
└── Exception
    ├── RuntimeException ← unchecked
    └── IOException 等    ← checked
```

**Error 不是 Exception 的子类** —— 这是最容易记错的一条。

### ② checked 只是编译器的检查

JVM 运行时不区分 checked / unchecked，字节码里都是 `athrow`。

`throws` 子句只存在于 class 文件的 **Exceptions 属性**里，是给编译器看的元数据。
反射能读到（`Method.getExceptionTypes()`），JVM 不拿它做任何检查。

### ③ try-with-resources 编译成了什么（本日核心）

```java
try (R r = new R()) { body(); }
```

展开成：`try { body(); } catch (Throwable t) { primary = t; throw t; }`
`finally { if (primary != null) { try { r.close(); } catch (Throwable c) { primary.addSuppressed(c); } } }`

**关键**：body 和 close 同时失败时，**body 的是主异常**，close 的挂到 `getSuppressed()`。
JDK 7 之前没有 suppressed，close 的异常会**直接吞掉**业务异常。

**关闭顺序：逆序**（后开的先关），因为后面的资源可能依赖前面的。

### ④ 异常链（cause）

`new ServiceException("x")` → cause 为 null → 根因永久丢失。
`new ServiceException("x", e)` → `getCause()` 能一路走到根因。

2. 改成 try/catch/finally，但**又套了 try-with-resources**（`try(flakyResource){`）
   → close 被调**两次**；且 `throw closeException` **无条件**抛，挂完 suppressed 又扔出去
3. 改对：去掉括号（普通 `try`）、`throw` 只在 `mainException == null` 时执行

## 复盘问答

### ① try-with-resources 的展开

- 首答：只说出「主异常是 body 的」，**没说 close 的去向**
- 复核 ✅：body 的异常是主角；close 的挂在 **`getSuppressed()`** 上（`length == 1`），两个都不丢；
  `else throw closeException` 只在**主异常为 null**（body 没炸）时才让 close 的异常自己抛出去

### ② 关闭顺序

- 首答 ❌：「反了的话可能会覆盖到主要的异常」—— **把「关闭顺序」和「异常优先级」混成了一件事**
- 复核 ✅：依赖别人的先关。`bw` 依赖 `fw`，`bw.close()` 要先把缓冲区 **flush 到 `fw`**，
  `fw` 先关就会 `Stream closed` / 丢数据
- **教训：关闭顺序跟异常无关**，它考的是**资源依赖**

### ③ 异常链

- 首答：「差的就是异常的信息」—— 太笼统
- 复核仍不准：**没说出 `getCause()` 一个是 `null` 一个是 `e`**
- 教练补：不是「信息多少」，是**因果链断没断**。断链的日志，根因永久丢失

## 教练点评

1. 🟢 **Q2 / Q3 一次过** —— try-with-resources 的语法、异常链的概念他都具备。
2. 🔴 **Q1 卡了 4 轮，而 Q1 是全卷最简单的一题**（3 个 token）。
   根因不是语法，是「**异常是一个对象；throw 出去的，catch 接住的就是同一个对象**」这个模型没建立。
   → 以后遇到「最简单的题卡最久」，先怀疑**概念模型**，不要怀疑语法。
3. 🔴 **复发「造东西骗测试」**：Q1 第 2 版 `return new IllegalStateException("body failed")` 让测试变绿。
   **这是本课最危险的动作** —— 比红着交更糟，因为它伪装成完成。
4. 🔴 **复发「改形式不改实质」**：Q4 第 2 版把 try-with-resources 和手写 `finally` 混用，
   一个资源两个主人 → close 被调两次。
5. 🟡 **「关闭顺序」与「异常优先级」混淆** —— 两个不同机制被合成一个。
6. 🟡 **连续把「预测」当成「输出」提交**（实验 2/3/4 三条预测全错，第 4 条空着）。
   → 固定格式：**预测单独一行，跑完在下一行写实际值**，两行都在才算做完。
7. 🟢 学员自己指出「这块我比较陌生」并要了「步骤注释」—— **主动要脚手架，比硬编要好**。
