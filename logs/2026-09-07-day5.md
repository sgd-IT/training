## 今日考点
- 继承：extends、子类自动拥有父类的 public 方法（getName 等）
- super()：构造器第一行调父类构造器（和 this() 委托对比——父类版）
- 继承的校验链：父类构造器的校验子类绕不过（super 拦截）
- 重写 override：@Override 注解、父类方法被子类替换
- 多态：基类方法内部调用被重写的方法时，跟着对象真实类型走
- 重载 overload（同名不同参）vs 重写 override（父子类同名同参）——对比贯穿今天
- private 字段子类不可见，只能通过 super/继承方法（封装复习）

### 教学工具升级（第 4 轮末）
口诀式类比（服务员/后厨、遥控器/电视）**对该学员无效**，改用**机械步骤法**：

> 遇 `A x = new B(); x.m("hi");`
> **步骤1** 找名字类型：等号左边变量声明成什么 → `A`
> **步骤2** 找实物类型：`new` 后面是什么 → `B`
> **步骤3** javac 只问步骤1：「`A` 里有没有 `m(String)` 签名？」有→记录 `A.m(String)`；没有→**编译报错**（B 有也没用）
> **步骤4** JVM 只问步骤2：「`B` 里有没有重写 `m(String)`？」有→执行 `B.m(String)`；没有→执行继承来的
> **铁律：步骤3 查 A，步骤4 查 B，两个类型绝不串门。**

**支撑实验（全部实机验证，非推测）：**
| 实验 | 命令/代码 | 结果 |
|---|---|---|
| A | 构造器写 `r = r;`（字段 final） | `error: variable r might not have been initialized`（报错位置在构造器收尾 `}`） |
| B | 子类写 `salary * 12` | `error: salary has private access in Employee` |
| C | `super(...)` 非第一行 | `error: call to super must be first statement in constructor` |
| D | 去掉 final 后 `r = r;` **运行** | `new Circle2(2.0).area() = 0.0`（正确值 12.566…）——**静默算错，最危险** |
| E | 抽象类 `new` | `error: Shape3是抽象的; 无法实例化` |
| F | javac 能否知道实物类型 | 编译通过（`if/else` 分支里 `new Dog()` / `new Cat()`）——**javac 物理上不可能知道** |
| G | `A x = new B(); x.onlyB();` | `error: cannot find symbol`——**javac 看不到实物类型 B 独有的方法** |
| G2 | `A x = new B(); x.m()` | `B.m`——JVM 按实物类型执行 |

**javap 实证（`Dispatch.java`，Day 5 真实类）：**
```
g .greet("a")  ->  Greeter.greet:(String)        javac 用 g 的声明类型
l .greet("a")  ->  LoudGreeter.greet:(String)    javac 用 l 的声明类型
g2.greet("a")  ->  Greeter.greet:(String)        但运行输出 HELLO, A! ← 分歧点
g .greet()     =   Hello, friend
l .greet()     =   HELLO, FRIEND!                编译通过（继承）
g2.greet()     =   HELLO, FRIEND!
```
