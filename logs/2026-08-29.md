2. Q6 委托概念：
   - 用户问「构造器委托是什么意思」→ 讲透 this(...) = 转交另一个构造器，
     流程演示 + 前台/后厨类比 + 三条规则（第一行、传参、必经校验）
   - 用户混淆 this(...) 与 this.xxx（「B 不是也有 this 吗」）→ 区分：
     括号 = 调构造器（转交），点 = 访问当前对象成员（自己干活）；
     委托链尽头 = 参数最全的构造器；互相委托 = 死循环
   - 用户问「不应该会有无参构造器吗」→ 规则：写了任何构造器，默认无参构造器消失
   - 用户问「构造器的作用是什么」→ 初始化器 = 校验 + 赋值；
     默认值不等于合法值（null/0 是坏对象）；private 字段只能靠构造器装数据
   - 用户答「像校验器」→ 补充：校验只是前半段，后半段是赋值，合称初始化
   - 用户答「字段 private 只有内部方法能碰，所以需要构造器封装」→ ✓ 完全正确
   - 委托 vs 不委托：new Employee(null) 委托版抛 IAE ✓（答对）；
     不委托版直接存 null 不报错 → 坏对象（用户未明确答出，教练讲解）
