## 二、题目（7 个 TODO + 3 个天然绿）

| TODO | 方法 | 考点 | 判定 |
|---|---|---|---|
| Q1 | `nameInNewThread` | `start()` 真的开新线程 + 线程名 | 返回 `day22-worker` |
| Q2 | `nameViaRun` | `run()` 只是一次普通方法调用 | 返回 `main` |
| Q3a | `sizeBeforeJoin` | `start()` 是**异步**的，不 join 就读到 0 | 返回 `0` |
| Q3b | `sizeAfterJoin` | `join()` 让当前线程等它死 | 返回 `3` |
| **Q4** | `plainIncrement` | ★ **故意复现丢更新**（这题不要修） | 返回 **< 400000** |
| Q5 | `lockedIncrement` | `synchronized` 修好 | 正好 `400000` |
| Q6 | `atomicIncrement` | `AtomicInteger` 修好，且不加锁 | 正好 `400000` |
| Q7 | `stopIsVisible` | `volatile` 可见性（字段少一个修饰符） | 返回 `true` |
| 天然绿 | `concept1/2/3` | 线程状态 `NEW` / `start` 只能调一次 / `interrupt` 只置标志 | 不用写，读断言 |

### ⚠️ 两条跟以前不同的规矩

1. **Q4 是「绿 = bug 存在」**。它断言 `< 400000`。你要是手滑加了 `synchronized`，这条会**变红** —— 那说明你修了不该修的东西。
2. **Q7 那个字段少一个修饰符**。类顶部的 `private boolean stop;` 是故意写残的，你要补上它，并且能一句话说清为什么。

## 三、收尾机制题（3 题，闭卷口述 → 按 2026-11-18 新标准改为**开卷 + 贴证据行**）

| # | 题 | 要交什么 |
|---|---|---|
| 1 | `count++` 是哪三步？两个线程同时在 ① 之后会怎样？`synchronized` 锁住以后为什么就不能插队了？ | 三步写全 + 说清"锁的是对象"而不是"锁的是代码" |
| 2 | `t.start()` 和 `t.run()` 差在哪？为什么 `run()` 不报错却完全错？怎么**一眼**分辨自己写错了？ | 说清"新线程 vs 普通方法调用" + 判别方法（打印线程名） |
| 3 | JIT 为什么敢把 `while (!stop)` 里的 `stop` 读进寄存器不再回内存读？`volatile` 做了**哪两件事**？ | 可见性归因 + volatile 的「禁止重排」这一半必须说出来 |

**Q7 追加动手题**：把 `volatile` 删掉，再跑一遍 `q7`，记下结果（返回 false / 卡住 / 还是 true）。
> 这个结果本身就是证据 —— 如果这次仍然是 true，说明**可见性 bug 是概率性的**，正好印证第五节那句话。
