## 主题：Lambda 的**机制**，不是 Lambda 的语法

### ① 函数式接口 = 只有一个抽象方法

`@FunctionalInterface` **什么都不执行**，只是让编译器在写了两个抽象方法时报警。
真正的判定标准是 **SAM**（Single Abstract Method）。
`Function` / `Consumer` / `Supplier` / `Predicate` 全部满足。

### ② ★ Lambda 不是匿名内部类

| | 类名 | 怎么来的 |
|---|---|---|
| lambda | `Xxx$$Lambda$14/0x...` | `invokedynamic` + `LambdaMetafactory`，**运行期在内存里生成** |
| 匿名内部类 | `Xxx$1` | 编译期**生成 .class 文件**，磁盘上真的有 |

面试答到 `invokedynamic` 才算答到机制；只说「lambda 更简洁」是背的。

### ③ ★★ 变量捕获：只能捕获 effectively final

```java
int count = 0;
Runnable r = () -> count++;      // 编译错误
```

**为什么**：lambda 捕获的是局部变量的**值拷贝**（存成 lambda 对象的字段）。
能改的话，改的是拷贝，外面的 `count` 还是 0 —— 看着在工作，实际没有。所以编译器禁掉。

**为什么 `int[]` 可以**：

```java
int[] box = {0};
Runnable r = () -> box[0]++;     // 合法
```

`box` 这个**引用**没变；改的是引用指向的**对象内容**。拷贝的是引用。

> 一句话：**不能改的是「变量」，不是「变量指向的对象」。**

### ④ Lambda 里的 this

lambda **没有自己的 this** → `this` 是外层对象；
匿名内部类里 `this` 是匿名类自己。

### ⑤ 组合顺序

```
f.andThen(g)   = g(f(x))      先 f 后 g
g.compose(f)   = g(f(x))      完全等价，只是换个写法读
p.and(q) / p.or(q)            有短路：左边定了结果右边不执行
```

1. **② 题是四天来第一次真取证。** Day 13 起的老毛病是「把概念当输出」，这次他把 javac 的原话一字不差抄了回来，还主动还原并确认全绿。这个动作比当天答对任何一题都值钱。
