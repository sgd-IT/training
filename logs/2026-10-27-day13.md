## 主题：Set 只有一个承诺 —— 不重复

三家各有各的"顺序观"：

| 实现 | 顺序 | 判重依据 | 复杂度 |
|---|---|---|---|
| `HashSet` | 无 | `hashCode` + `equals` | O(1) |
| `LinkedHashSet` | 插入顺序 | `hashCode` + `equals` | O(1) |
| `TreeSet` | 排序顺序 | **`compareTo` / `Comparator`** | O(log n) |

## ★ 今天最大的坑

**`TreeSet` 判重不看 `equals`，只看比较结果是否为 0。**

```java
TreeSet<String> t = new TreeSet<>(Comparator.comparingInt(String::length));
t.add("ab"); t.add("cd"); t.add("ef");     // → size == 1
```

三个内容完全不同的字符串，只剩一个 —— **不报错的丢数据**。
和 Day 10 的 `getOrDefault(k, new ArrayList<>())` 同一类陷阱：**安静地错**。

正确做法：比较器必须构成**全序**（长度相同时比内容）。

## ☕ JDK 21 Sequenced Collections（JEP 431）

JDK 21 之前，拿首尾每个集合写法都不同：

```
List      →  get(0) / get(size()-1)
Deque     →  getFirst() / getLast()
SortedSet →  first() / last()
```

JDK 21 统一成 `SequencedCollection`：`getFirst()` / `getLast()` / `reversed()` / `addFirst()` / `addLast()`；
`SequencedMap` 对应 `firstEntry()` / `lastEntry()` / `reversed()`。

三个要点：
- `reversed()` 是**视图**不是拷贝 —— 改原集合，视图跟着变（测试里专门验了）
- 空集合 `getFirst()` 抛 `NoSuchElementException`，不返回 null
- 接口层统一，底层实现没变，**没有性能代价**
