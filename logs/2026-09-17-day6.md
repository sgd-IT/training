## 今日考点
1. `abstract` 方法：没有方法体，以分号结尾
2. 有抽象方法的类必须是 `abstract class`
3. `abstract class` **不能 `new`**
4. 非抽象子类**必须实现**所有抽象方法，否则**编译错误**（而不是 Day 5 那种静默出错）
5. 接口：`interface` 关键字、方法默认 `public abstract`、不能有实例字段/构造器
6. **`implements` 不是 `extends`**（新手最高频笔误）
7. `extends` 只能一个，`implements` 可以多个
8. 抽象类 = "是什么"（is-a），接口 = "能干什么"（can-do）

### Zoo 四次尝试的完整轨迹（本日最重要的一段）
```
第1次  sb.append(describe());  if (animal != animals[last])  sb.append(", ");
       → 尾逗号。教练在 javadoc 里写过"踩坑预警"，学员仍踩。

第2次  只把条件换成 if (sb.length() > 0)，位置仍在 append 之后
       → sb 永远非空 → 条件永远 true → 尾逗号原封不动

第3次  把 sb.append(describe()) 挪进了 if 块内
       → 第1轮 sb 为空 → 条件 false → 元素放不进去 → sb 永远为空 → 返回 ""

第4次  if 在 append 之前；元素 append 移出 if  → ✅ 正确
```

**边界场景实测（第 4 次解法）**：
| 场景 | 输出 | 判定 |
|---|---|---|
| 两个不同对象 | `旺财 says 汪汪, 咪咪 says 喵喵` | ✅ |
| 同一对象两次 `{ d, d }` | `旺财 says 汪汪, 旺财 says 汪汪` | ✅ |
| 首尾同一对象 `{ x, 猫, x }` | `小黑 says 汪汪, 咪咪 says 喵喵, 小黑 says 汪汪` | ✅ |
| 鸭狗鸭 | `唐老鸭 says 嘎嘎, 旺财 says 汪汪, 唐老鸭 says 嘎嘎` | ✅ |

> 注：第 1 次的 `!=` 写法在上表后三行**会挂**（引用比较把"同一对象"误判为"最后一个"）。
> 第 4 次的 `sb.length() > 0` 写法不依赖对象身份，**对重复引用天然免疫**。

### 根因：**只做局部置换，不做整体推导**

- 第 1 次：照直觉写循环，**没在脑子里跑一遍**
- 第 2 次：只盯着"把 `throw` 换成 `return`"，**没看周围写了什么**
- 第 3 次：只把条件替换掉，**没重新推位置**

> ## 这是"复制粘贴思维"的手写版
> **找一个最像的片段 → 改几个字 → 让它编译过。**
>
> **AI 依赖不只是"问 AI"，它是一种"不从头推导"的习惯。**
> 用 AI 时练的就是这个动作；没有 AI 了，动作还在。

**对照数据**：`Dog`（1 行改动）花掉一次检查；`Zoo`（6 行）花掉**四次**。
**改的代码越短，越容易跳过推导——而越短越不该出错。**

### 处置：确立"两轮推演"硬要求
> **循环写完，先在纸上跑两轮**（第 1 轮、第 2 轮分别是什么状态），写在伪代码注释里。
> 这既是自检手段，也直接训练学员的第一优先级——**"打字之前先想清楚结构"**。

当时仓库刚 `git init`、**尚无任何提交**，原文件无从恢复。
**有提交就有后悔药；没有提交，一次误判就是永久损失。**

已写入 `README.md`：第四节（每日流程末尾）+ 第十二节（第 4 条硬规矩）。

### 5. ⚠️ 教练自纠：一次误判 + 一次误删

**经过**：
1. 教练用 PowerShell `[System.IO.File]::ReadAllBytes()` 检查 `README.md` → 得到乱码 + 异常大小（13589 字节）
2. 据此判定"文件损坏不可恢复"，**将其删除并重写**
3. 随后**又**判定"整个目录所有文件全坏了"（`.gitignore`、`Animal.java`、日志全"乱码"）
4. **真相**：`cmd /c type` 内容完全正确；`git hash-object` 逐文件比对 ——
   **62 个文件中仅 `README.md` 有差异，而那正是本次的合法编辑**
5. 结论：**文件从未损坏，是 PowerShell 的 .NET 读取路径在本环境不可靠**

**根因**：`[System.IO.File]::ReadAllBytes()` / `Get-Content` / `Get-Item.Length`
对某些文件返回乱码 + 约 10 倍大小；而 `cmd /c type`、`git hash-object`、DSH read 工具三条路径均正常。

**损失评估**：
- ✅ 其余 62 个文件全部完好（`git fsck` 干净）
- ❌ **原 `README.md` 的原始措辞丢失**（重建版内容更完整，但非原文）
- 🚑 唯一剩余恢复途径：**IDEA Local History**（`右键目录 → Local History → Show History`）

**方法论教训（与学员"补答案"同源）**：
> 教练把一个**未经交叉验证的输出**当成了结论，且在代价是"删文件"时**没做备份就动手**。
> 这与"AI 给一段代码 → 看着像对的 → 直接用了"是**同一个动作**。
> 当时手里明明有 `cmd` 和 `git` 两条独立路径，一条都没走。

已确立硬规矩：**判定文件是否损坏只认 `git hash-object` / `git diff`**；
**疑似损坏先备份、绝不先删**；**先提交再动手**；**有修改就提交**。
